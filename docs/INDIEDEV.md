# Модуль для инди-геймдева

Единая точка входа по развороту Cedar Clerk в тулкит инди-разработчика игр. Первоисточник замысла — `_Documents_/CedarClerk/Gamedev_Focused_Rework.md` (бриф Марти). Решения — `docs/DECISIONS.md`, ADR-101…107. Устройство десктопа — `docs/DESKTOP.md`. Порядок работ — `docs/ROADMAP.md`, Phase 13.

Ветка: `indiedev_module` (создана от `dev`). Бриф прямо допускает её удаление, если бизнес-модель не подтвердится — поэтому обратимость входит в требования, а не является приятным свойством (ADR-101).

## Что меняется

Cedar Clerk перестаёт быть «редактором постов с публикацией в несколько сетей» и становится платформой, где **пост — один из типов документа**, а документы живут внутри **проекта** (в терминах Марти — игры). Вокруг документов появляются вещи, которые постами не являются вовсе: задачи, спринты, индекс ассетов, референс-борды, помощники сценариста и гейм-дизайнера.

При этом ничего из существующего не подменяется. Модуль **добавляет** — редактор, `/drafts`, `/posts`, `/settings` работают как работали, и выключение флага `Cedar:Modules:IndieDev` возвращает сегодняшнее приложение целиком.

## Позиционирование

Это заодно ответ на `Q-1` в `docs/BACKLOG.md`, висевший открытым с 30.07.2026: тогда было названо четыре фокуса (блоггеры, фотографы/видеомейкеры, помощь писателям, помощь инди-геймдевам) и потеряна формулировка пятого. Бриф выбирает один — **инди-разработчик игр**, — и выбирает его по честной причине: это сам Марти, то есть единственная аудитория, чьи потребности здесь проверяются не догадкой, а собственной работой.

Важно, что аудитория при этом не сужается до «программиста». Формулировка брифа перечисляет роли одного человека: программист, гейм-дизайнер, продюсер, сценарист, звукорежиссёр, композитор, режиссёр, маркетолог, аналитик. Тулкит адресован этому набору ролей, а не типу занятости.

Рабочее имя из брифа — `Cedar Clerk For Indie Developers`. Имя продукта остаётся открытым вопросом (`Q-17`, `docs/BACKLOG.md`); рекомендация — оставить `Cedar Clerk` именем платформы, потому что переименование тянет за собой домен, имя бота, расширение `.cedar` и все сто ADR, а маркетинговую задачу решает подзаголовок.

Сверено по коду 10.08.2026, а не по докам (`docs/DOCS-FLOW.md` предупреждает, что доки отстают — и это правило нашло уже три расхождения). Версия `0.9.40`, последний ADR до этой сессии — ADR-100, последняя фаза — Phase 12.

## Модель данных

Полное обоснование каждой строки — ADR-102, ADR-106, ADR-107.

**Изменения существующего:**
- `Draft.DocumentType` — string, default `post`. Существующие строки становятся постами без миграции данных.
- `Draft.ProjectId` — `Guid?`, plain scalar без FK и nav-свойства, как `FolderId`. Null = документ вне проекта (все сегодняшние).
- `GlossaryTerm.ProjectId` — `Guid?`. Null = глобальный термин (сегодняшнее поведение), заполнен = локальный глоссарий проекта.

**Новое:**

| Сущность | Смысл | Ключевые поля |
|---|---|---|
| `Project` | Игра или иная работа, вокруг которой собраны документы | `OwnerId`, `Name`, `Description`, `CoverAssetId?`, `CreatedAt`, `ArchivedAt?` |
| `GameTask` | Задача таск-трекера | `OwnerId`, `ProjectId`, `Name`, `Status`, `Priority`, `Description`, `Assignee`, `SprintId?`, `DueAt?` |
| `TaskLink` | Связь задачи с чем угодно | `TaskId`, `EntityType`, `EntityId` |
| `Sprint` | Отрезок планирования поверх задач | `OwnerId`, `ProjectId`, `Name`, `StartsAt`, `EndsAt` |
| `AssetEntry` | Строка индекса локального ассета — путь и метаданные, файл не копируется | `OwnerId`, `ProjectId`, `RootPath`, `RelativePath`, `SizeBytes`, `ContentType`, `ModifiedAt`, `Hash`, `MissingSince?` |

Соглашения проекта соблюдаются: GUID-первичные ключи, плоский `string OwnerId` на каждой owner-scoped строке, фильтрация по владельцу в каждом эндпоинте (`docs/ARCHITECTURE.md`). Сущности модуля живут в `Data/Entities.IndieDev.cs` — второй файл, а не тридцать: конвенция «всё в одном плоском `Entities.cs`» существует, чтобы не плодить файл на сущность, и разделение по модулю ей не противоречит.

**Обязательная миграция.** Любое из перечисленного трогает `Entities.cs` — значит, `dotnet ef migrations add <Name> --project CedarClerk.Server` в той же сессии, немедленно. `SchemaDriftGuardTests` уронит `dotnet test`, если про это забыть (`.claude/rules/ef-migrations.md`).

## MUST — состав v1 модуля

Порядок — приоритет Марти от 10.08.2026, скорректированный одной зависимостью: десктоп поднят на второе место, потому что Asset Manager без него вырождается в ту же загрузку файлов, что уже есть (ADR-107).

| # | Что | Почему здесь |
|---|---|---|
| 1 | `Project` + `DocumentType` + привязка документов | Фундамент — без него остальное некуда класть |
| 2 | Десктоп-оболочка (Electron + sidecar) | Пререквизит №3, а не самостоятельная хотелка |
| 3 | Asset Manager / Viewer | Названо Марти; единственное, что физически требует локального процесса |
| 4 | Task Tracker (`GameTask` + `TaskLink`) | Названо Марти |
| 5 | Development Planner (`Sprint`, дедлайны, поверх задач) | Названо Марти; поверх №4 и потому дёшево |
| 6 | Локальный глоссарий (scope = проект) | `GlossaryTerm` уже есть, нужна одна колонка |
| 7 | Тегирование билдов и версий | `Draft.Tags` и `DraftRevision` уже есть, нужна структура тегов |

## MIGHT — после v1

Из брифа, ни одно не отменено — просто ни одно не является пререквизитом чего-либо:

- **Press Kit** — самообновляемый генерируемый документ («как `presskit()`, но лучше»). Технически это ещё один рендерер поверх данных проекта, то есть ложится на архитектурную ось «один документ, много рендереров» без нового механизма.
- **References board** — галерея-мудборд.
- **Brainstorm session** — организация сырых мыслей.
- **Game Script Writer** и **Game Plot Writer** — инструменты сценариста, второй короче первого.
- **Game Design Helpers** — помощники в проектировании механик и систем.
- **Workflow planner** — планирование пайплайна разработки.
- **Code Documentation** — просмотр документации кода.
- **Расчёты бюджета**.
- **Новые цели публикации** — см. ниже, риск не в коде.

## Что требует проверки до скоупинга

Четыре цели публикации из брифа архитектурно тривиальны: каждая — реализация `IPublishTarget`, механизм отлажен на Telegram, Bluesky и X. **Риск целиком в чужих API, и его надо снять ресёрчем до того, как строка попадёт в план.** Ни одно из утверждений ниже не проверялось в этой сессии — это гипотезы, требующие подтверждения:

- **itch.io** — публичного API для публикации devlog, судя по всему, нет: `butler` заливает билды, OAuth API читает данные. Может оказаться неосуществимым вовсе, и тогда честный ответ — ссылка на ручную публикацию, а не имитация.
- **Steam** — анонсы делаются через партнёрский Web API; нужен partner-аккаунт и publisher key. Доступно только владельцу изданной игры.
- **IndieDB** — наличие write-API под вопросом.
- **LinkedIn** — UGC Posts API существует, требует app review.

Прецедент, почему это выделено отдельно: очередь сетей в `Q-13` уже один раз перестраивалась после того, как выяснилось, что X с февраля 2026 берёт деньги за пост. Проверять чужие условия до планирования дешевле, чем после.

## Что сознательно не делается

- **Синхронизация десктопа с облаком** — ADR-105. Режим выбирается явно.
- **Вынос публикационных полей `Draft` в отдельную таблицу** — тех-долг, заведён строкой в `docs/BACKLOG.md`; принят как цена ADR-102.
- **Мультипользовательские проекты** — `Assignee` в задаче остаётся свободной строкой. Приглашения соавторов, права и уведомления это отдельный продукт внутри продукта, и ни бриф, ни один пользователь его сейчас не просят.
- **Переименование продукта** — `Q-17`, решает Марти.

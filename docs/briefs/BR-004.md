# BR-004 — Desktop provider sign-in

**Date**: 2026-10-09
**Project**: Cedar Clerk
**Inputs**: `T-442`; the owner's choice of the system-browser handoff over an in-app browser
**Previous brief**: BR-003

## Discussions

- Keeping the provider's pages in the app window: dropped. Google refuses embedded browsers, and the navigation block is a security line of ADR-117.
- A loopback redirect to the local agent instead of a `cedarclerk://` link: dropped. The agent has no part in identity, and the link also brings the app forward.
- Storing codes in the database: dropped. One process serves production and a code lives two minutes; memory needs no migration.
- Redeeming with a fetch from the main process: dropped. A navigation of the window is the certain way to put the cookie in the window's jar.

## Decisions

- ADR-327 — a desktop provider sign-in runs in the system browser and returns by a one-time code bound to a verifier the shell holds.

## Made actions

- Server: `DesktopAuthEndpoints.cs` (`POST /api/auth/desktop/code`, `POST /api/auth/desktop/redeem`, `DesktopHandoffCodes`), registered in `Program.cs`.
- Shell: `cedar:sign-in` bridge call, `cedarclerk://` handling, single-instance lock in `main.js`; `signIn` in `preload.js`; `protocols` in `electron-builder.yml`.
- Web: `/auth/desktop` (`desktop-handoff.component`), the desktop branch in `ExternalAuthService`, the continue-in-browser note on the provider buttons, English and Russian strings.
- Tests added: `DesktopHandoffTests`, `desktop-handoff.component.spec.ts`, one case in the provider-buttons spec.
- Docs: ADR-327 and its index row, `DESKTOP.md`, `SECURITY.md`, `QA.md`, `UI-INVENTORY.md`, `CHANGELOG.md`; `T-442` left `BACKLOG.md`.
- Validation: `dotnet test` 2275 passed; front-end 105 files / 940 specs; `check:icons`, `check:density`, `check:contrast` pass; `npm run build` clean. Against a scratch bot-off server with a throwaway data folder: code refused without a session (401) and with a malformed challenge (400); redeem refused without the header, on replay and with a wrong verifier; redeem with the header set a session `/api/auth/me` accepted and redirected to the asked path; an off-origin return path fell back to `/`.

## Warnings

- The shell half was syntax-checked only. Nothing here ran Electron: scheme registration, `open-url` / `second-instance` delivery and the redeem navigation are unproven until an installed build signs in.
- `/auth/desktop` and the note under the provider buttons were not opened in a browser.
- A packaged build now refuses a second copy. Two windows of the app at once are no longer possible.
- An installed app older than this build keeps the old failure; the page cannot tell it apart from a browser beyond the missing `signIn`.

## Errors

- The scratch server was stopped with a process-name match on `CedarClerk.Server`. That would also have stopped a local dev server or a running desktop app's file agent, had either been up.

# UI Inventory

Per-element inventory of the frontend UI — what exists, where it lives, what it does, and whether it needs (and has) a loading indicator. Complements `docs/design/DESIGN.md` (which covers tokens/CSS patterns, not individual elements). Update this file whenever a UI element is added, removed, or meaningfully changed — that's the point of it: a future session should be able to scan a page's table and answer "does this popup need a loading indicator, and does it have one?" without re-reading the component.

## Format

Two layers, added 30.07.2026 (Phase 10, ADR-070): the **per-element tables** below — one per page/component, six columns, unchanged — and, at the end of the file, a **verification map** with one row per route/surface plus an icon inventory. They are separate on purpose: "does this popup have a loading indicator" and "has anyone opened this screen" change at different times and for different reasons.

Per-element table columns:

| Column | Meaning |
|---|---|
| Element | Short name |
| Location | File + selector/anchor to find it |
| Type | `button` / `modal` / `popover` / `panel` / `toast` / `tab` / `dropdown` |
| Purpose | What it does and why it exists |
| Loading state | Whether a long-running action here needs a loading indicator, and whether one exists today |
| Notes | Anything else worth knowing (gating, known issues) |

## `editor.component` (`cedarclerk-web/src/app/pages/editor.component.{ts,html,css}`)

The main writing surface — by far the most complex page. Since ADR-239 clause 9 it is **one document with three tabs** inside `app-document-frame` (`shell/document-frame.component.ts`, the shell lane's): the frame draws the top bar (project switcher, undo/redo, the save word, the date, the Publish split button), the read-only title with its status tag, the **Write / Preview / Publish** tabs addressed by `?tab=`, and the footer (Share preview · «Synced · saved N min ago · N words» · the next step). **Write** is the editor — the tool strip at the head of one card, the sheet under it, the inspector card beside it (Document, Languages, Outline, Where it goes). **Preview** is `pages/editor-preview/` — destinations with readiness, the server's render, the checks for the selected destination. **Publish** opens the Export modal and keeps the previous tab (T-365 makes the modal's steps the tab's body). Nothing is published into chrome any more: `RailActionsService`/`RulerService` are not called from here, the counts and the sync word are the footer's own, and brand, navigation, theme, Appearance and the account belong to the shell. Write stays mounted behind the other tabs (`.is-hidden`) because TipTap owns the sheet's DOM node.

## shell (`cedarclerk-web/src/app/shell/`)

The paper-first shell (ADR-239, `docs/design/paper-first/CONTRACT.md` §A): the parent route every authenticated screen renders inside, the sidebar that is the navigation, and the three components a page composes its own chrome from — header, document frame, empty state. The `/stats` redirect is a function returning a `UrlTree`, not a string, because a string `redirectTo` is a path and would drop the `?tab=stats` an old metrics bookmark depends on.

Paper first (ADR-239 clause 12): a `.page` root with an `app-page-header`, a `.seg` tab strip, and three `.card` columns on the Posts tab — the 280px post list on the left, the detail sheet in the middle, the 300px inspector on the right (the layout ADR-167 set; the materials are the contract's). `data-density="compact"` is gone — this is a screen you read — and so is the page's own `@media (pointer: coarse)` block, since the global `[data-surface] button` rule already carries the touch floor (ADR-156). Nothing is published into chrome any more: the counts the ruler used to carry are the header's meta line, and the page's one primary action is the header's primary slot. The Metrics tab is `app-stats` inside the page's scroller.

## `comments.component` (`cedarclerk-web/src/app/pages/comments.component.{ts,html}`) — embedded under the selected post in the Posts Manager (FI3.5); `onlyDraftId` scopes it, unscoped still renders every post

**It is a fragment, not a screen, and deliberately not a drawer tab** (ADR-167 clause 9). `/comments` has redirected to `posts` since N7, nothing in the app, the server or the smoke suite links to it, and the component only ever renders inside `posts-manager.component.html`. Moving it into the bench drawer would hang a Feedback tab on every screen — the shell mounts the drawer once — and would need a global "current post" holder, which is chrome reaching into a page's selection (ADR-159 clause 1 exists to stop that). It would also undo ADR-046 clause 4, which put feedback *under the post it belongs to* on purpose. The half of the plan that mattered — never its own screen — already holds. What it did get is the page chrome deleted out of its stylesheet: the `100vh` minimum, its own header, brand name, crumbs and avatar all belonged to the screen it stopped being.

## `teams.component` (`cedarclerk-web/src/app/pages/teams.component.{ts,html,css}`)

T-358 — teams, an account-wide screen reached from the hook rail's tray (`/teams`), like Glossary and Presets. A team is a named group the owner invites people into once; handing it to a project (the project's own edit dialog) gives every active member that project. It grows out of per-project membership (ADR-217) and does not replace it: inviting one person to one board must not require standing a team up first, and a per-project invitation still wins where both exist.

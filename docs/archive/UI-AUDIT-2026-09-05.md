# Interface layout and destructive actions

## Scope and environment

The audit covers the authenticated interface, shared overlays and locally served public pages.
The implementation is on `codex/ui-audit-polish`. ADR-289 records the design rules.
The browser uses the scratch database from `Scripts/e2e.ps1`. The Telegram bot is disabled.
The audit uses English and Russian, light and dark themes, desktop widths and a 390 × 844 phone viewport.
Phone evidence comes from browser emulation. It does not establish physical-device or native Electron behavior.

## Findings and changes

| Priority | Evidence | Result |
|---|---|---|
| High | Some destructive actions changed data immediately. Others used browser confirmation or an inline second click | Shared asynchronous confirmation before deletion, disconnection and access revocation. Existing dedicated confirmations remain |
| High | The editor printed template attributes above its header | Removed the stray text. A regression test checks the rendered frame |
| High | Outline selection scrolled the mobile writing area down to the inspector | Caret tracking scrolls only the shelf. The writing area remains visible |
| High | A new account received a false save-conflict dialog in its first document | Initial version timestamps come from the saved server document |
| High | Four task columns collapsed into narrow strips on a phone | Columns retain a 240px minimum with one horizontal board scroller |
| Medium | Calendar dates crossed the empty-state text. Narrow day cells had individual horizontal scrollbars | The message sits below the dates. Compact cells fit their date labels |
| Medium | Document columns and state controls exceeded the available width | Narrower column defaults, wrapping controls and a folder panel below the list up to 1600px |
| Medium | Search labels disappeared against the dark background | Labels use the surrounding surface ink, with explicit toolbar overrides |
| Medium | Collection selects and filter buttons collapsed to native text height with a mouse | Explicit desktop fallbacks for the surface size variable |
| Medium | Empty project pages showed large dashed areas with little hierarchy | Bounded paper surfaces, accent icons, display titles and wrapped actions |
| Medium | Narrow Preview controls competed for one row | Destination settings sit below the destination strip on phones |
| Medium | Publish settings forced horizontal page scrolling, and Week clipped its date range | Settings columns fit their container; the full calendar title wraps |
| Medium | Existing deletion buttons used the green primary variant | Dedicated deletion controls use the danger variant. Confirmation Cancel controls receive focus |
| Low | The build-publication checkbox separated from its label | The checkbox and label share one aligned row |
| Medium | The public landing header cut off the waitlist button on a phone | Identity and actions wrap into separate rows without horizontal page scrolling |

## Verification boundaries

The audit does not send real publications, messages, invitations or payments.
Live provider callbacks, connected-account states and paid-provider dialogs require their respective accounts.
First-entry evidence uses a separate account created in the scratch database.
The shared components and automated suites cover additional paths. They do not establish visual coverage of every data permutation.

The initial public-page captures lacked static assets in the scratch server configuration.
Those captures are diagnostic evidence, not accepted public-page validation.
Captures 68 onward use the built Angular static directory through `ASPNETCORE_WEBROOT`.
The corrected Russian landing header measures 375px of document width within the 390px viewport, including the browser scrollbar.

## iPad follow-up (ADR-290)

Three supplied portrait screenshots exposed an intermediate-width gap in the initial desktop/phone audit.
The sidebar left too little room for the hub's fixed aside, Showcase columns and full-height task board.
Named CSS containers now base the layout on the remaining work area.

| Surface | Correction |
|---|---|
| Project hub | Stack the aside when needed; keep the title and count together; wrap filters, metadata and long addresses |
| Showcase | Three columns on a wide work area, two with the inspector below at medium widths, one at narrow widths; readable block labels and bounded settings fields |
| Task board | Four statuses fit tablet landscape; compact empty columns; portrait retains a board-only horizontal scroller |

The browser matrix covers 1024x768, 1180x820 and 1366x1024 landscape, plus 820x1180 portrait.
Each size runs in English and Russian with touch enabled, using a separate scratch account and profile language.
Checks cover document titles, containment, block selection, expanded settings, empty and populated tasks, and task dialogs.
Screenshots live in `.e2e-audit/ipad-layout/`; names use `{width}-{language}-{surface}.png`.
This is Chromium emulation. The supplied photos establish the original iPad issue; physical Safari acceptance remains unverified.

`cedar test --smoke` passed: 30 Rust, 1952 backend, 766 frontend and 71 browser tests,
including the eight tablet cases. Eighteen opt-in screenshot jobs were skipped.
Icon, contrast, density and production build checks passed. The local log is `.e2e-audit/ipad-full.log`.
Final tablet captures disable motion so route transitions do not obscure dialog evidence.
Expanded Showcase cards are checked for both horizontal and vertical clipping.

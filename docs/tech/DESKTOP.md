# Десктопное приложение

Решения — ADR-104 (Electron поверх нашего же сервера) и **ADR-117 (одна база в облаке, локальный процесс — агент файловой системы)**, `docs/DECISIONS.md`. ADR-105 (два режима) и ADR-108 (upstream-аутентификация) им отменены — если встретите их в старых записях, это история.

Причина существования — Asset Manager: описать содержимое папки игрового проекта (`MyGame/Assets` на диске разработчика) умеет только процесс, запущенный на той же машине (ADR-107).

> **Построено и проверено 10.08.2026** — оболочка, свободный порт, завершение без сирот.
> **Самообновление 11.08.2026 (ADR-116)** — `cedar deploy --desktop`, установленная копия обновляется сама.
> **Стало клиентом облака 12.08.2026 (ADR-117)** — локальной базы больше нет.
> **`T-121` остаётся открытым одним пунктом**: собранный установщик ни разу не ставился на чистой машине.

## Общая схема

```
┌────────────────────── Electron ───────────────────────┐
│  main                                                  │
│   ├─ CedarClerk.Server.exe с Cedar:Agent:Enabled       │──► обход папки,
│   │     127.0.0.1:<свободный порт>                     │    stat файла,
│   │     Bearer-токен на запуск + выданные корни        │    генерация JPEG
│   ├─ machine.json     { id, name }                     │
│   ├─ granted-folders.json                              │
│   └─ BrowserWindow.loadURL(https://…/projects)          │
│                    │ IPC (preload, гейт по origin)      │
│  renderer ─────────┴─ тот же Angular SPA, но с прода   │
└────────────────────────────────────────────────────────┘
                             │ HTTPS, обычная cookie-сессия
                             ▼
        cedarclerk.mooexe.dev — ЕДИНСТВЕННАЯ база
        AssetEntry: путь + метаданные + превью в thumbs/
        байты ассетов — никогда
```

Ни серверный код, ни фронтенд не форкаются (ADR-101). Angular-сборка — та же, что уезжает на прод; десктоп её даже не хостит, а открывает с прода.

**Кто что делает: агент читает диск, страница отправляет.** У страницы уже есть cookie к облаку — значит, агенту не нужны никакие учётные данные, а Electron не занимается аутентификацией вообще. Побочная выгода важнее экономии: работа идёт в обычном экране с прогрессом и кнопкой отмены, а не в фоновом процессе, о котором нельзя спросить, чем он занят.

## Структура в репозитории

| Файл | Что в нём |
|---|---|
| `CedarClerk.Desktop/main.js` | Запуск агента, токен, гранты, окно, мост, самообновление |
| `CedarClerk.Desktop/preload.js` | Мост IPC с `contextIsolation: true` — единственный канал между страницей и диском |
| `CedarClerk.Desktop/package.json`, `electron-builder.yml` | Electron + сборка установщика |
| `CedarClerk.Server/Modules/Agent/` | Собственно агент: эндпоинты, обходчик, гранты, сервис сканов |

Сборка десктопа — `cedar build`: `npm run build` (Angular) → `dotnet publish -r win-x64` → `electron-builder`. `cedar deploy --desktop` вызывает те же шаги и публикует результат на сервер (ADR-116); без флага деплой десктопа не касается.

## Агент

Тот же `CedarClerk.Server.exe`, запущенный с `Cedar:Agent:Enabled=true`. В этом режиме `Program.cs` **выходит из сборки в самом начале**: ни базы, ни миграций, ни Identity, ни Quartz, ни бота, ни SPA, ни лендинга, ни `/api/*`. Только Kestrel и группа `/agent`.

Ранний выход, а не набор `if` вокруг остального, и это не про аккуратность: так режим агента не может **случайно** получить способность, которую кто-то добавит ниже потом.

| Эндпоинт | Что делает |
|---|---|
| `GET /agent/health` | Версия — по ней оболочка ждёт готовности |
| `POST /agent/grant` | Разрешает папку. Вызывает **только main**, сразу после диалога ОС |
| `POST /agent/scan` | Запускает обход, возвращает `scanId` |
| `GET /agent/scan/{id}` | Прогресс: посчитано, описано, нечитаемых папок |
| `GET /agent/scan/{id}/files` | Страница описанных файлов — **читается, пока обход ещё идёт** |
| `DELETE /agent/scan/{id}` | Отмена |
| `POST /agent/stat` | Один файл заново — для кнопки «Переиндексировать файл» |
| `POST /agent/thumb` | Превью одного файла, JPEG-байтами |

Почему агент остался .NET-процессом, а не переехал в Node: в нём уже лежат парсер превью `.blend` (прямой запрос Марти, `CedarClerk.Core/BlendThumbnail.cs`), парсер WAV и покрытие ImageSharp по TGA/TIFF/QOI/PBM/WEBP. Переписывать это на JS — недели работы и второй набор форматных багов ради экономии 70 МБ, которые ADR-104 уже согласился платить.

### Два замка, и второй не дублирует первый

Прошлый sidecar был обычным Cedar Clerk и закрывался cookie Identity. У агента Identity нет — значит, нужен свой замок, иначе локальный HTTP-сервер, перечисляющий папки, читается любым процессом на машине **и любой страницей в любом браузере** (браузер до `127.0.0.1` дотягивается).

1. **Bearer-токен** — 32 случайных байта, оболочка генерирует на запуск, передаёт агенту переменной окружения, на диск не пишет. Проверяется фильтром на всю группу, а не в каждом обработчике: эндпоинт, добавленный позже, закрыт по умолчанию, а не по памяти. Агент, запущенный без токена, отказывает во всём — отказ закрытый, единственно безопасное направление.
2. **Только выданные корни** — токен говорит «ты оболочка», грант говорит «а вот папка, которую выбрал человек». Сравнение идёт по **разрешённому** пути, потому что `root\..\..\Windows` — строка, начинающаяся с корня, и место, к корню не относящееся. Разделитель в конце тоже важен: без него грант на `C:\Art` покрыл бы и `C:\Artwork`.

**Гранты запоминаются в `granted-folders.json` и восстанавливаются при запуске.** Иначе после каждого перезапуска пришлось бы заново указывать папку только чтобы её перечитать — трение без безопасности: жест был сделан, просто на прошлой неделе. Список лежит **у оболочки** и никогда не берётся с сервера, и в этом весь аргумент: восстанавливать то, что записало облако, значило бы позволить скомпрометированной странице вписать любой путь в корень проекта и попросить его назад. Остаточная цена, названная прямо: **папка, выбранная однажды, остаётся читаемой для приложения, пока файл не отредактируют** — та же сделка, которую браузер заключает с сохранёнными разрешениями на каталог.

CORS у агента нет вовсе: единственный его клиент — Electron main.

## Данные

**Их у десктопа нет.** База одна, облачная; `%APPDATA%\CedarClerk` держит только `machine.json`, `granted-folders.json` и `update.log`.

Из этого следует то, чего раньше приходилось бояться отдельно: **бэкапить у десктопа нечего** (`T-137` закрыт как моот, а не как сделанный). Зато появилась другая цена, и она названа в ADR-117: **без сети десктоп не работает вообще.** Тридцатидневная cookie спасает от повторного входа, но не от отсутствия сети.

`cedar.db`, оставшийся в `%APPDATA%\CedarClerk` от версий до 0.11.0, **никто не открывает и никто не удаляет**. Это данные Марти; убирать их молча оболочка не вправе. Если они не нужны — файл можно удалить руками.

## Идентичность машины

`machine.json` = `{ id: <guid, один раз>, name: os.hostname() }`. Имя обновляется при каждом запуске (переименованная машина должна называться новым именем), id — никогда (переименованная машина — всё та же машина с теми же файлами).

Это то, что даёт экрану ассетов отличать файл от отпечатка: облако помнит, какая машина индексировала папку, а клиент сравнивает с этим id. У браузера моста нет, значит нет и id, значит он всегда показывает отпечатки — и это правда, а не подстраховка.

## Файл или отпечаток

Главное следствие ADR-117 для интерфейса. Индекс живёт в облаке и открывается откуда угодно, поэтому чаще всего экран ассетов смотрит на **отпечатки**: превью и метаданные, стоящие вместо файла, который лежит в другом месте.

- Не совпала машина → чип «Отпечаток» на плитке, в строке и в модалке, подсказка называет машину, и в модалке есть отдельный абзац про то, что именно здесь лежит.
- «Показать в проводнике» и «Переиндексировать файл» **скрыты**, а не заблокированы: серая кнопка приглашает искать причину серости.
- `isLocal` по умолчанию **ложь** — неизвестная машина, проект, проиндексированный до ADR-117, и любой браузер отвечают «не здесь». Ошибиться в эту сторону стоит мёртвой кнопки и секунды сомнения; ошибиться в обратную — обещания, которого никто не выполнит.

Три состояния превью, а не два: **есть** (залито), **будет** (формат превьюшный, но ещё не приехало) и **не будет** (PSD, EXR — их не откроет декодер). Без среднего свежепроиндексированная папка в браузере выглядела бы точно как папка, набитая форматами, которые никто не декодирует.

## Как индексируется папка

```
pickFolder → диалог ОС → grant агенту
  → PUT  /api/projects/{id}/assets/source   { machineId, machineName, rootPath } → scanStartedAt
  → POST /agent/scan
  → цикл: GET /agent/scan/{id}/files → POST .../assets/batch (по 500)     фаза «индексация»
  → POST .../assets/sweep  { scanStartedAt }                              фаза «отмечаю пропавшие»
  → цикл: GET .../assets/thumbs/pending → POST /agent/thumb
          → PUT .../assets/thumbs (по 20)                                 фаза «превью»
```

Оркестрация целиком в `cedarclerk-web/src/app/core/asset-sync.service.ts`.

Три свойства этого потока держат его в рамках:

- **Загрузка идёт за обходом, а не после него.** Агент дописывает список по ходу, страница забирает страницу из 500 сразу, как она появилась. На большой папке это накладывает сетевую цену на дисковую вместо того, чтобы платить их подряд.
- **Проход по превью возобновляем и идемпотентен.** Его ведёт ответ сервера (`thumbs/pending` = всё, у чего `ThumbnailForModifiedAt != ModifiedAt`), а не список, собранный на клиенте. Обрыв на восьмитысячном файле стоит продолжения, а не повторения; запустить догоняющий проход можно через неделю отдельно от скана. **Именно это свойство делает «все превью, без лимита» выполнимым.**
- **Пересканирование не трогает превью неизменённых файлов.** Иначе каждый повторный индекс перекачивал бы всю папку. Превью сбрасывается только когда изменились байты (размер или время правки).

Пределы, потому что это открытый канал записи в облако: ≤500 строк в батче, ≤200 000 строк на проект, путь ≤1024 символов с отказом на `..` и абсолютные префиксы, ≤256 КБ на превью с проверкой magic-байтов JPEG, ≤20 превью за запрос, и потолок `Cedar:AssetIndex:ThumbBudgetBytes` (по умолчанию 2 ГБ на владельца). «Без лимита» — это про отсутствие лимита у автора, а не потолка у дроплета с 45 ГБ свободного диска.

## Мост

Девять функций, и **ни одна ничего не пишет, не удаляет и не запускает**: `machine`, `pickFolder`, `scan`, `scanProgress`, `scanFiles`, `scanCancel`, `stat`, `thumb`, `reveal`.

`shell.openPath` в мост **не входит** — решение Марти. `showItemInFolder` подсвечивает файл в проводнике и ничего не запускает; это разница между чтением и исполнением, и она стоит того, чтобы отказаться от двойного клика, открывающего Blender.

### Граница, которую ADR-117 сдвинул

Раньше окно грузило `127.0.0.1`, то есть «страница» и «наш сервер» были одним и тем же. Теперь окно грузит `cedarclerk.mooexe.dev` — **удалённый origin**, а SPA рендерит TipTap-документы и вставленный HTML. Значит: **XSS на домене превращается в чтение выбранной папки.** Это принятый риск, а не решённая проблема.

Что его сужает:

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webSecurity: true`.
- **Гейт по origin в preload**: мост не появляется на странице, приехавшей откуда-то ещё.
- **Гейт по origin в main** на каждом вызове (`guard()`). Не дубль: проверка в preload выполняется внутри renderer и потому не может быть последним словом о нём.
- **Блокировка навигации** за пределы upstream — окно не должно превращаться в браузер общего назначения, живущий внутри приложения с доступом к диску.
- Bearer-токен и выданные корни у агента (выше).

Константа адреса продублирована в `main.js` и `preload.js` намеренно: sandbox-preload может требовать лишь документированный набор модулей, и `process.argv` — не та поверхность, на которую стоит ставить гейт безопасности. Если две константы разойдутся, мост просто не появится — отказ закрытый.

## Окно открывает `/projects`, а не `/`

Лендинг перехватывает ровно `GET /` без cookie (`LandingEndpoints.UseLanding`), поэтому любой другой путь отдаёт SPA. Незалогиненного `authGuard` уведёт на `/login`.

Это убирает баг, который Марти нашёл 10.08.2026 (приложение открывалось на маркетинговой странице с ценами) **выбором адреса, а не флагом**: `Cedar:Desktop` за этим больше не нужен и удалён. Одним флагом меньше — одним меньше того, что можно выставить неверно на публичном сервере.

## Чем десктопная конфигурация отличается от прода

| Переменная | Что делает | Почему так |
|---|---|---|
| `Cedar__Agent__Enabled` | Превращает exe в агента | **Главная граница.** С ним нет ни базы, ни Identity, ни `/api/*` |
| `Cedar__Agent__Token` | Замок агента | Без него локальный читатель диска открыт всей машине |
| `Cedar__Urls` | Свободный порт от ОС | Два инстанса на машине не могут держать 8080 |
| `Cedar__BotToken=''` | Бот выключен | Агент бота не поднимает вообще; это страховка от унаследованной переменной, и 409 против прод-бота её оправдывает |

Ушли: `CEDAR_DATA_DIR` (нет базы), `Cedar__AssetIndex__Enabled` (нет серверного обхода), `Cedar__Auth__Upstream` (нет локальных учёток), `Cedar__Desktop` (нет лендинга на пути), `Cedar__Registration__Open` (нечего регистрировать локально).

`Cedar:Registration:Open` остался в серверном коде — он всё ещё правильный ответ для self-hosted установки на одного человека, просто его больше никто не выставляет.

## Сверка версий разъехалась по назначению

С версией оболочки сверяется **агент**: они едут одним установщиком, расхождение = битая сборка, диалог оправдан. Версия облака только показывается и **не сверяется**: сайт едет каждым деплоем, установщик — только с `-Desktop`, они расходятся законно (ADR-116), и диалог об этом срабатывал бы после каждого обычного деплоя.

## Сборка и запуск

```
cedar build                    Angular + сервер + десктоп
cedar build --desktop-only     пересобрать только оболочку
cedar build --installer        плюс CedarClerk-Setup-<версия>.exe
cedar build --run              собрать и сразу запустить
cedar open desktop             запустить уже собранное (или установленную копию)
```

`BuildPipeline` синхронизирует версию в `package.json` с `Consts.CurrentVersion`. `CedarClerk.Desktop/server/` — выход сборки (~70 МБ self-contained рантайма), в git не попадает.

**`Scripts/build.ps1` больше нет** (как и `deploy.ps1`/`test.ps1`) — с 12.08.2026 всё это живёт в `CedarClerk.Cli/Pipelines/` (ADR-119). На свежем клоне сначала `.\Scripts\install-cli.ps1`, дальше всё через `cedar`.

## Как приезжает обновление (ADR-116)

```
cedar deploy --desktop
   │
   ├─ обычный деплой сайта (сборка → архив → swap → health) — сайт уже живой
   ├─ сборка оболочки + electron-builder  →  CedarClerk-Setup-<версия>.exe (~119 МБ)
   └─ заливка в  ~/cedarclerk/data/downloads/
         ├─ .exe и .blockmap  →  проверка sha256  →  mv на место
         └─ latest.yml        →  последним
                    │
                    ▼  https://cedarclerk.mooexe.dev/downloads/latest.yml
        установленная копия: проверка при запуске и раз в 4 часа,
        скачивание в фоне, установка при закрытии окна
```

**Порядок деплоя обязателен и в другую сторону тоже: сначала обычный деплой, потом `-Desktop`.** Прод должен получить эндпоинты импорта раньше, чем появится копия, которая в них пишет.

Три вещи, неочевидные каждая по своей причине:

- **`latest.yml` пишется последним.** Это единственный файл, который читает установленная копия. Пока его нет, клиенты видят прошлую версию — незаконченная публикация невидима, а не сломана.
- **Файлы лежат в `data/`, а не в `app/`.** `app/` деплой сносит целиком при каждом релизе.
- **Версии сайта и установщика расходятся, и это нормально.** Постоянная ссылка — `https://cedarclerk.mooexe.dev/downloads/latest`.

**Агент убивается до установки.** NSIS перезаписывает `resources/server/CedarClerk.Server.exe`, запущенный в этот момент дочерним процессом; заблокированный файл сорвал бы установку на середине. Поэтому `stopAgent()` синхронный (`spawnSync`) и вызывается до `quitAndInstall()`.

**И перед этим снимает обработчик `exit`.** `taskkill /f` отдаёт убитому процессу код 1, а на `exit` висело «сервер упал неожиданно» с модальным `showErrorBox`. До обновлений это не было видно: все остальные остановки происходят после закрытия окна, что обработчик и проверял. Установка обновления останавливает процесс при живом окне — и модальное окно вставало посреди выхода, блокируя главный процесс. Поймано Марти на первом настоящем обновлении 11.08.2026. Правило: **остановка, о которой мы попросили сами, не может быть аварией.**

**Обновление ставит та версия, которую заменяют.** Установку выполняет старый код, поэтому любая правка пути обновления начинает действовать только со следующего раза. Единственный обход — поставить новую версию установщиком руками.

**Что происходило, пишется в `%APPDATA%\CedarClerk\update.log`.** У упакованного приложения нет консоли, а обновление заканчивается выходом.

**Подписи кода по-прежнему нет** (`T-145`), и для обновлений это значит больше, чем для первой установки: без сертификата `electron-updater` пропускает проверку подписи и опирается на sha512 из манифеста, полученного по тому же HTTPS. Доверие к обновлению = доверию к `cedarclerk.mooexe.dev`. **С ADR-117 эта строка стала весомее**: тот же домен теперь ещё и получает мост к диску.

В разработке (`npm start`) обновления выключены: рядом с распакованной оболочкой нет `app-update.yml`.

## `npm start`, а не `electron .`

Бинарник Electron — это по совместительству рантайм Node, и `ELECTRON_RUN_AS_NODE` переключает его в этот режим. Её выставляют в своих встроенных терминалах несколько редакторов (VS Code в их числе). Тогда `electron .` выполняет `main.js` под Node: `require('electron')` возвращает **путь к бинарнику**, а не API, и первое же использование падает с

```
TypeError: Cannot read properties of undefined (reading 'handle')
```

— сообщением, которое о причине не говорит ничего. Поймано на первом запуске у Марти (10.08.2026). Поэтому `npm start` идёт через `start.js`, который снимает переменную, а `main.js` в начале проверяет, что `require('electron')` вернул объект.

## Риски, каждый с проверкой

| Риск | Проверка |
|---|---|
| **Доступ к диску у удалённого origin** | Гейт preload по origin + гейт в main на каждом вызове + блокировка навигации + отсутствие `openPath` + токен и гранты у агента. Остаточный риск назван в ADR-117 |
| **Без сети приложение не работает** | Прямое следствие «только облако». Сказано вслух здесь и в ADR-117 |
| Агент открыт другим процессам | `curl http://127.0.0.1:<порт>/agent/scan` без токена → 401 |
| Папка вне гранта | Запрос пути выше корня → 403 |
| «Все превью» на большой папке — долго и объёмно | Возобновляемый проход, отмена, счётчик с мегабайтами, потолок `thumbs/` с внятным отказом |
| Порт занят другим процессом | Свободный порт у ОС (`:0`); проверить с запущенным `dotnet run` на 8080 |
| Агент пережил закрытие окна | Убить дерево процессов на `window-all-closed` и `before-quit`; проверить диспетчером задач |
| Рядом лежит exe от другой сборки | Сверять версию `/agent/health` с версией оболочки |
| Antimalware Service тормозит неподписанный exe | Замерить холодный старт на машине Марти |
| Размер дистрибутива (~119 МБ инсталлер, см. схему выше) | Цена решения ADR-104; фиксируем, не боремся |
| Обновление ставится поверх запущенного агента | `stopAgent()` синхронный, вызывается до `quitAndInstall()` |
| Обновление с подменённого origin'а | Не закрыто: `T-145`, подпись кода |

## Что не решено

- **Установка на чистой машине** — `T-121`: инсталлер собирается и проверен на артефактах, но ни разу не выполнялся там, где нет ни `%APPDATA%\CedarClerk`, ни dev-окружения.
- **iPad** — `T-011` в `docs/tasks/BACKLOG.md`. Electron туда не идёт.
- **macOS/Linux сборки** — технически `electron-builder` умеет, но проверять их некому и не на чем.
- **Подпись кода и нотаризация** — `T-145`: деньги и учётные записи, не техника.
- **Офлайн-режим** — сознательно отсутствует (ADR-117). Если он когда-нибудь понадобится, это снова задача синхронизации, от которой ADR-105 отказался не зря.

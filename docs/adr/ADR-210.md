# ADR-210 — A tenant subdomain is one account's public blog and nothing else

**Context.** The application and every tenant blog are one Kestrel process behind one tunnel. So
`alpha.cedarclerk.app/api/drafts`, `alpha.cedarclerk.app/index.html` and
`alpha.cedarclerk.app/login` all reach real handlers unless something stops them, and an
unregistered subdomain reached the landing page — a marketing page, with a 200, cacheable at the
edge, under a name nobody owns.

**Decision.** A resolved subdomain serves that account's blog, and the rest of the application is
not merely refused there — it is not there.

- **Routing's pick is dropped.** `UseBlogOnlyHost` calls `SetEndpoint(null)` on a tenant request, so
  the API endpoints and the SPA fallback become the 404 they should be rather than the 401 a
  refused-but-present endpoint answers with. `/index.html` is 404 on its own account: it is the one
  file that would boot an application whose API does not live on this host. The rest of `wwwroot`
  keeps answering, because the blog's own pages ask it for fonts and the OG image.
- **A signed-in identity is dropped on any host that renders a blog, and logged.** It is not a
  second opinion about whose request this is: the tenant is already the host's owner, so every row
  that session wrote would land stamped with the *host owner's* id and pass every check on the way.
- **The auth cookie is host-only, stated rather than defaulted.** Setting `Cookie.Domain` would send
  the signed-in owner's cookie to every `name.cedarclerk.app` — which is other people's content
  served by the same process.
- **An unknown or malformed subdomain is a 404 before anything else runs**, ahead of the landing
  page, which is what the marketing-page incident above needed.
- **One question, asked in one place.** `TenantRouting.ServesBlog` — a resolved subdomain, or the
  legacy blog host (ADR-209) — is what the blog branch, the landing page and the static-file segment
  all read. Asking it in three shapes is how a registered subdomain came to answer with a cacheable
  marketing page while the API advertised the same host as a blog.

**Consequence.** A tenant host offers a blog, its assets and nothing that belongs to an account.
Two known gaps stay open against this rule: `UseBlogOnlyHost` gates on "is a tenant request" rather
than on `ServesBlog`, so the legacy blog host is outside it (`T-287`), and `/downloads/*` is
registered unconditionally and answers on every host including subdomains (`T-290`) — public
installers, so a consistency defect rather than a disclosure one.

# ADR-289 — Destructive actions use the shared modal before changing data

## Context

Deletion is inconsistent across the application: some actions use a modal, some use
browser confirmation, and others immediately remove persisted content or access.
The visual audit also exposes clipped collection controls, low-contrast labels on
the night canvas, and calendar empty-state text overlapping dates.

## Decision

- Preserve existing dedicated confirmation dialogs. Other destructive actions use
  one asynchronous confirmation service backed by `app-modal` and Bench buttons.
- Mount the transient confirmation at the document body so it can open above an
  existing editing dialog without inheriting its inert background. The existing
  overlay coordinator owns focus containment, background inertness and focus return.
- Default focus goes to Cancel. Escape and Close cancel; the backdrop does nothing.
  Navigation cancels a pending request. Concurrent requests do not replace its target.
- Name the target or consequence before deleting stored entities, removing authored
  blocks, disconnecting destinations or revoking access. No mutation starts before
  the affirmative response. Keep existing API authorization and error handling.
- Ordinary text editing, clearing a search, and removing a not-yet-uploaded attachment
  remain direct editing operations.
- Repair shared modal wrapping and popover bounds. Use paper-backed, bounded empty
  states and readable search controls; keep calendar dates unobscured. Retain the
  existing warm palette, type scale and page navigation.
- Keep task columns readable through one horizontal board scroller. Outline caret
  tracking scrolls only its shelf, so stacked layouts keep the writing sheet visible.
  Narrow preview controls stack; editor tabs keep one accessible name each.
- Wrap the public landing rail on phones so language, login and waitlist controls
  remain visible without horizontal page scrolling.
- The first editor document uses the server's saved timestamps as its save-guard
  baseline. The browser clock must not trigger a false conflict after onboarding.

## Verification

Exercise cancellation, Escape, focus return, nested dialogs and duplicate requests.
Check the affected pages and overlays in both themes at desktop and phone widths.
Run the canonical frontend, backend and smoke gates before committing.

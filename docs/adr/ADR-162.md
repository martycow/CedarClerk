# ADR-162 — The outline is a view of the document, not a second selection: one clock for structure, another for the caret

**Context.** `ui_kits/writer.html` gives the writer a third column: a 224px shelf headed `Структура` (Structure)
listing every top-level block of the document, indented under the heading it falls beneath, with the
selected block lit. ADR-159 ported the two columns beside it — the worktop in the middle and the
inspector on the right — and left this one out by name: *"Structure shelf (224px, left) — not built,
that is T-225."* The kit's row carries an icon, an ellipsized label and a mono type tag, and its lit
row is drawn with a pine wash and a 2px pine rule down its left edge.

The panel is trivial to draw and easy to get wrong, because it is the first place in the app where a
control both reads the ProseMirror selection and writes it. Three failures are the usual ones. A
component that stores "the current entry" and also sets the document selection has two copies of one
fact, and every write to either has to be suppressed on the way back — a loop, or a flag that
suppresses a real user action alongside the echo. A component that rebuilds its list from the
document on the editor's existing `tick` rebuilds on every keystroke, and `Node.textContent` over
every block of a long post is not free — that is a stutter while typing. And a component that
debounces *both* the list and the highlight makes the lit row lag the caret, which reads as a broken
panel rather than as a slow one.

The editor already has the two things this needs. `onTransaction` fires on every ProseMirror
transaction and bumps `tick`; `scheduleRuDiffRecompute` is the established shape for the work that
must not run on every one of them.

**Decision.**

1. **The outline holds no selection.** `shared/document-outline.component.ts` takes `entries` and
   `active` as inputs and emits `pick`; the lit row is `active()`, and `active()` is
   `blockIndex() - 1` read off `state.selection.$from.index(0)` in the editor. Clicking a row does
   not set anything in the component — it emits, the editor dispatches a ProseMirror transaction,
   the transaction bumps `tick`, and the same derivation lights the row. **The loop is not broken,
   it is unrepresentable**: there is one copy of "where the caret is", it lives in ProseMirror, and
   the panel is a function of it. No guard flag exists, so no guard flag can swallow a real
   selection change — which is the failure the flag would have introduced.

2. **Two clocks.** Structure and caret change at different rates and are recomputed on different
   schedules. The list is a `computed()` over an `outlineVersion` signal bumped **only when
   `transaction.docChanged`**, and then only after a 200ms trailing debounce — the same interval and
   the same reason as the RU diff gutter beside it. The lit row is recomputed on every transaction
   through the existing `tick`, because it is one integer read off the selection and costs nothing.
   Typing rebuilds the list once when the burst settles; the highlight never lags a keypress.

3. **A stale list may not dispatch a bad position.** The debounce means the entries on screen can
   describe a document that has since lost blocks, so `goToBlock` re-reads `doc.childCount` and
   refuses an index past the end rather than resolving a position that no longer exists. The
   position itself is `topLevelStart`, a pure function over the top-level node sizes, so the
   arithmetic that would silently land the caret in the wrong block is the part with a spec.

4. **What the click selects depends on the block, because the inspector is watching.** ADR-159
   clause 5 makes a `NodeSelection` the only thing that counts as an object being selected. So an
   atom the schema is willing to select — an image, a video, a gallery — is picked as a
   `NodeSelection`, which lights it on the sheet and fills the inspector; anything else takes
   `TextSelection.near` at the block's start, which is a caret to keep typing from. One click, and
   the two shelves agree about the subject.

5. **Indentation comes from the preceding heading, because a TipTap document is flat.** The kit's
   nesting is drawn, not structural: `doc` has one level of children and no tree to walk. A heading
   of level *L* indents *L−1*; every other block indents to the level of the nearest heading above
   it; both clamp at two steps, which is as deep as the kit goes and as deep as 224px affords.

6. **The kit's mono type tag does not port; its information moves.** At the kit's 9.5px the tag is
   nearly free, and on paper it is not: the shelf's sheet is paper (ADR-138), whose floor is 14px,
   and a 14px mono tag would take a third of a 224px column away from the label it sits beside. The
   type is carried by the icon for a sighted reader and by a visually-hidden word inside the row's
   accessible name for a screen reader — `H2`, `Image`, `List` — so nothing is lost except the
   duplicate. A block with no words of its own is labelled by its kind, and a media block by its
   file name, which is what the kit draws for the one image it shows.

7. **The outline is navigation, so it is operable without a mouse and lit by more than colour.** One
   tab stop, roving `tabindex`: entering the panel lands on the current entry, Up/Down/Home/End
   browse without touching the document, Enter or Space commits and moves focus into the sheet. The
   current entry carries `aria-current="true"`, a 2px accent rule down its left edge and a bold
   label — a state word, a shape and a weight, of which only the rule is a colour. The left rule is
   written `:not(:focus-visible)` so it cannot out-specify the global focus halo (ADR-140).

**What was rejected.** *A `selected` signal inside the component, synced both ways.* It is the
second copy of one fact, and the guard that stops it echoing is the guard that eventually eats a
real click. *Rebuilding on the existing `tick`.* It is the stutter, and it would have looked fine on
a three-paragraph test document. *One debounce for both directions.* A lagging highlight is read as
a bug, not as a delay. *`role="listbox"` with `role="option"` rows.* The rows are buttons, the global
touch floor already reaches `[data-surface] button` (ADR-156), and overriding a button's role to
`option` would have cost that floor to buy an ARIA pattern a nav list does not need. *A collapse
control in the shelf header,* which the kit draws: it needs a persisted preference to be anything
other than annoying, and the width question it half-answers belongs to `T-236`.

8. **224px is a token, because the family already exists.** `--bench-dock-w-narrow` joins
   `--bench-dock-w` and `--bench-dock-w-wide` in `styles.scss`. The port's rule is tokens only, and
   the alternative to adding one was spending the 300px dock on a column the kit draws at 224 — a
   76px error carried by every screen that copies it. T-224's report named "no token for a shelf
   column width in a page layout" as a gap; this fills the one case it hit.

**Consequence.** The writer now spends 224px on the left and 340px on the right of a sheet the
Appearance preference sizes independently. ADR-159 recorded that the inspector and the sheet begin
to fight below roughly 1100px; the outline moves that number up, and nothing here addresses it —
ADR-147 defers every width rule to the commissioned designs, and this is the second entry pointing
at `T-236` for the same answer.

The shelf's counter and the rule's `block N / M` are the same number from the same source, so they
cannot disagree. The list itself can disagree with the sheet for up to 200ms after a structural
edit — that is the debounce, it is deliberate, and clause 3 is what keeps a click during that window
from doing damage rather than what makes the window shorter.

`Node.textContent` is walked for every top-level block on each rebuild. On a post of a few hundred
blocks that is cheap and bounded by the debounce; on a document large enough for it not to be, the
fix is an incremental rebuild keyed on which children the transaction's steps touched, and this
sentence is where the ceiling is written down rather than found.

# ADR-132 — Sprint → devlog draft: the assembler writes the material, not the story (18.08.2026)

**Context.** T-158, feature No. 1 of the competitor analysis: closed tasks, the sprint and the build assemble into a devlog draft with one button — none of the four competitors connects "work" to "story". The ingredients exist: `Sprint`, `GameTask.CompletedAt`, `Build.ReleasedAt`, and the T-126 precedent of generating a real document (the changelog). What was missing is the assembler over a sprint.

**Decision.**
1. **`POST /api/sprints/{id}/devlog` produces a `Draft` of type `post`** — publishable, because that is the whole point ("edit, publish everywhere"). The changelog stays its own type; a devlog is an announcement, not shipping notes.
2. **The skeleton is material, not prose**: an empty opening paragraph (the story is the author's), then "What got done" — one bullet per task finished in the sprint, ordered by completion; "Released" — each build whose `ReleasedAt` falls inside the sprint window, version plus its notes; "What's next" — the sprint's still-open tasks. Sections with nothing in them are omitted, not rendered empty.
3. **Section headings follow the document's language** (ru/en, en for the rest) — a hard-coded three-entry map, not a localization system: generated content is the author's to edit, and two languages cover the operator and the market. The document's language comes from the request or the account default, same as the changelog.
4. The JSON node helpers the changelog generator kept privately (`Heading`/`Paragraph`) move to a shared `DocJson` so the second generator does not become the second copy.
5. The button lives on the planner's sprint card and opens the created document — same flow as the builds screen's "Changelog".

**Consequence.** "Per period" (a devlog over an arbitrary date range, for people who do not run sprints) was considered and deferred: the sprint is the container the module already sells, and a date-range picker is a second UI for the same assembler — add it when someone without sprints asks. The assembler reads `CompletedAt`, which T-123 deliberately stores rather than derives — this is the feature that cashes that decision in.

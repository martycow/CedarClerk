# ADR-137 — The contract token names are an API: flat colours in the base blocks, bench materials alongside

**Context.** With one look and no skin attribute (ADR-136), the Cedar Bench values land in the bare `:root` block at `cedarclerk-web/src/styles.scss:9` and in `:root[data-theme="dark"]` at `styles.scss:178`. Those two blocks are not merely where the palette happens to live — they are the only thing four separate consumers read, and none of them reads anything else:

- `cedarclerk-web/tools/check-contrast.mjs:30-31` builds its light and dark variable maps from exactly those two selectors and measures a fixed pair table against thresholds. It is a phase of `cedar test` (`CedarClerk.Cli/Pipelines/TestPipeline.cs:79`).
- `cedarclerk-web/tools/generate-design-tokens.mjs:40-41` reads the same two blocks, filters them through the 25-name `WANTED` list at line 17, and writes `CedarClerk.Core/DesignTokens.generated.cs`. That file is inlined into the blog (`BlogEndpoints.cs:2744-2745`), the landing page (`LandingEndpoints.cs:301-302`) and the single-file export (`DraftEndpoints.cs:1767-1769`) — ADR-090's mechanism.
- `CedarClerk.Tests/DesignTokenDriftTests.cs` pins ten names by `[InlineData]` and compares the raw declaration text against the generated copy.
- `cedarclerk-web/src/app/core/appearance.service.ts:124` injects `:root{--accent:…}` at runtime from the user's saved preset.

Under the skin, all four saw the default palette and none of them saw forest — ADR-120 states that hole plainly. Bench in the base blocks closes it, and the price of closing it is that these names stop being a palette and become an integration surface. A rename is no longer a refactor.

**Decision.**

1. **The contract is a closed list of names, and they keep their exact spelling in both base blocks.** Surfaces `--bg --canvas --surface --sheet --alt`; text tiers `--text --t2 --t3`; status `--accent --danger --ok --warn`; boundaries `--border-strong` and `--border`; accent derivations `--asoft --abord`; data `--series-1` … `--series-6`. Each is load-bearing for a stated reason: the checker's pair table dereferences `vars[p.fg]` and `vars[p.bg]` directly, so a missing name is a `TypeError` that kills the run rather than a skipped check (`--border` and `--abord` carry no pair by ADR-074's deliberate exemption, and are load-bearing through the generator only); `WANTED` decides what crosses to the server surfaces at all; the drift test pins `text t2 t3 accent danger ok warn border bg surface`; `--accent` alone is also written at runtime by the appearance service. The non-colour carriers in `WANTED` — `--shadow`, `--font-sans/-mono/-serif`, `--fs-read`, `--lh-read`, `--radius-sm/-md/-lg` — are part of the same contract and follow the same naming rule.

2. **The colour tokens in the contract hold flat colours.** The non-colour carriers named above — `--shadow`, the three font stacks, `--fs-read`, `--lh-read`, the three radii — are exempt from this clause and bound only by rules 3 and 4. For the rest: a literal hex, or a `color-mix(in srgb, …)` whose operands are themselves contract names — nothing else. A gradient on one of them fails **twice**: `resolveColor` in the checker has no gradient branch and throws `cannot resolve: linear-gradient(…)` uncaught, so `cedar test` goes red with a stack trace rather than a failing pair; and the generator resolves nothing at all, survives, and writes the gradient string into `DesignTokens.Light`, which `BlogEndpoints` then paints where a flat colour is expected. Loud first, silent second. For `--border` and `--abord` only the silent half fires.

3. **A contract token never points at a name outside the contract.** `--bg: var(--wood)` passes the checker (which has every variable in the block) and reaches the blog as a dangling reference, because `WANTED` filtered `--wood` out. This is not hypothetical. `--fs-read` ships as the literal string `var(--fs-17)` (`cedarclerk-web/src/styles.scss:145`) and `--fs-17` is outside `WANTED`, so `LandingEndpoints.cs:145` — the one line there that reaches for a contract name — resolves to nothing on the served page. The other eight `var(--fs-*)` in that file (147, 168, 169, 174, 176, 178, 185, 192) name `--fs-caption`, `--fs-body` and `--fs-ui`, which are outside `WANTED` to begin with: the same blank result by the simpler route. This ADR repairs neither; it names the rule the first one breaks. The direction of aliasing is therefore fixed: **the contract name holds the value and the material name aliases onto it**, never the reverse.

4. **Bench material names are additive.** `--wood --paper --pine --brass --resin --rail-ink --bench-*` and the rest are added beside the contract, not in place of it. No material may shadow a contract name, and none may be declared above the `:root` block: `DesignTokenDriftTests` matches the first `--<token>:` occurrence in the whole file, and both tools anchor on the first `:root` string in it — the incident recorded in the comment at `styles.scss:1-6`. For the same reason V2's `--text-<size>` scale names (`--text-2xl` through `--text-stamp`) are not imported at all — sizes stay on `--fs-*` — and its `--text-body`/`--text-muted`/`--text-faint` colour roles are not imported either, because `--text`/`--t2`/`--t3` already hold them. The three dense-chrome *role* names ADR-138 keeps (`--text-chrome`, `--text-chrome-sm`, `--text-readout`) are neither scale names nor contract names; they resolve to `--fs-*` and their numbers are ADR-138's subject, not this one's.

5. **The call-site rule.** If the value answers a *role* question — what colour is body text, an error, the page ground, the third chart series — the contract name is used. If it answers a *material* question no role covers — the brass of a pin, the resin of a drop, the ink on the rail — the material name is used. **Where the two are the same swatch, the contract name wins.** This is not preference: only the contract name is measured by the checker, carried to the blog and the landing page, and moved by the user's accent preset. A primary button painted `--pine` looks identical today and stops following the accent the user chose in Appearance the moment either value moves.

   The mapping this produces for the ink tiers is worth spelling out once, because it is the one the mirror will fight: `--text-body` → `--text`, `--text-muted` → `--t2`, `--text-faint` → `--t3` — and `--t3` does not carry content (ADR-074). `--ink-3` #93866B measures **3.32:1 on `--paper` and 2.99:1 on `--paper-2`**, while V2 puts chart axis numbers, `Worktop` labels, `LogLine` timestamps and `ModuleTile` sublines on it. Those call sites take `--t2`.

**Rejected.** Renaming the contract to bench's vocabulary and updating the tools in the same commit — buys evocative names, pays with ten `[InlineData]` pins, the checker's pair table, `appearance.service.ts`, and every component declaration in the app, during a port that already has enough to be wrong about. Making everything `--bench-*` and aliasing the contract onto it (`--text: var(--ink)`) — the generator ships the alias rather than the colour, per 3. Teaching `generate-design-tokens.mjs` to resolve values so aliasing would be safe — that means a second copy of the checker's `var()`/`color-mix()` resolver, forty lines maintained twice, to buy back a freedom a one-line rule already grants.

**Consequence.** Two vocabularies share one block, and a reader has to know that `--pine` and `--accent` can be the same colour with different obligations. The half kept as canonical is the less evocative one — `--wood` says what a thing is made of, `--canvas` says what it is for — and it is kept because it is the half with tests behind it. `WANTED` is now the whole border of what a server-rendered surface may reference; anything outside it must be defined server-side or not used there. Adding a token to the contract is four steps, not one: both base blocks, a checker pair with a stated threshold, `WANTED` if a server surface needs it, and `npm run tokens:generate` re-run so the drift test stays green. Extends ADR-071 principle 2 (one palette, product-wide) and principle 6 (the blog is inside the system), and ADR-090's generated-token mechanism.

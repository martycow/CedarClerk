# ADR-249 — The editor starts with the document, not its chrome (02.09.2026)

**Context.** The document frame stacks a utility bar, repeated document heading, low-emphasis tabs,
body padding and the editor toolbar before the first line of the document. Write, Preview and
Publish read like minor links even though they are the editor's primary states. The sheet then caps
at 1040px in its widest mode, leaving most of a wide workspace unused. The title ellipsis repeats
Posts navigation and History, while the labelled Details button competes with the title.

**Decision.**

1. One compact frame header carries document context, the single sync indicator and three equal
   Write, Preview and Publish / Export segments. Each segment is a full target with an icon, label,
   non-colour selected mark, `role="tab"`, `aria-selected` and the existing keyboard behaviour. The
   selected state meets the non-text contrast requirement.
2. The repeated frame title row and duplicate sync copy are removed. The editable title inside the
   sheet remains the document title. TipTap stays mounted while another editor state is visible.
3. The ellipsis is removed. *Open in Posts Manager* keeps its one home in sidebar navigation.
   History becomes a secondary Write footer action and remains available in the inspector.
4. Details becomes a compact pane toggle at the edge of the Write toolbar. It has a tooltip,
   `aria-label`, `aria-pressed` and `aria-controls`. The stored inspector state and Preview's *Fix*
   actions keep working.
5. Sheet measures become Narrow 640px, Normal 760px and Wide 960px. Full has no fixed maximum and
   fills the available editor centre with the existing safe inset. This supersedes ADR-035's width
   values. The preference remains explicit; a document is not forced to Full.
6. The footer keeps one primary next action for each state. It may carry contextual secondary
   actions, but it does not repeat status already present in the header.

**Rejected.** *Make the type smaller* — the number of stacked bands remains. *Remove Details with
no replacement* — the inspector contains unique document controls. *Conditionally mount Write* —
TipTap would lose selection and transient state. *Make every document Full* — readable measure is a
valid user preference.

**Consequence.** ADR-242 clause 4 is superseded for History, Posts Manager and Details. ADR-239's
separate title and tab bands are superseded. The publish pipeline, preview renderers and document
model do not change. Component and smoke tests keep the three-state URL contract, mounted TipTap,
keyboard tabs, inspector focus and preference reload.

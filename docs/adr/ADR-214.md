# ADR-214 — Icon size is corrected per glyph, in the viewBox, not in the drawing

**Context.** Phosphor draws every glyph on the same 256-unit canvas but lets each shape fill it to
whatever width the shape wants. Measured across the 106 icons the app carries, the painted extent
runs from 192 units (`check-square`, `shield-check`) to 240 (`game-controller`, `sun`, `eye`) — a
quarter's difference at one nominal size. In a row of unrelated icons nobody notices; in the hook
rail, where nine of them sit one under the next at `--icon-sm`, it is three pixels of difference
between neighbours and reads as a set that was never sized. ADR-142 accepted the optical mismatch
against the Cedar Bench kit and said the alternative was redrawing 94 glyphs; this is the case it
did not cover, which is Phosphor against itself.

**Decision.** `tools/generate-icons.mjs` measures each glyph's painted bounding box and emits
`ICON_BOXES` — a per-icon `viewBox` that cancels the difference. A wider canvas holds the same
drawing smaller, so nothing about the artwork changes; the markup stays byte-identical to the
package's, and `app-icon` binds the box instead of hardcoding `0 0 256 256`.

The correction is bounded rather than absolute, because most of the spread is the designers' own
judgement and only the tails are wrong:

- Only glyphs filling the canvas in **both** axes are measured against the target. A caret, an
  ellipsis, a `+` are deliberately smaller than a cube, and normalising them would be the same
  mistake in the other direction.
- The scale is clamped asymmetrically — down a tenth, up a twentieth — which cuts the spread of the
  rail's icons from 25% to 7% without any single glyph changing character.
- Anything within 2% of the target is left exactly as drawn, so two thirds of the set is untouched.
- The measurement runs on the regular weight and applies to every weight. Bold is the same drawing
  with a fatter stroke, so its extents are uniformly larger, and correcting it separately would make
  an icon behave differently at one weight than at another.

Centring is **not** corrected. The worst off-centre glyph in the set misses by 12 units, which is
half a pixel at `--icon-sm`, and a bbox centre is a poor stand-in for an optical one on an
asymmetric shape — the fix would cost more than the flaw.

**Consequence.** Icon sizing is one generated table rather than a per-call-site adjustment, which is
what ADR-072 bought the single `app-icon` component for. The price is that a scaled glyph's strokes
scale with it: an icon brought down a tenth draws a tenth lighter, the same as rendering it at a
smaller pixel size. Within the clamp that is under a fifth of a stroke unit and invisible; widening
the clamp would make it visible, and that is the reason the clamp exists.

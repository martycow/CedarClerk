# ADR-104 — Desktop: Electron over the existing server as a sidecar (10.08.2026)

**Context**: the brief asks for a desktop app — the reason is stated directly: "Asset management will definitely need some local application." The `T-010` line sat in the backlog as Low with the wording "on top of the existing code" and no mechanism at all. The choice was made by Marty on 10.08.2026 out of four options (Electron+sidecar, Tauri+sidecar, PWA only, native Avalonia/MAUI).

**Decision: an Electron shell launches the existing `CedarClerk.Server` as a local process and opens the same Angular SPA in a window.** Neither the server code nor the frontend gets forked. The full mechanism is in `docs/DESKTOP.md`.

**Why not Tauri**: it saves ~140 MB of distributable size and a noticeable share of memory, but brings a stack unfamiliar to Marty (Rust) and WebView differences across OSes — and the whole point of the decision is that the shell is thin and barely needs developing. The size savings don't pay for a second unfamiliar tool in a project that already carries .NET + Angular + TipTap.

**Why not a PWA**: it doesn't solve the problem the desktop app is being built for. A browser can't index a Unity project folder — the File System Access API requires a user gesture for every folder and doesn't work in Safari/iPad, meaning the Asset Manager would only ever work with uploaded files.

**Why not a native client (Avalonia/MAUI)**: the editor is TipTap, meaning a WebView either way, and all the remaining UI would have to be written again from scratch and then maintained in two copies. That's a fork of the frontend under a different name, which is exactly what ADR-101 avoids.

**The key saving**: `CEDAR_DATA_DIR` already exists and already controls where SQLite and media live (the systemd drop-in on the Pi, `.claude/rules/production-environment.md`). Desktop sets the same variable in `%APPDATA%/CedarClerk` — and as far as storage goes, the server code doesn't change at all. One exception was found while writing this ADR: the listen address is hardcoded (`app.Run(Consts.URLs.Localhost)`, i.e. `http://localhost:8080`) rather than read from configuration, so `ASPNETCORE_URLS` gets overridden by it. Desktop needs a free port — so exactly one line of `Program.cs` becomes configurable, with the same default value as before. The bot on desktop turns itself off, because without a token `TelegramBotService.IsRunning` already returns false by design; this isn't a convenience, it's protection against a 409 (`.claude/rules/telegram-bot.md`), which would otherwise fire every time Marty opens the desktop app while the Pi is live.

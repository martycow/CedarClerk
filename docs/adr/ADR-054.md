# ADR-054 — FI5: real social icons, two more header-slot types, per-language signatures
**Context** (28.07.2026): `docs/BACKLOG.md` FI5 — Settings' social-links row used generic Lucide glyphs that don't read as their brands (an @-sign for Twitter/X, a thumbs-up for Facebook), "more slot types" for the header-slot system (currently AuthorSignature/Url/MapLocation/PublishedDate/Length/TimeToRead), and multi-language post signatures — the last one explicitly unblocked this session by NF2 (six content languages decided).

**Decision**:
- **Real brand marks, inlined rather than a new dependency.** Lucide has no brand/logo icons at all (checked the full type-definitions file — zero hits for github/twitter/instagram/facebook/youtube), and the project's own rule is `@lucide/angular` only (`docs/ARCHITECTURE.md`). A new `app-brand-icon` component (`shared/brand-icon.component.ts`) inlines the standard single-colour SVG paths for X/Instagram/Facebook/YouTube/GitHub directly — nominative use, same as any site's footer social row, no new npm package.
- **Two more header-slot types**: `WordCount` and `ViewCount`, added to `HeaderSlotType` (Core) and `HeaderSlotRenderer`. Both reuse data the caller already computes for other slots (`Length`/`TimeToRead` already derive word/character counts; the per-post view count was already computed for the post-meta views line) — no new storage, no new query. Considered and **rejected**: a `ContentLanguage` slot (redundant with the visible language switcher already on the page) and a `SocialLinks` slot (the renderer's `HeaderSlotValue(Text, LinkUrl)` shape only carries one label+link, not a multi-icon row — a bigger reshape than this pass warranted; social links still aren't wired into any blog display, unchanged from before).
- **Signatures follow the exact pattern already established for cross-links** (ADR following ADR-039's `LocalizedTextMap`): `ApplicationUser.PostSignatureTranslationsJson` (migration `AddPostSignatureTranslations`) alongside the existing primary-language `PostSignature`, resolved via `LocalizedTextMap.Pick(postSignature, translationsJson, lang)` at every one of the four read sites (live blog page, Telegram publish, `.cedar`-style HTML export, the `.zip` export's per-language loop — the last of which had been quietly applying the *primary* signature to every language's page in the archive, since no per-language mechanism existed until now). **Only the text is per-language, not the URL** — a personal link doesn't change meaning by language. The Pro gate (`PlanLimitations.HasCustomSignature`) now also covers the translated map, not just the primary fields, closing what would otherwise have been a way to set a custom signature on a Free account by only ever touching the non-primary languages.

**Consequence**: `AuthEndpoints.SignatureRequest` gained an optional `SignatureTexts` dictionary; `POST /api/auth/signature` and `GET /api/auth/me` both now carry `postSignatureTexts`. `SettingsComponent` gained the same "hold every language in a local dict, switch the two visible fields, one Save sends the lot" shape `blogLinkText`/`telegramLinkText` already used, rather than a second bespoke mechanism. `dotnet test` 349/349 (2 new `HeaderSlotRendererTests` cases), `ng build`/`ng test` clean. Not yet live-verified in a browser, and the migration has not been applied against the production database yet.

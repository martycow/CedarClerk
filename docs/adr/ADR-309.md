# ADR-309 — Editorial landing with admin-owned copy

## Decision

Implement the selected centered landing concept in the existing server-rendered page. Use shared paper, pine and typography tokens, a large uploaded product screenshot, a three-step publishing explanation, an optional live showcase, compact plans, FAQ and a closing invitation.

Admin → Landing remains the single editor. Preserve existing saved headlines, screenshots, captions, section switches, roadmap, story and showcase host. Add a nullable JSON dictionary of bilingual editorial overrides for the new section titles, descriptions, workflow steps, FAQ and closing invitation. Missing or blank overrides use localized defaults. An omitted dictionary in an older save request preserves stored overrides.

Prices, quotas, language count and supported publishing destinations remain derived from product definitions. Discovery continues to use its consent-filtered snapshot and its existing admin controls. No invented maker content, prototype publishing controls or generated article illustration ships on the marketing page.

Keep the anonymous waitlist endpoint, honeypot, modal signup, language negotiation, cache variation and consent gate. Headline markup permits only line breaks; all editorial prose is escaped. Uploaded screenshots remain in the data directory.

## Consequences

One additive nullable column requires a migration; existing settings need no rewrite. Existing admin content can have different line lengths and screenshot ratios from the mock, so the layout is responsive and does not crop product screenshots. The page uses two existing font roles: display and sans. Roadmap, Story and Download remain optional sections. Feature details remain available inside one disclosure rather than dominating the page.

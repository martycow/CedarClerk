# ADR-191 — Martian Mono replaces --font-mono's system stack, product-wide (23.08.2026)

**Context.** Marty asked for Martian Mono on the blog. `--font-mono` has never been a real face — it
was `ui-monospace, Menlo, Consolas, monospace` from the token's introduction, and ADR-180 looked at
replacing it directly rather than adding a role beside it, then rejected that: of the 53 rules pairing
`font-family: var(--font-mono)` with a size, four in five sit off Departure Mono's 11px grid, and "the
system stack is what a code block wants: at 13px in a post body the reader needs a coding face, not a
texture." Departure Mono became `--font-readout` instead, fenced to 11px.

Martian Mono is a different shape of face than Departure Mono — a proportioned geometric mono with
weights up to 800, not a bitmap font bound to one pixel grid — but it is exactly as distinctive, and
ADR-180's readability argument does not evaporate just because the face changed. It was put back to
Marty in those terms, with three shapes on the table: reopen ADR-180's rejected option product-wide, add
a second named role beside `--font-mono` the way Departure Mono got one, or confine it to the blog's
code blocks only. Marty chose the first, explicitly.

**Decision.**

1. **`--font-mono` becomes `'Martian Mono', ui-monospace, Menlo, Consolas, monospace`, in the one
   `:root` block both the app and the server-rendered surfaces read (ADR-071 principle 2, ADR-177).**
   There is no blog-only token to change into — a scoped version would need a second role and a second
   set of call sites naming it, which is the shape Marty turned down.
2. **Self-hosted the way the other four faces are (ADR-143), not linked from Google.** `@fontsource/
   martian-mono` ships the same subset shape — one file per weight per named subset — so the six
   `@use` lines in `styles.scss` and the `latin`/`cyrillic` glob in `angular.json` mirror Vollkorn's
   and Source Sans 3's entries exactly. ADR-143 clause 3's one-origin argument was never about which
   face, and does not get revisited per face added.
3. **Three weights: 400, 600, 700 — every weight a call site of `--font-mono` actually asks for**,
   app and blog alike (`.chip-count`, `.lang-switch-btn`, `.series-part-no`, `.react-btn .count`
   among them). Narrower than the four faces' full sets only because nothing calls for a fourth
   weight, the same reasoning ADR-178 clause 4 used to leave Source Sans 3 700 and Caveat off the
   server's copy.
4. **The blog's copy follows ADR-178's mechanism unchanged**: the six files land in
   `assets/fonts` unhashed, and `DesignTokens.FontFaces` grows six more `@font-face` rules, each
   with the `unicode-range` clause 3 of that decision requires — taken from `@fontsource/martian-mono`'s
   own `index.css`, and identical to the ranges the other four faces already use, because Google's
   subset boundaries are shared across families.

**Rejected.** *A second named role, `--font-mono-display` or similar, beside a system-stack
`--font-mono`.* This is the shape ADR-180 used for Departure Mono, and it was offered; Marty asked for
the replacement instead. *Blog-only, via a second token the blog alone reads.* Breaks ADR-071 principle
6 the same way a blog-only palette once did — the two surfaces would carry different code-block type
under names that claim to be the same token. *Making Departure Mono do this instead of adding a sixth
face.* Wrong shape of font for body text and code at 13–21px, which is exactly what ADR-180 already
established and this decision does not reopen.

**Consequence.** `--font-mono` now names a real face everywhere it is read — the app's dates, counts,
tags and code blocks, and the blog's alongside it — closing the gap ADR-180 left standing (Departure
Mono covers 11px readouts; the rest of mono typography, until now, covered nothing of its own). ADR-180
clause 1 and its "Rejected — making it `--font-mono` product-wide" line are superseded by this entry for
`--font-mono` specifically; `--font-readout`'s own 11px-only contract is untouched, and Departure Mono
still fills it. Whether Martian Mono reads well in a dense `pre` block at 13.5px, as opposed to the
short numeric strings most `--font-mono` call sites actually are, was not measured against real post
content before this decision — it is asked for, not benchmarked, and is worth Marty's eyes on a real
post before this ships to production.

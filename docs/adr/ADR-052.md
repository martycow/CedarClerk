# ADR-052 — Header/nav redesign: one shared glass header across all six screens
**Context** (27.07.2026): Claude Design brief + spec (`Cedar Clerk Redesign Spec.dc.html`) covering the editor topbar plus the four "secondary" headers (`/posts`, `/glossary`, `/settings`, `/admin`). Those four had already drifted into two different visual styles — glass on Posts/Admin, solid `--surface` fill on Glossary/Settings — and none of them offered real navigation between each other; the only way to jump from Glossary to Settings was the account popover. ADR-046's own consequence note had already flagged "extracting a shared chrome component would be a real improvement" as deferred, not rejected.

**Decision**:
- **New `app-page-header` (`app/shared/page-header.component.*`)** replaces the four near-identical header blocks (plus `/drafts`', which the design brief's 5-screen list didn't cover but which would otherwise have lost its only route to Posts/Glossary/Settings once the account popover stopped carrying them — see below). Takes a `page` input (`'posts' | 'glossary' | 'settings' | 'admin' | 'drafts'`) and an optional `showBack` (false only for `/drafts`, the post-login landing screen with nothing to go back to).
- **Every header now carries the same glass material** (`--glass`/`--blur`/`--glass-border`/`--gloss-top`) the editor topbar and Posts/Admin already had — Glossary and Settings pick it up for the first time. Applied directly to the header element (the pattern 3 of 4 pages already used), not via the editor topbar's `::before`-pseudo-element/`isolate` trick — none of these four pages have a `position:fixed` descendant inside their header that a backdrop-filter containing block would break.
- **Nav row (Posts/Glossary/Settings/Admin) ships on every header**, same shape as the editor topbar's existing `.nav-btn` (I11) — current page fills with `--accent`, exactly like the editor's `.export-btn.on`. No new `NavButton` component: this is the same soft-button-plus-active-state pattern already in use, just reused instead of copy-pasted four more times.
- **`AccountMenuComponent` lost its `showNav` input and the entire nav-links branch.** With a nav row on every screen, the popover's own Posts/Glossary/Settings/Editor links were pure duplication (the design decision that triggered this: "показывать nav-ряд… аватар-меню… showNav=false everywhere"). The popover is now just Profile, Admin-if-applicable, and Logout, everywhere, with no per-page flag.
- **Two small token/consolidation fixes bundled in, both flagged safe by the spec**: `--shadow-lg` (`0 24px 64px rgba(0,0,0,.30)` light / `.6` dark) added to `styles.scss` and `modal.component.css`'s hardcoded box-shadow (which was silently using the *light* alpha in dark mode too) now references it; and a `--fs-9…--fs-27` font-size scale was added to `styles.scss` (values lifted from what the app already used, not invented) for the new header component to reach for — **not** a repo-wide hardcode-replacement sweep, which stays open tech debt.
- **`.btn-accent`/`.btn-ghost` global consolidation was explicitly left out of this pass.** The spec's brief flagged real drift here too (5 different padding/font-size/display values across editor/settings/admin/drafts/posts-manager component CSS), but unlike the header blocks these classes are used throughout each page's body content, not just chrome — auditing every call site was too large a surface for this change. Still open; see `docs/BACKLOG.md` candidate.

**Consequence**: `posts-manager.component.ts/css`, `glossary.component.ts/css`, `settings.component.ts/css`, `admin.component.ts/css` and `drafts.component.ts/css` each lost their header markup, header-only CSS classes, and the now-unused `RouterLink`/`ThemeService`/`CedarLogoComponent`/`AccountMenuComponent`/icon imports that only the header used. `dotnet test` (347/347) and the frontend build/unit tests are unaffected (pure Angular/CSS change, no backend surface). Not yet visually verified in a running browser as of writing — screenshot review across both themes and ≤768px is the next step before calling this done.

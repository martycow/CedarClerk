# ADR-216 — The showcase becomes the game's own site (26.08.2026)

**Context.** ADR-134 shipped `/games/{slug}`: cover, description, store links, devlog feed, roadmap. A review on 26.08.2026 against the code found seven gaps between that page and the thing an indie developer would use *instead of* a site (T-294…T-300). None of them is a rendering detail: the page has no entrance, shows nothing to look at, measures nothing, and cannot be followed.

**Decision.**

1. **Entrances (T-294).** The blog index carries a `Games` strip above the post list — public, non-archived projects only, cover and name. A post that belongs to a project with a showcase carries a line back to it. Both use the showcase's own visibility rule; neither invents a query the index does not already run.

2. **Gallery and trailer (T-295).** `Project.ShowcaseGallery` holds `/media/…` paths, one per line, at most 12; `Project.ShowcaseTrailerUrl` holds a YouTube link, rendered through the same `youtube-nocookie` embed the blog renderer already emits. ADR-134's exclusion of `AssetEntry` stands and is the reason for the shape: gallery images are uploaded `Asset` media — bytes this server already serves under its own quota — not fingerprints of files on somebody's disk. Text columns rather than a table, for the same reason `ShowcaseLinks` is one: an ordered list of paths with no per-row attributes is a list, and a table of it would be a join to reconstruct the order.

3. **Metrics (T-296).** One table, `ShowcaseStatDaily(OwnerId, ProjectId, Day, Kind, Label, Count)`, upserted the way `RecordViewGeoAsync` already upserts. Two kinds: a page view, deduplicated by the same 30-minute cookie a post view uses, and a store-link click, counted by routing the link through `/games/{slug}/go/{index}` and answering 302. A click is counted server-side because a page with no JavaScript cannot report one, and the redirect keeps the destination in the markup where a reader can see it before clicking.

4. **Following (T-297).** `ShowcaseFollower` with double opt-in: an address is stored unconfirmed, a mail carries the confirm link, and only a confirmed row is ever written to. Every mail carries an unsubscribe link, and the token is per-row, so unsubscribing needs no account. Publishing a devlog into a project mails its confirmed followers — a subscription that never delivers is a form, not a subscription — and a failed send only logs, exactly like the form-response mail in `PostRegistrationAsync`.

5. **Per-project feed (T-298).** `/games/{slug}/rss.xml`, the same items `RenderShowcaseAsync` lists, announced from the page with `<link rel="alternate">`. The blog-wide feed keeps its rule (public posts only, no listed-private ones), because a feed reader never meets the gate.

6. **Public builds (T-299).** `Build.IsPublic` and `Build.DownloadUrl` — a link the author hosts, not bytes we take. Storage is already the registration blocker (T-172); a download page that quietly turned a 2 GB build into our disk problem would make that worse to solve a different problem. When the flag is on and a URL is set, the showcase renders a Downloads section; version, date and notes are already the author's public words about that build.

7. **Custom domain (T-300).** `Project.CustomDomain` — a host that is not the tenant domain resolves to a project, and that project's showcase is served at the root of it. The DNS and certificate side is Cloudflare's and is done by hand; the code's job is to answer for a host it has been told about. A domain is claimed only once it resolves to us, so an unreachable domain costs nothing and blocks nobody.

**Consequence.** The showcase gains three tables' worth of behaviour without gaining a second identity model: followers are addresses with tokens, not accounts, and the reader-account question (T-004) stays open and unprejudiced. Metrics are daily counters, not events — "how many people clicked Wishlist on Tuesday" is answerable, "who" deliberately is not. The custom domain is the one part whose completion is not in the repository: the code answers, the DNS record is a manual step.

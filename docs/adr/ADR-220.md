# ADR-220 — An export card selects with its body and includes with its checkbox (29.08.2026)

**Context.** ADR-198 made the export modal a destination rack: cards for every network, one active work area. Each card was a `<label>` wrapping its checkbox, so a click anywhere on the card both set the active destination *and* — by label semantics — flipped whether the network gets published. Opening a network to manage its settings silently changed what the next send would do, which is the worst kind of surprise a publish surface can hold.

**Decision.** Two independent affordances on every card, and neither ever does the other's job:

1. **The card body** is a `div[role="button"]` (click / Enter / Space): it sets `activeExportDestination` — what step 3 manages — and nothing else. Selection is announced via `aria-pressed` and drawn as the `--abord` border + `--asoft` wash.
2. **The checkbox** is a real `input[type=checkbox]`, visually integrated, with its own accessible name: it toggles inclusion in the send and nothing else. Its clicks and key events stop propagation, so ticking never moves the active selection; the checked state is what announces inclusion.
3. The two visual states are independent and combinable — a card can be selected-for-management without being included, and included without being selected.
4. Unsupported and not-connected cards stay select-only (there is nothing to include); the not-connected card's settings link neither selects nor toggles.

**Consequence.** Clicking a card body never changes what gets published; ticking a box never changes what the panel shows. Both affordances are in the tab order with a visible focus ring. The cost is that a card is no longer one big label — the checkbox needs its own `aria-label`, carried per network through `includeDestination`.

# ADR-317 — The Posts Manager becomes the Publishing Manager

**Status**: DRAFT
**Session**: BR-002
**Supersedes**: the three-column layout and name in ADR-046

## Context

The owner supplied `Docs_CedarClerk/UI_Prototypes/Publishing_Manager.png`. Most of its cards already exist in the Posts Manager's studio overview: publishing journey, Performance, Recent activity, post details. The layout (three columns), the name and the list filter (a select in a popover) differ. Recent activity dates Telegram sends from `Draft.UpdatedAt`, which is wrong.

## Decision

1. Name: "Publishing Manager" in every UI language; route stays `/posts`.
2. Two panes: the post list (search, All / Published / Scheduled / Drafts chips, sort) and the selected post.
3. The selected post has tabs Overview · Publishing · Engagement · Details. Overview holds Publishing destinations, Performance, Recent activity, Post details and a "next step" hint naming the first unreached destination.
4. Telegram times and links come from `ChannelPost` (every send), not from `Draft.LastTelegram*` and `UpdatedAt`.
5. The page header carries "+ New post".

## Consequences

- No new entity; data comes from `Draft`, `ChannelPost`, `PublishJob`, `ScheduledPost`, `DraftStatSnapshot` (ADR-110).
- X/Bluesky per-post engagement remains unavailable; the Engagement tab says so.
- The shell inspector no longer duplicates the selected post (T-390).

# ADR-033 — YouTube embed block: new `youtube` node, thumbnail+link on Telegram (no native Blocks link-preview exists)
**Context**: Marty asked for a Media-toolbar button (next to Insert Link) that takes a pasted YouTube URL and inserts a clickable video preview, working both on the blog and in the Telegram post — modeled on how pasting a link directly in the Telegram client auto-generates a webpage preview. Checked before building: `Telegram.Bot` 22.10.2's `LinkPreviewOptions` only exists on the classic `SendMessage`/`EditMessageText` request types — `InputRichMessage.Blocks` (the only send path since ADR-018) has no equivalent block type, so there is no way to reproduce a native Telegram auto-preview through `sendRichMessage`. A real embedded player is also not an option — Telegram has no "iframe"-equivalent block.
**Decision** (23.07.2026): New TipTap node `youtube` (`cedarclerk-web/src/app/tiptap-extensions/youtube-node.ts`), attrs `{ videoId, caption }` — stores the extracted 11-char video ID, not the raw pasted URL, via a `extractYouTubeId()` helper covering `watch?v=`, `youtu.be/`, `shorts/`, `embed/`, and `live/` URL shapes (with or without extra query params). Toolbar button lives in the Media group (custom inline SVG icon — Lucide dropped brand/logo icons, confirmed by grepping the installed `@lucide/angular` bundle for "youtube" with zero hits), opens the same URL-input-plus-Apply popover pattern as Insert Link. Per Marty's choice, the editor node view shows a static thumbnail (`img.youtube.com/vi/{id}/hqdefault.jpg`) with a Play-button overlay and a caption input — no live iframe while editing; the real preview only exists on the published outputs. Renderers:
- **Blog** (`CedarToBlogHtmlRenderer`): a real `<iframe src="youtube-nocookie.com/embed/{id}">`, responsive-wrapped — this is the one output that actually supports embedding.
- **Telegram Blocks** (`CedarToTelegramBlocksRenderer`, the only renderer that sends): reuses the existing `RichPhotoBlock` with the same thumbnail URL as the editor, captioned with a `RichRunLink` (existing run type, already used for the `link` mark) pointing at the original `youtube.com/watch?v=` URL — thumbnail-plus-clickable-link is the closest equivalent to a native preview that Blocks supports, not a true auto-fetched webpage preview.
- **Legacy `CedarToTelegramHtmlRenderer`/`CedarToTelegramMarkdownRenderer`** (kept but unused for sending per ADR-018): given a matching case for parity/tests only, same thumbnail-plus-link shape.
**Consequence**: The clickable preview on Telegram is Cedar Clerk's own construction (thumbnail image + link caption), not Telegram's native link-preview card — visually different (no title/description text Telegram would normally scrape), and not yet verified live against `@testingandfun` as of writing this entry. If a future Bot API version adds a genuine link-preview block to `InputRichBlock*`, this should be revisited.

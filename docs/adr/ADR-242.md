# ADR-242 — Publish / Export is the document's third state, not a door to a window (02.09.2026)

**Context.** ADR-239 clause 9 made the editor one document with three tabs and deferred the third:
"Publish this sprint opens the existing Export modal from the tab and from the top-bar button; the
modal's steps become the tab's body later." The consequence it recorded — "for one sprint the editor
has a tab that does not stay selected" — is the defect this entry closes. The maintainer chose the
three-screen direction (`Write → Preview → Publish / Export` inside `app-document-frame`) on
02.09.2026 from a set of visualisations; the mockups are the layout, hierarchy and rhythm, and
nothing else about them is authoritative.

What the modal held is not small: ADR-096's three questions (version, where, parameters), ADR-099's
"When", ADR-100's per-network languages, ADR-131's link-only Discord, ADR-190's shelves, ADR-220's
select-with-the-body-include-with-the-checkbox cards, ADR-223's copy targets, ADR-241's matrix, the
pre-publish checks, CTA buttons, silent/pin, the best-time hint, tracked links and the file panel.
Each of those is a behaviour with its own entry, and the port keeps every one of them.

**Decision.**

1. **`?tab=publish` is a real selected state.** `tab()` resolves `publish` beside `preview`, the
   bare editor URL stays Write, and `setTab('publish')` navigates with `queryParamsHandling:
   'merge'` exactly as Preview does. The tab is named *Publish / Export*, because a third of what it
   holds — `.cedar`, `.zip`, the copy targets — exports without publishing. Supersedes ADR-239
   clause 9's sentence "Publish this sprint opens the existing Export modal", its clause 13's `T-365`
   deferral, and the inventory's "Publish never becomes the selected tab".

2. **The Export modal is gone; its body is the tab's.** The `app-modal` wrapper, `exportModalOpen`
   and the top-bar Publish split button (ADR-239 clause 9's "the Publish split button") are removed.
   Entering the tab runs what opening the modal ran — presets, the capability issues, the short-post
   targets, the preflight, the best-time hint, the CTA buttons, the file list — through one
   `effect` on `tab()` and `currentId()`, so a deep link and a click arrive at the same state. The
   signals, the validation (`canPublishAll()`), `publishAll()`, `publishAllConfirmed()`, the queue
   polling and every endpoint are the ones the modal used, unchanged; there is no second publishing
   model. ADR-096's one Publish button stands, on the frame's footer now.

3. **Write stays mounted.** The three bodies are three `[body]` slots of the frame, hidden by
   `.is-hidden`, never conditionally destroyed: TipTap owns the sheet's DOM node, and unmounting it
   would orphan the editor with its plugins, its selection and its pending autosave. Preview and
   Publish are `@if`-mounted on their own tabs because neither owns a DOM node the page cannot
   recreate.

4. **One primary action per state.** Write → *Continue to Preview*; Preview → *Continue to Publish*;
   Publish → *Publish to N destinations* (or *Update* / *Schedule and publish* when that is what the
   press does, as ADR-096 and FI2.6 already required). A Back button precedes it on Preview and
   Publish. Share preview stays on the footer's start on Write and Preview; History and the Posts
   Manager stay behind the title's ⋯; Details stays the title's toggle. Nothing gets a second home.

5. **Publish / Export is three columns at 1180px and above.** A destination rack (publish targets;
   *Copy for stores* — Steam, itch.io, no checkbox, never a `PublishJob`, ADR-223; *Coming later* —
   Instagram, Threads, YouTube, unselectable), the settings of the active destination in the middle
   with the Version row above them and When / Private access below, and a readiness review on the
   right. A stepper — Version · Destinations · Settings · Review — heads the workspace and moves
   focus to the region it names; its done/current marks are derived from the ticks and
   `canPublishAll()`, never drawn. The compatibility matrix folds behind *Compatibility · N warnings*
   (N = limited-or-dropped cells for the kinds the document holds on the ticked destinations), the
   full table one disclosure away. `.cedar`, `.zip`, tracked links and the file list become a
   compact utility strip under the columns.

6. **A destination card is two controls, not one.** ADR-220's two affordances stay, but the
   checkbox no longer sits inside a `role="button"`: the card is a plain row holding a labelled
   checkbox (*Include Blog*) and a button (*Blog settings*, `aria-pressed`), each its own tab stop.
   Selecting never toggles inclusion; the active destination defaults to the first ticked one that
   is ready.

7. **One state vocabulary across Preview and Publish** — Ready, Warning, Blocking, Needs setup,
   Unavailable — each an icon with a word, never a colour alone, and the checks in both tabs are
   grouped under those headings. Blocking is what the existing contract already refuses: working
   material (the server's 400, ADR-102), a Telegram version without a channel (ADR-098), a
   short-post over its limit, X credits short (ADR-092). Warnings stay warnings — `canPublishAll()`
   reads none of them. A *Fix* action appears only where a real route or action exists: the type
   row of the inspector, Settings → Integrations, the destination's own settings.

8. **Progress stays a modal.** The publication checklist (`publishRun`) opens over the workspace as
   it opened over the modal: a publish is a run with a beginning and an end, its rows are the only
   truth about what went out, and a panel that could scroll away or be navigated from would lose the
   error that is pinned to the failed step. Closing it cancels nothing — the queue owns the jobs
   (T-090) — exactly as before.

9. **Narrower widths collapse the columns, not the content.** Between 760px and 1179px the rack
   becomes a horizontal strip, the settings stay the main region and the review moves below. Under
   760px it is one column in reading order — destinations, settings, review — the page never
   scrolls sideways and the sticky footer covers nothing. These are page rules in the editor's own
   stylesheet, the same allowance ADR-147 clause 2 makes for page bodies; the shell still carries no
   width rule.

**Rejected.** *A Publish route of its own* (`/editor/publish`) — the document is one thing with
three faces, and a route would lose the mounted sheet. *Extracting the publish state into a service
or a child component that owns it* — the state has one owner today and every handler reads the
draft the editor holds; a mirror would be the second publishing model this entry refuses. *A Save
draft button* — autosave owns saving, and the footer already says so. *A readiness endpoint* —
ADR-239 refused it once; every fact the review needs is already on the client.

**Consequence.** `e2e/14-thread` and `99-audit` open the tab instead of a button named Publish;
the smoke suite's `.dest-card` locators keep working because the class survives. The inventory's
Export-modal rows become Publish-tab rows. What this leaves open: the utility strip's file list is
the same list the modal had, not a redesign; and `T-236`/`T-237` still own the shell's narrow
screens — this entry adds page rules to the editor alone.

# ADR-124 — OG/Twitter meta on the blog: privacy policy and absolute URLs (18.08.2026)

**Context.** Blog post pages emit not a single meta tag — a link to a post unfurls as a bare string in Telegram/X/Discord, which hurts acquisition channel #1 (`docs/product/BUSINESS.md` §6, gate #11). At the same time the blog carries private and semi-public posts protected by a gate, a watermark and copy-protection — meta tags collected without a policy would become a leak channel for that very content (T-174; the session brief from INPUT_PROMPT demanded the policy be a decision, not code).

**Decision 1 — the policy is a function of two post flags, and nothing else.** `f(IsPrivate, IsListedWhilePrivate)`: a private, unlisted post **emits no meta at all** (no title, no description, no image — zero `og:` tags on the page, on the gate, and on the 404); a semi-public post (`IsPrivate && IsListedWhilePrivate`) — **only `og:title` + a static placeholder image**, no description and no cover pulled from the content; a public post — the full set (og/twitter/canonical/hreflang/article-times). **Reader authorization does not extend the policy**: a crawler with a valid invite cookie is still a crawler, and the preview must not depend on whose eyes the bot happened to view the page through.

**Decision 2 — canonical across language versions: every version is self-canonical.** The main language is `/{slug}`, a translation is `/{slug}?lang={l}`; an hreflang cluster links them all, `x-default` is the main language. Collapsing translations into a single canonical would mean hiding them from indexing, and translations here are first-class content (ADR-064/065).

**Decision 3 — absolute URLs are built only as `https://` + host from config** (`Cedar:BlogHost` with a fallback to `Consts.URLs.BlogHost`), never from the request: TLS terminates at Cloudflare, Kestrel listens on loopback over HTTP, the project has no `UseForwardedHeaders` — `Request.Scheme` in production honestly answers `http`, and "correctly" deriving the scheme from headers would add middleware for something the config already knows. The two previously existing const-only spots (`siteUrl` in the RSS and the renderer's media-path base) are brought under the same config pattern.

**Decision 4 — field sources.** `og:description` — from `CedarPlainText.Paragraphs` (prose paragraphs, the same source used for X/Bluesky teasers), truncated to ≤200 characters at a word boundary; not `TipTapTextNodes.ExtractTexts` — that one sweeps up table cells and captions too. `og:image` — the document's first image (`CedarImageRefs.Collect`) → the owner's avatar → the static placeholder `/og-default.png` (1200×630); for a semi-public post it is always the placeholder only. `article:published_time` — `BlogPublishedAt` (first-publish semantics, not rewritten on republish), `article:modified_time` — `UpdatedAt`.

**Consequence.** Meta assembly lives as a pure builder in Core (`OgMetaBuilder`: strings in, escaped HTML out, the policy is an enum) and is covered by unit tests on escaping/policy/truncation; pages where meta must not appear are not "filtered" — they simply get nothing, an empty `PageShell` parameter by construction. Telegram's preview cache lives a long time — re-checking the same link goes through `@WebpageBot` or `?v=2`.

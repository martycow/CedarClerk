# ADR-283 — Document tree drag&drop: a flat drop list, depth from sideways travel (05.09.2026)

**Context.** ADR-128 shipped the document tree with a "Move under…" picker and up/down buttons and
deferred dragging (T-201), because Angular CDK has no tree drop list: `cdkDropList` sorts one flat
axis and knows nothing about nesting. A hand-rolled tree drop would have to answer two questions
the flat list does not ask — *which parent* and *at what position* — from a pointer that only
reports where it is.

**Decision.**

1. **One flat `cdkDropList` over the visible rows**, `lockAxis="y"`, each `.tree-row` a `cdkDrag`
   started from a grip (`cdkDragHandle`), never from the row itself: the row still opens the
   document on click, and touch waits 200 ms before a drag so a finger can scroll the list.
2. **Depth is the pointer's sideways travel in indent widths**: `wanted = startDepth +
   round(distance.x / indent)`, where `indent` is the `--tree-indent` token read off the list at
   drag start (the same token the rows' padding uses, so the math and the drawing cannot disagree).
3. **The neighbours clamp the depth** (`treeDropTarget`, a pure function): no deeper than one level
   under the row above the placeholder, no shallower than the row below it, and never past the
   server's ceiling. The parent is the nearest row above at `depth − 1`; the sibling to go before
   is the first row at `depth` before the subtree ends. Rows and index in, parent and `beforeId`
   out — the drop calls the same `PUT /api/drafts/{id}/parent` the menu calls, through the same
   `applyMove`, so the server's cycle guard and depth limit stay the only rules.
4. **The placeholder is drawn at the computed depth** (`*cdkDragPlaceholder`, a row-tall dashed
   slot indented to `dropDepth()`), so the drop is visible before it happens.
5. **A dragged parent folds its subtree for the duration.** The children move by data — their
   `ParentDraftId` does not change — so leaving their rows in the flat list would let the sort
   strategy shuffle them separately from the row being moved. They come back once the drop has
   been applied (or the drag is released outside the list).
6. **Keyboard stays the menu.** The grip is `aria-hidden`; the up/down buttons and the parent
   picker remain the accessible path, unchanged. Motion goes through `--motion-*`, which the global
   reduced-motion clamp already shortens to 1 ms.

**Consequence.** No new endpoint, no server change, no second notion of "move". A drop that lands
where the row already sits sends nothing. The one number in TypeScript is a fallback for a DOM
that computes no styles (unit tests); everywhere else the indent is the token. Dropping onto a
collapsed parent appends to the end of its children, which is what the placeholder shows.

# ADR-219 — A picture on a shared board is readable by the board's people (27.08.2026)

**Context.** ADR-218 was written assuming `/media/*` needed no new rule for a shared board. It does. The door in front of the media directory answers three questions in order: is the file public (a published post claims it), is it gated by a private post the reader holds a cookie for, and failing both, is the reader its owner. A canvas image is none of those. It is an ordinary library upload — no post claims it — so `MediaVisibilityIndex` puts it in neither set, and the last question is exactly the wrong one on a surface whose entire point is that somebody else is looking. An owner-uploaded picture was a 404 for every collaborator, and the two-client run that would have caught it only ever added a note.

**Decision.**

1. **A fourth readable case, asked last.** After public, gated-with-grant and owner have all said no, `CanvasMediaIndex` asks which projects display this file on a board and lets `ProjectAccessResolver` decide for the signed-in caller. An anonymous reader never gains anything by reaching it: with no account there is no project to resolve.

2. **The lookup is by file name, cached, and off the hot path.** Payloads store the name as written, so `Payload.Contains("asset_<id>")` against the owner's own image items is the whole query, held for 30 seconds like the visibility index. It is deliberately *not* folded into `MediaVisibilityIndex.LoadAsync`: that runs for every blog page's images, and every reader of a blog would then pay for a feature most owners do not use.

3. **Not a signed grant.** `MediaGrant` lives fifteen minutes and a board stays open for hours, so stamping the URLs in `CanvasMapping.Describe` would blank the pictures out mid-session. Also rejected: copying the bytes per member, which makes "their images stay on the boards" (ADR-217) a lie about storage rather than a promise about access.

**Consequence.** A member who is removed loses the pictures with the board, on the same 30-second boundary the rest of the index moves on. The middleware now takes one dependency from the indie-dev module and is registered whether or not `Cedar:Modules:IndieDev` is on — one door for every host, and a flag that changed which questions it asks would be a different door rather than a hidden feature. With the module off there are no board rows, so the answer is always no.

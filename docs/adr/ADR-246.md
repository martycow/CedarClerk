# ADR-246 — One navigation and four workspace measures (02.09.2026)

**Context.** Eighteen screenshots of the current application at 3440×1392 exposed a second
failure after the Paper-first port. The frame is quieter, but the screens do not yet behave as one
product. The editor changes the sidebar automatically, fixed list and inspector widths leave wide
blank fields or force horizontal scrolling, several pages scroll both the shell and a nested card,
and equal-looking rows use different selection, metadata and overflow rules. Empty states often sit
beside a second creation action or preserve a large empty data surface. Discovery repeats two empty
feeds and seven zero-count categories, so the public page looks unfinished precisely when its honest
content pool is small.

These are system defects, not eighteen independent styling defects. Patching each screenshot with a
new width or local empty-state box would reproduce the drift that ADR-071 and ADR-239 were meant to
remove.

**Decision.**

1. **Sidebar state belongs to the person, not the route.** Expanded and collapsed are two views of
   the same navigation: the same ordered groups, active item, project context, account row and
   separated foot. A labelled control in the sidebar changes the mode and the preference is stored
   locally. Expanded is the default. Opening the editor no longer changes the mode. The collapsed
   view keeps group separators and a compact project switcher instead of removing project context.
   The editor's document top bar is part of `app-document-frame` and renders in both sidebar modes.
   This supersedes ADR-239 clause 5 and ADR-240's assumption that the rail exists only on the editor.

2. **A page declares one of four measures.** The shell remains ignorant of individual pages; the
   page root uses a shared layout attribute.

   - `focus` is a centred reading or editing column.
   - `form` is a 720–960px authoring column with actions near the fields.
   - `operational` is a left-anchored, fluid workspace for lists, boards and inspectors.
   - `editorial` is a 1200–1440px public composition with a deliberately shorter hero.

   The current blanket `.page { max-width: 1920px; margin-inline: auto; }` is retired. A page may not
   invent a fifth width contract in component CSS. This narrows ADR-239 clause 7: content fills the
   available height, while its readable width follows the job being done.

3. **Split workspaces are fluid.** List panes, canvases and inspectors use shared minimum and maximum
   tokens with `minmax()`/`clamp()`; a fixed 280, 300, 320 or 340px dock is not a layout contract.
   The centre always receives `minmax(0, 1fr)`. Long paths, titles and URLs either wrap at safe
   boundaries or truncate with their full value available through `title`; they never widen a pane.
   Horizontal scrolling is reserved for an explicitly tabular surface whose columns cannot reflow.

4. **One vertical scroll owner exists on each visual axis.** A normal page scrolls in the shell.
   A full-height operational workspace may give each sibling pane one scroll region, but a pane may
   not contain another scroll region on the same axis. A modal has one scrolling body and fixed
   heading/actions. Clipping a first control under a sticky header is a failed layout, not an
   acceptable compact state.

5. **Entity lists share one anatomy.** A row is thumbnail or icon, title with one metadata line,
   status, then trailing action. Column labels appear when the list reads as a table. The selected
   row uses the accent wash, a leading accent rule and `aria-selected` or `aria-current`; colour is
   never the only signal. Icon-only destructive actions keep a visible 38px paper target and an
   accessible name.

6. **An empty state replaces the data surface it explains.** It names what is absent, why the page
   matters and one next action. The same action is not repeated in the header while that empty state
   is visible, and a creation form does not coexist with a second zero-state invitation. Calendars
   may keep their meaningful grid, but the explanation and Schedule action belong inside that grid.
   This supersedes the weaker placement-only rule in ADR-239 clause 8.

7. **Only one transient layer is active.** Opening Feedback, Appearance, Search, a modal or a
   destructive confirmation closes the account menu and any peer popover first. Background controls
   become inert while a modal is open, focus enters the layer, Escape closes only the top layer, and
   focus returns to its trigger.

8. **Controls state their selection and their label.** Segmented controls, type cards, language
   picks and destination choices use `aria-pressed`, `aria-selected` or a native checked state plus
   a non-colour visual marker. Text fields have visible labels; placeholder text is example or hint
   text only. The deliberate free-text `GameTask.Assignee` decision remains unchanged.

9. **Discovery is composed for a small honest pool.** The public page keeps all privacy and opt-in
   gates from ADR-243. It renders only category links whose count is non-zero, omits an empty feed
   section instead of repeating “no matches,” and uses one editorial invitation when the entire pool
   is empty. That invitation explains how an author becomes eligible and links to the existing
   publishing entry point; it never fabricates Projects, Blogs or testimonials. Search, lenses and
   Shuffle form one control band, section numbering is generated from the sections that actually
   render, and the stage is shorter so real content or the invitation appears in the first viewport.

10. **The eighteen-screen pass is one acceptance set.** Projects, Editor and history, Posts Manager
    and Forms, all three Preset kinds, Teams, Calendar, Planner, the task card, Dialogues, Project
    Assets, Settings, Feedback, Discovery and the public Showcase must each be checked at the source
    screenshot size. The shared shell is also checked in both sidebar modes. Automated acceptance is
    `cedar test`, an Angular production build, icon/contrast/density gates and the existing smoke
    suite; visual acceptance requires fresh rendered evidence, not the original screenshots alone.

**Rejected.** *A CSS patch per screenshot* — it preserves the competing contracts. *A single narrow
max-width for every page* — operational surfaces and reading surfaces have opposite needs. *Keep the
editor-only rail and merely restyle it* — route-driven navigation is the inconsistency. *Populate
Discovery with demo Projects that look like user work* — it violates the page's public-trust model.
*Turn Assignee into a member picker during the task-card cleanup* — collaboration deliberately does
not reach the tracker.

**Consequence.** `styles.scss` gains layout and pane tokens plus the shared row/selection contract;
the shell gains one persisted sidebar preference and the document frame loses its dependency on the
sidebar mode. Page styles choose a declared measure and replace fixed docks, nested scroll and local
selection treatments. Existing components and i18n groups are reused; new visible strings are added
to both dictionaries and `docs/design/UI-INVENTORY.md` changes with their screens. Discovery changes
only its server-rendered composition and CSS; its query, privacy gates and data model remain intact.

# ADR-238 — Inspectors that can be written to, and the facts they were missing (01.09.2026)

**Context.** Sprint S-15 gathers six rows that are all one complaint in different places: a shelf
that describes an object it cannot change, or names a property nobody stored. T-239 (an inspector
row drawn as a typeable field that is a `<span>`), T-240 (resolution, byte size and originating
asset, none of them on a TipTap node), T-256 (`/drafts` has no selected-object shelf at all),
T-257 (the admin per-user form still inline), T-260 (a glossary count that exists only for the
duration of a blog render), T-270 (`documentType` missing from the draft DTO).

Reading the code first changed the sprint. **T-270 is already done** — `DraftEndpoints` carries
`DocumentType` on both the listing and the single-draft projection, and the editor's Type row is
a live `<select>` bound to `assignDocumentType`. **T-239 is half done** — alt text is already an
`<input>` writing through `setSelectedAttr`, exactly as the row asked. What survives of T-239 is
the other half of its own sentence: three rows still carry `field` while rendering plain ink. The
backlog was describing a state the code left behind, which is the ordinary direction of that drift
and is why the rows were re-read against the code rather than implemented from their text.

**Decision.**

1. **`field` means "this row hosts a control", and rows that host none lose it.** The marker was
   being used as decoration, so the sunken paper box became a promise the sheet does not keep — the
   defect the row named. The styling moves off `.text` onto the value container, so a projected
   `<input>`/`<select>` *becomes* the field instead of sitting next to one. That inverts today's
   behaviour, where `field` is inert on exactly the rows that are editable and visible on the rows
   that are not.

   **The rule, amended after implementation:** `field` belongs on a row **whose value container is
   itself the control** — one bare input or select that takes its face from the row. It never goes
   on a row that renders plain ink, and never on a row hosting a control that **paints its own
   face**: a bordered component, a picker trigger, or anything that stacks more than one line. The
   test a future row is held to is one question — *strip the row's box; does anything still draw an
   edge?* If yes, the row must not carry `field`, or the sheet ends up with a field inside a field,
   which is the same lie in a costlier form.

   This clause first shipped naming two rows, and the editor lane found a third: the document
   **Location** row, whose `app-location-input` draws its own bordered input with a profile chip
   stacked under it. **The exemption stands** — the lane applied the principle rather than the list,
   and the principle gives the right answer, since clause 1's own instruction to move the box onto
   the value container is precisely what would have wrapped a two-line composite in a one-line
   field. Keeping the letter would have meant reaching into `shared/location-input.component.ts`, a
   file no lane owns this sprint, for a cosmetic gain. The list was the fault, not the lane: like
   clause 8, **the rule is the invariant and the rows are its census.** Current census — `field`
   stays on **alt** (an input), **Type** (a select) and **slug** (an input, clause 2); it drops from
   the media **source** (the file itself, not typeable), the **link href** (the link mark's own
   editor owns it, and a second weaker one is not worth building) and **Location** (above). The
   folder, series and tag pickers never carried it and are the same category as Location, so the
   rule describes existing practice rather than inventing one.

2. **The slug row becomes a real edit rather than losing its box.** `docs/design/UI-INVENTORY.md`
   already promises this on the `Slug row` line, and `POST /api/drafts/{id}/slug` plus
   `DraftsService.setBlogSlug` have both existed since FI3.4 — the port simply stopped calling
   them. Making it editable costs a handler and an error line; deleting the promise would have cost
   the same edit and left the endpoint unreachable from the product. The server keeps every rule it
   already has (slugify the typed text, refuse an empty result, refuse a taken slug, refuse before
   the post has a slug at all), so the row surfaces those refusals and invents none.

3. **A media node links to its `Asset` by id, and the three facts come from the server.** The
   alternative was to denormalise `width`/`height`/`bytes` onto the node at insert time. It was not
   taken: those are properties of a **file**, not of a document, and a copy in the document goes
   stale the moment `ImageCompressor` writes a derivative or the asset is replaced — a document that
   quietly asserts a wrong resolution is worse than one that says nothing. The link is also the
   thing a usage table needs (T-200); the numbers are not.

4. **The lookup resolves by id *or* by media path, so documents written before today answer too.**
   An id-only endpoint would light the panel up for images inserted after this ships and leave every
   existing document blank forever — the feature would be true and useless. `Asset.LocalPath` is
   what `src` already contains, so the fallback is one predicate. The node attribute still earns its
   place: it survives the file being re-pathed, and it is the half T-200 reads.

5. **Dimensions are identified from the file on request, not stored on `Asset`.** `Image.Identify`
   reads a header, not an image, and ImageSharp is already a dependency. Columns would have meant a
   migration plus a backfill pass over ~937 MB of existing media to fill them in, and would still
   have to be re-read whenever the bytes change. Nothing is cached because nothing needs to be: the
   call happens when a writer selects one picture.

6. **`/drafts` gets a selection that is a second gesture, never the row's own click.** A row is a
   door to the editor (ADR-163) and that stays the row's single meaning; a click that sometimes
   opened and sometimes selected would break the one interaction the board is for. Selection is an
   explicit control in the row's existing action cluster, which already stops propagation for four
   other buttons and is already in the tab order — so keyboard selection needs nothing extra.
   Hover-to-describe was rejected: it is invisible to a keyboard, absent on touch, and the shelf
   would change contents while the pointer travels toward it.

7. **The shelf is exclusive — the selected draft, or the folder filter, never both.** This is the
   Posts Manager's rule (ADR-167) restated rather than a second pattern, and the folder filter is
   what the third column falls back to, so the column is never empty. Tree view keeps `no-shelf`:
   it shows structure, and both the status filter and the folder filter already stand aside there.

8. **Glossary hits are recorded, and they are recorded where the text changes and where the term
   changes.** A count that exists only inside a blog render is a count that costs a page view to
   read, and recording during the render would write on every anonymous reader's GET. One trigger
   was not enough either: a usage row is a fact about a **pair**, and both halves move
   independently — a document is edited, and a term's aliases are edited. So a draft save rescans
   that draft against every term, and a term write rescans that term against every draft. The
   lazy-batch shape used for `CoverImageScanned` (T-337) was the alternative and was refused here:
   a cover thumbnail may lag a listing, but a number labelled "used in N" that is quietly a
   different N is a lie rather than a delay.

   **Amended after implementation.** The clause first shipped as a list of call sites, and the C#
   lane found two it did not name: `POST /api/drafts/{id}/primary-language`, which swaps the body
   and a translation wholesale, and `DELETE /api/drafts/{id}/translations/{lang}`, which removes
   text outright. **Both join the trigger set** — the lane's own argument settles it, since each
   leaves rows describing text that has moved or is gone, and that is a wrong N, which is exactly
   what this clause refused to accept. The lane was right to stop rather than invent a seventh
   trigger; the fault was writing the rule as a census. **The rule is the invariant, not the
   list: any endpoint that changes a draft's stored text calls `SyncForDraftAsync` before it
   returns.** The enumeration below is that invariant's current census and is expected to grow with
   the endpoints — a new writer of `CedarJson` that skips the call is a bug against this clause, not
   a contract amendment.

9. **The count is "documents this term appears in", not "times the blog marked it".** Those two
   numbers legitimately differ — `GlossaryScanner.Mark` runs on already-escaped HTML and skips
   entities, suppresses itself inside code blocks, and `DraftGlossaryExclusion` (ADR-197) can
   deliberately omit a term from one document-language pair. The scan therefore runs on plain text
   via `CedarPlainText`, shares the matcher and nothing else, and **ignores exclusions**: an
   exclusion is a publishing decision, and the writer asking "where is this term used" wants the
   text, not the render.

10. **The field is `usedInDrafts`, not `usedInPosts`.** Since ADR-102 a post is one `DocumentType`
    among six; a term that appears in a changelog and two design documents is used three times, and
    a field named for posts would have to either lie or exclude them. `TERMINOLOGY.md` makes `Draft`
    the entity word. The UI label is free to read naturally in each language — the wire name is not.

11. **The admin per-user form becomes a modal opened by clicking a row.** This is a step back
    toward a shape the UI V2 port deliberately retired: ADR-164 and ADR-167 replaced the asset
    modal and the glossary preview modal with inspector shelves, and ADR-164 clause 5 kept this
    form inline precisely to avoid squeezing it into 340px. That tension is real and is not being
    papered over — two selects, a date, three inputs and six buttons do not fit a shelf, and the
    inline row that holds them today expands to a height that pushes the rest of the user list off
    screen. The maintainer chose the modal over both the shelf and the status quo. It is the
    existing `app-modal`, the same overlay every other dialog in the app uses, so the retreat costs
    one shell and not a second modal system.

12. **The delete confirmation closes the user modal instead of stacking on it.** Two `app-modal`
    instances would put two backdrops and two Escape handlers on one screen, and `ModalComponent`'s
    `document:keydown.escape` fires on every mounted instance — Escape would shut both. The delete
    dialog already exists and already names the account it is about, so nothing is lost by the user
    modal standing down while it is answered.

13. **Two terms spelled the same: the blog's winner wins the count, and the loser says so instead
    of reporting zero.** Added after implementation — `CountHits` is a single non-overlapping pass,
    so only one term can be credited at a position, and the C# lane's ordering (project-scoped ahead
    of global, per ADR-112) is **correct and stays**: the count has to agree with what a reader
    actually sees marked, and any other winner would make the number describe a render that never
    happens. What is not acceptable is the consequence the lane flagged. A bare `0` on the shadowed
    term is indistinguishable from "this term appears nowhere in your documents", and those two
    readings call for opposite actions — one says delete the term or add aliases, the other says
    nothing is wrong. The inspector would state the wrong one as fact, which is the same defect
    clause 1 fixed on the row that looked typeable and was not.

    So the collision travels to the client as a fact of its own. It is **read off the glossary
    table, not off a second scan**: two terms of one owner and language whose spellings intersect
    is a property of the glossary, knowable without opening a single document, and the read path
    already has every term in memory. The count itself stays exactly as scanned — a shadowed global
    term is still genuinely used in documents of every *other* project, so its number is real and
    must not be blanked; the note explains a zero when there is one and stands beside a non-zero
    count when there is not.

    Ordering needs one more thing to be stable: after project-scoped-beats-global, ties break on
    `CreatedAt` then `Id`, so the winner is the same across runs and the field below can name the
    same term the scan credited.

    The UI decides severity for itself from data it already holds. Cross-scope shadowing is a
    deliberate override — "the ferry" inside one game against a general term — and reads as plain
    information. Two terms **in the same scope** sharing a spelling is a genuine mistake in the
    glossary, and there the row takes `app-spec-row`'s existing `warn`. Both cases come off
    comparing the two terms' `projectId`, so this costs one field and no second concept.

    **`CanMeet`, added by the C# lane and confirmed here.** Two terms scoped to **different**
    projects can never appear in one document, so neither can take the other's position: a pair
    collides only when **at least one is global, or both are in the same project**. This follows
    from the clause's own "would win at the same position" and should have been written into it —
    without the guard the field would report a collision between terms that never meet, and the
    severity rule would then describe a deliberate override between two people's unrelated games,
    which is a sentence about a relationship that does not exist. The UI branch is unaffected and
    stays as written: "different scope" can now only ever mean project-against-global, never
    project-A-against-project-B, because that pair no longer arrives.

    **The case-sensitivity comparison was wrong as I first wrote it, and is corrected here rather
    than accepted.** "Compared under the stricter of the two `IsCaseSensitive` flags" makes a
    case-insensitive `"Unity"` and a case-sensitive `"unity"` read as not colliding — but both
    match the text `unity`, so they genuinely compete there, and the loser then shows the bare `0`
    this whole clause exists to prevent. That is a miss, not caution: the field would stay silent in
    exactly the case it was added for. The right test is whether **any text exists that both terms
    would match**, which mechanically means **compare case-insensitively unless *both* terms are
    case-sensitive**. It is not over-reporting — it is the same question asked correctly, and it
    still answers *no collision* for the pair the flag exists for, `"IT"` the industry against
    `"it"` the pronoun when both are case-sensitive, since no string matches both. The lane was
    right to implement the clause as written and say so rather than quietly improve it.

    One property worth stating for whoever reads this later: the field is computed over the term
    list **the endpoint returns**, so `GET /api/glossary?scope=global` cannot report a project term
    shadowing a global one — it never sees the project term. That is not a bug and needs no guard;
    the glossary screen, which is where the row is drawn, loads unfiltered.

## The zone split

Each file has exactly one owner. Where a design would have crossed a line, the shared thing sits
wholly in one zone and the other lane reads it through the contract below.

| Zone | Owns |
|---|---|
| **tech-general** | `CedarClerk.Core/**`, `CedarClerk.Server/**`, `CedarClerk.Localization/**`, `CedarClerk.Tests/**` |
| **tech-ui** | `cedarclerk-web/**`, `docs/design/UI-INVENTORY.md` |
| **tech-lead** | `docs/adr/ADR-238.md` |
| **project-manager** | `docs/tasks/**`, `docs/DECISIONS.md`, `docs/knowledge_base/TERMINOLOGY.md` |

Per row: **T-239, T-256, T-257** are wholly tech-ui (every endpoint they call already exists).
**T-240** is split — the endpoint is tech-general, the node and the shelf are tech-ui.
**T-260** is split — storage, scan and read path are tech-general, one row and one label are
tech-ui. **T-270** is closed already and belongs to neither.

## Contract

JSON is camelCase throughout (the app's serializer default; `documentType`, `coverImagePath` and
every existing field already arrive that way). Absent means **absent** — a fact that is not known
is omitted, never sent as `0` or `""`, because an empty inspector row asserts that the property
exists and is unfilled.

### T-240 — asset lookup (tech-general)

`GET /api/assets/meta` in `CedarClerk.Server/AssetEndpoints.cs`, authorized, owner-scoped.

| Query | Type | Notes |
|---|---|---|
| `id` | `Guid?` | The asset's id, as returned by `POST /api/assets` |
| `path` | `string?` | `Asset.LocalPath` — i.e. an `src` of `/media/{path}` with the prefix stripped |

`id` wins when both are given. Neither given → `400`. Neither resolves for this owner → `404`.

| C# property | JSON | TS type | Meaning |
|---|---|---|---|
| `Id` | `id` | `string` | Asset id |
| `FileName` | `fileName` | `string` | Original upload name |
| `ContentType` | `contentType` | `string` | |
| `SizeBytes` | `sizeBytes` | `number` | `Asset.SizeBytes` |
| `Width` | `width` | `number \| null` | From `Image.Identify`; null for audio, video and anything unreadable |
| `Height` | `height` | `number \| null` | Same |
| `ProjectId` | `projectId` | `string \| null` | ADR-204 — null is the "no project" bucket, not a gap |

Never throws on a bad or missing file: identification failure yields nulls for `width`/`height`
and the row is omitted client-side.

### T-240 — node shape (tech-ui)

`image`, `video` and `audio` nodes gain **one** attribute. Carousel and collage hold arrays of
URLs and are out of scope, stated so nobody widens it silently.

| Attribute | Default | DOM | Behaviour on old nodes |
|---|---|---|---|
| `assetId` | `null` | `data-asset-id` when set, absent when null | A node without it renders, saves, exports and publishes exactly as today — every renderer reads named attributes and ignores the rest |

`uploadFilePromise` resolves `{ id: string; url: string } | null` instead of `string | null` (the
upload response already carries `id` and it is being discarded). `insertMediaUrl(url, contentType,
assetId)` passes it through; `onLibraryPicked` passes `asset.id`.

`SelectionSpec` (`core/selection-spec.ts`) gains `assetId?: string`, read off the node like every
other field there. The three new inspector rows — resolution, size, asset — are drawn only from a
resolved lookup, and the whole group is absent when the lookup 404s or the node has no `assetId`
and no resolvable path. This retires the standing note at the top of `selection-spec.ts` that says
the three facts cannot be produced; update it rather than leaving it to contradict the code.

### T-260 — storage, scan, read path (tech-general)

New entity in `CedarClerk.Server/Data/Entities.cs`, DbSet `GlossaryTermUsages`:

| Property | Type | Notes |
|---|---|---|
| `Id` | `Guid` | PK, `Guid.NewGuid()` |
| `OwnerId` | `string` | Denormalized, like `Reaction`/`DraftGlossaryExclusion` |
| `GlossaryTermId` | `Guid` | Same name `DraftGlossaryExclusion` uses |
| `DraftId` | `Guid` | |
| `Occurrences` | `int` | Total across the draft's primary body and its translations in that term's language |
| `ScannedAt` | `DateTime` | UTC |

Indexes: `(OwnerId, GlossaryTermId)` and `(OwnerId, DraftId)`. One row per (term, draft) pair; a
pair with zero occurrences has **no row** rather than a row holding `0`.

**Migration name: `AddGlossaryTermUsage`** —
`dotnet ef migrations add AddGlossaryTermUsage --project CedarClerk.Server`. This is an added table
only, no rename, so EF's default diff is correct and needs no hand-editing. `Database.Migrate()`
runs at startup and `SchemaDriftGuardTests` fails the build without it — see
`.claude/rules/ef-migrations.md`.

Core matcher, in `CedarClerk.Core/GlossaryScanner.cs` beside `Mark` and sharing its private
helpers:

```csharp
public static int[] CountHits(string plainText, IReadOnlyList<GlossaryEntry> glossary)
```

Result is parallel to the input list — `GlossaryEntry` carries no id, and terms are not unique
across languages and projects, so a dictionary keyed by term would collide. Same word-boundary,
alias, longest-first and case-sensitivity rules as `Mark`; **no HTML-entity skipping**, because the
input is plain text and `&amp;` in a document body is five real letters there. `Mark`'s behaviour
does not change — `.claude/rules/renderers.md` invariant 2 means the new method needs its own tests
in `CedarClerk.Tests` (boundaries, aliases, case sensitivity, longest-first not double-counting,
absent term → 0).

Write path — a new `CedarClerk.Server/GlossaryUsage.cs` with two entry points:

- `SyncForDraftAsync(db, ownerId, draftId)` — rescans one draft against every term visible to it
  (global plus its project's, the `LoadForAsync` scoping rule). Called wherever a draft's stored
  text changes, next to the existing `SyncDocumentLinksAsync` call, which is the precedent for a
  per-save pass. Census as of this amendment, per clause 8: `PUT /api/drafts/{id}`,
  `PUT /api/drafts/{id}/translations/{lang}`, `POST /api/drafts/{id}/primary-language`,
  `DELETE /api/drafts/{id}/translations/{lang}`.
- `SyncForTermAsync(db, ownerId, termId)` — rescans one term against every draft of that owner.
  Called from `POST /api/glossary`, `PUT /api/glossary/{id}`, and the two translate endpoints that
  create terms. `/translate-all` uses the batched `SyncForTermsAsync` instead, so a run reads each
  document body once rather than once per term.

Deletion: `DELETE /api/glossary/{id}` deletes the term's usage rows beside the exclusion rows it
already deletes; draft deletion deletes the draft's usage rows in `DraftDeletion.cs`.

Read path — `GET /api/glossary` gains one field on its existing projection:

| C# property | JSON | TS type | Where |
|---|---|---|---|
| `UsedInDrafts` | `usedInDrafts` | `number` | `GET /api/glossary`, added to `GlossaryTerm` in `core/glossary.service.ts` |
| `ShadowedByTermId` | `shadowedByTermId` | `string \| null` | Same endpoint, same interface — clause 13 |

Count is `COUNT(DISTINCT DraftId)` per term for this owner, fetched as one grouped query and
merged in memory; a term with no rows reports `0`. No other endpoint carries it.

`ShadowedByTermId` names the term that wins this one's spelling — non-null only when another term
of the same owner and language shares a spelling (its `Term` or any of its `Aliases`, compared
**case-insensitively unless both terms are case-sensitive**), **can meet it** (at least one is
global, or both are in the same project), **and** would win at the same position: project-scoped
before global, then `CreatedAt`, then `Id`. Null means nothing shadows it. Computed from the term
list the endpoint already loads — no document is read for it, and it does not touch
`GlossaryTermUsage`. The count beside it stays as scanned and is **not** zeroed.

For the UI lane: draw the count as before, and when `shadowedByTermId` is set, name the winning
term in the same row. Compare the two terms' `projectId` for severity — different (an override,
plain information) or the same (a duplicate, the row takes `warn`).

### T-256 — the draft shelf (tech-ui, no server work)

`DraftMeta` already carries every field the shelf shows — status (`isBlogPublished`,
`blogPublishedAt`, `scheduled`, `isArchived`, `isPrivate`, `isTemplate`), `tags`, `folderId`,
`seriesId`, `documentType`, `languages`/`staleLanguages`, `viewCount`/`reactionCount` and the
`new*` deltas, `parentDraftId`/`siblingOrder`, `updatedAt`. Folder and series **names** come from
`FoldersService` (already bound as `folders` on the page) and `SeriesService`; the parent's title
comes from the already-loaded list. **No new endpoint, no DTO change, no request on selection.**

Selection is `selectedId = signal<string | null>(null)`, set by one control in `.row-actions` (and
its equivalent on the card face), cleared when the selected draft leaves `filteredDrafts()` so the
shelf never describes a row that is not on screen. Table and card views only; tree view keeps
`no-shelf`.

### T-239 (tech-ui, no server work) and T-257 (tech-ui, no server work)

T-239: `POST /api/drafts/{id}/slug` via the existing `DraftsService.setBlogSlug(id, slug)`; its
refusals (`PublishToBlogFirst`, `SlugHasNoUsableCharacters`, `SlugTaken`) render as a
`.channel-error` line under the row, the shape `documentTypeError` already uses. `SpecRowComponent`
keeps its public API unchanged — only its styles move.

T-257: every handler the modal needs already exists on `admin.component.ts` (`savePlan`,
`adjustCredits`, `resetTrial`, `toggleLock`, `toggleAdmin`, `attribute`, `askDelete`) and every
endpoint behind them is unchanged. `expandedId` becomes the modal's target; `app-modal` is the
shell.

**Consequence.** One migration, `AddGlossaryTermUsage`, and it is the only schema change in the
sprint — clauses 4 and 5 removed the second one T-240 looked like it needed. Four new inventory
rows and three amended ones fall to tech-ui in the same commit as the code
(`.claude/rules/ui-changes.md`): the `/drafts` selection control and its shelf, the three media
inspector rows, the glossary "used in" row, the admin user modal replacing the `User card`
expansion, and the `Slug row` line whose "read-only — T-239 makes it editable here" note is now
satisfied rather than pending. `docs/DECISIONS.md` gains this ADR's index row, and T-270 closes on
the board as *already shipped* rather than as work.

What this leaves open: the count in clause 8 is written by two triggers and by nothing else, so a
database restored from a backup taken mid-edit, or rows written by a future import path that does
not call the sync, will under-report until the next save touches them — there is deliberately no
sweeper, because a background rescan of every document against every term is a real cost on a
1 vCPU droplet with no swap and the number does not justify it. And clause 1 makes `field` a
truthful marker by convention plus a component style; nothing mechanically stops a future row from
setting it on plain ink again.

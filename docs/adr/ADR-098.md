# ADR-098 — Telegram: the channel is chosen per language, not per publish (09.08.2026)

**Context**: Marty's request — a second channel was set up, an English-language copy of the main one. The export window already knew how to send several post versions (ADR-096, the "Version" step), but there was one channel for the whole window: RU and EN both went to the same chat. Sending a translation to its own channel took two passes — publish RU, go back, switch the channel and the language, publish EN.

**Decision: a Telegram destination is a pair (language, channel), not just a channel.** The Telegram panel shows one selector row per checked version; with one version there's exactly one row and it looks as before. `canPublishAll` requires a channel for **every** checked version — "RU is set, EN isn't" is an incomplete request, not a request with a default.

**Why not language-on-the-channel** (a `Channel.ContentLanguage` field in Settings): this looked like the more "correct" model, but it answers a different question — "what language is this channel" — while publishing asks "where does this version go." One channel can accept both versions (a shared channel, different days), and the "language belongs to the channel" model forbids that for no reason. The mapping lives where the decision is made — in the export window.

**The mapping is remembered in the browser** (`localStorage`, key `cedar.tgChannelByLang`), not in the database. This is the author's preference, not a property of the post: a draft sent to channel X has no obligation to suggest channel X for the next draft just because of history — but the same person at the same desk almost always sends EN to the EN channel. A stale remembered value breaks nothing: a channel that's no longer in the connected list is simply not filled in.

**Consequences**: the link to the published post is now built from the channel of the language that produced it (previously — from the single `chatId`); `update-preview` (ADR-065) now asks about each version's channel separately, so "overwriting the live post" is now checked against the right chat — previously the question about EN was asked against the RU channel.

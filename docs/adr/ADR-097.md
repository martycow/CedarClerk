# ADR-097 — Blog views by country and reader language: a daily rollup, not a visit log (08.08.2026)

**Context**: Marty's request — "view stats by country (by language) on the stats page." Until now a view was a single `Draft.ViewCount` increment with no dimension at all: no country, no language, no time-of-day. There's no query that can answer "who's reading me" from this — the data simply isn't there.

**Decision: a new `BlogViewGeoDaily` table — one row per (owner, UTC day, country, language), with a counter inside.** Not a visit log: the page only ever asks one question, "how many", so a row per visit would buy nothing except a trail behind the reader. Upsert done by hand (EF has no `INSERT … ON CONFLICT`): increment first, insert only if the bucket doesn't exist yet, and a race between the day's first two views is caught by a unique index — the loser increments the winner's row instead of losing the view.

**Where the dimensions come from**: country from Cloudflare's `CF-IPCountry` header (the tunnel is the app's only entry point, see `.claude/rules/production-environment.md`), language from the primary subtag of `Accept-Language`. Both are normalized in `CedarClerk.Core.ReaderGeo` (pure functions → unit tests): anything that doesn't look like a code falls into one honest `??` bucket — "unknown" is a real share of the audience, not a dropped row.

**The reader's language, not the served version's language.** `Accept-Language` answers the question the breakdown exists for in the first place — "which language is it worth translating into." The served page's language would answer a different one ("is my translation being read") and would be biased: a post with no translation offers no choice, and the whole audience would get recorded under the primary language.

**The breakdown exists only for the blog.** The Bot API doesn't give geography per channel — there's nothing to put here on the Telegram tab, so the block lives only on the "Blog" tab and stays silent on the others.

**Counted per period, not cumulatively.** The cards above are a running total (snapshots), the breakdown is a sum over the selected range: the question is "who read me this month," not "how many readers do I have in total."

**History starts on the day of the rollout** — like `DraftStatSnapshot`, and for the same reason: `ViewCount` is a total with no dimensions inside it, there's nothing to reconstruct a breakdown from. An empty block says so in text, rather than showing a zero.

**What was deliberately not done**: there's no `DraftId` on the row — that would multiply the row count by the number of posts for a per-post breakdown nobody asked for. No cities/regions either: Cloudflare only returns those on paid plans, and country already covers the question.

# ADR-105 — Desktop v1 does not sync with the cloud (10.08.2026)

**Context**: as soon as desktop holds its own SQLite, an obvious expectation appears — that the data is the same as on `cedarclerk.mooexe.dev`.

**Decision: v1 does not sync. On first launch the user chooses a mode: local data, or connecting to the cloud instance as a client.** In cloud mode, desktop doesn't run its own server at all and works as a browser window with filesystem access.

**Why not sync**: two-way sync of two SQLite databases with offline edits is conflict resolution at the level of a TipTap document, meaning either CRDT or "last write wins" with the loss of someone else's edits. The project has already been through a text-loss incident (`T-060`, 29.07) and built three guards around it (ADR-065/066/067); adding an unsolved merge on top of that is a direct path to repeating the same incident, only this time without the ability to roll back.

**A promise not made beats a promise that gets broken.** The mode is chosen explicitly and stays visible in the interface at all times, so that "I edited on my laptop, where are my changes" can't happen silently.

**What this means for the Asset Manager**: in cloud mode, indexing local folders still works — paths go to the server, files are never copied (ADR-107). That is, the main reason the desktop app exists doesn't depend on which mode is chosen.

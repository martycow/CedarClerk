# ADR-105 — Десктоп v1 не синхронизируется с облаком (10.08.2026)

**Context**: как только десктоп держит собственный SQLite, возникает очевидное ожидание — что данные те же, что на `cedarclerk.mooexe.dev`.

**Decision: v1 не синхронизирует. При первом запуске пользователь выбирает режим: локальные данные или подключение к облачному инстансу как клиент.** В облачном режиме десктоп не поднимает свой сервер вовсе и работает как окно браузера с доступом к файловой системе.

**Почему не синк**: двусторонняя синхронизация двух SQLite с офлайн-правками — это разрешение конфликтов на уровне TipTap-документа, то есть либо CRDT, либо «кто последний, тот и прав» с потерей чужих правок. Проект уже проходил через инцидент потери текста (`T-060`, 29.07) и построил вокруг него три гарда (ADR-065/066/067); добавлять к этому нерешённый merge — прямой путь к повторению того же инцидента, но уже без возможности откатить.

**Обещание, которое не даётся, лучше обещания, которое нарушится.** Режим выбирается явно и виден в интерфейсе постоянно, чтобы «я правил на ноутбуке, где мои изменения» не мог случиться молча.

**Что это значит для Asset Manager**: в облачном режиме индексация локальных папок всё равно работает — пути уходят на сервер, файлы никуда не копируются (ADR-107). То есть главная причина существования десктопа не зависит от выбранного режима.

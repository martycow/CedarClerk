# ADR-048 — Registration-form field rules and a DM on each submission
**Context**: Brainstorm v2 items N6 (validate the form's inputs: name at least 2 characters, no special characters except `-`) and N11 (Telegram DM when someone fills the form in). Both sit on the private-post registration flow.
**Decision** (27.07.2026):
- **The rule lives in Core** (`RegistrationFieldValidator`, unit-tested), not in the endpoint and not only in the browser: the page script mirrors it to save a round-trip, but the server re-checks, since a form POST is trivially replayable outside the browser. Letters are tested by **Unicode category, not an A–Z range** — Cyrillic names are the normal case here, so an ASCII regex would have rejected most real submissions. Spaces and `-` pass; digits and all other punctuation don't; a value made only of hyphens and spaces fails because at least one letter is required.
- **Validation applies whenever a name was supplied, not only when the owner marked it required** — junk in an optional field still lands in the audience list the form exists to build.
- **Only the name field is constrained.** Nickname deliberately keeps its freedom (digits and underscores are what nicknames are made of), email keeps its existing `@` check, and the social link is a URL, not a name.
- **The client-side copy of the message reads `document.documentElement.lang`** instead of being interpolated per render: the blog page shell is one static template shared by both languages, so runtime lookup is the only way to keep RU/EN text without threading the language through the template.
- **N11 reuses `NotifyOwnerAsync`** (ADR-040) rather than adding a second notification path: same opt-in flag, same "log and move on" failure behaviour, so a bot that's down or an owner who never `/start`ed it can never turn a successful registration into an error for the visitor.
**Consequence**: existing `PostRegistration` rows that predate this rule are untouched — the validator runs on submission, not on read, so old junk stays visible in the owner's list rather than disappearing retroactively. Names legitimately containing an apostrophe (O'Neill) or a period (Jr.) are now rejected; that follows Marty's rule as stated ("no special characters except the hyphen") and is a one-character change in Core if it turns out to be too strict in practice.

# ADR-291 — Project cleanup and external operations ownership

## Decision

Cedar Clerk owns its application, tests and `cedar.json` operations profile.
MooTool owns the operations executable and its Rust tests.
The `cedar` command remains the Cedar Clerk build, test and deploy entry point.

The existing MooTool implementation and its uncommitted files must remain intact.
The Cedar operations module can live in a separate crate inside MooTool without replacing its interface or configuration.
The module must build without source files from a Cedar Clerk checkout.
Its bundled profile is a starter template; the target repository's `cedar.json` is the active profile.

Remove unused root package metadata, obsolete scratch scripts, old logs and reproducible build output.
Preserve local application data, secrets, source design references and active tools.
Remove comments that repeat code or describe change history.
Retain comments that explain external constraints, safety invariants or deliberate tradeoffs.

## Verification

Validate the repository profile with the external executable.
Run the operations module tests and lint checks from MooTool.
Run Cedar Clerk tests, browser smoke tests and its production build through `cedar`.
Verify that dry-run commands preserve deployment, rollback and local bot safeguards.

## Consequences

A Cedar Clerk checkout requires an installed operations executable.
Its application tests do not rebuild the external operations project.
CLI source installation and Rust verification belong to MooTool.
The deployment protections from ADR-252 remain required.

# ADR-229 — UI tables stay headless: hand-rolled today, CDK when volume grows (29.08.2026)

**Context.** A research pass asked which lightweight table components fit the app. The bench draws
every surface from its own tokens (ADR-071; the prototype look is the law), Angular Material was
never adopted, and the existing tables — the stats page, the drafts and posts-manager row grids —
are hand-written markup styled by the design system. Any library that owns its DOM and ships its
own theme (AG Grid Community at ~338 kB gzipped, ngx-datatable with its lagging Angular
compatibility, Grid.js, PrimeNG Table, Simple Table) would reopen exactly the styling fight the
bench exists to end.

**Decision.** Tables are headless, in three tiers, each entered only when the one below runs out:

1. **Hand-rolled markup on design tokens** is the default and covers everything shipped today.
   Nothing changes for the current tables.
2. **`@angular/cdk`** — already a dependency — is the first escalation: `cdk-virtual-scroll-viewport`
   when a list outgrows plain rendering, `CdkTable` when column/row templating gets repetitive.
   CDK ships zero styles, so the tokens keep full ownership of the look. Sorting is written
   by hand (`MatSort` is off the table with no Material).
3. **`@tanstack/angular-table`** (headless core ~14 kB gzipped, signals-native, Angular 19+) may be
   added only when one screen genuinely needs sorting, filtering and grouping together — and not
   before such a screen exists.

**Consequence.** No new dependency today and no second styling system ever; the heaviest future
table costs one ~14 kB headless core. The price is writing our own sort/filter glue for the simple
cases — accepted, because that glue is smaller than the theme-override layer any DOM-owning grid
would demand.

# ADR-320 — A glossary entry is one term with per-language names

**Status**: DRAFT
**Session**: BR-002
**Supersedes**: ADR-061 (row per language, aliases never translated); the per-term endpoint shape of ADR-062

## Context

`GlossaryTerm` stores one row per language, linked by `SourceTermId`; aliases are a comma-separated string per row and are deliberately not translated. The owner wants one entry with: Name, a localized name and other spellings per selected language, a case-sensitive flag, an image, AI translation and an AI description from the term and/or the image. No AI path accepts images today.

## Decision

1. `GlossaryEntry` (name, description, image, case-sensitive, project) owns `GlossaryEntryLanguage` rows (language, localized name, spellings list, localized description).
2. A migration groups existing rows by `SourceTermId` into entries without losing any alias or description.
3. Matching in renderers and the editor reads the language row for the document's language, as today.
4. AI translate fills localized names and spellings for chosen languages; spellings are produced as inflection lists for that language, not word-for-word renderings.
5. AI description takes the term and, if present, the image. The AI provider interface gains an image input. Both actions charge credits through `SubscriptionPlan.ChargeAiOrRefuseAsync`.

## Consequences

- One editor form shows every language of an entry.
- Glossary import/export and the renderers' term lookup are rewritten against the new shape; `GlossaryTests` and the renderer tests cover it.
- Vision support raises the per-call cost; its credit price is set in `docs/product/BUSINESS.md`.

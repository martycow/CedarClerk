# ADR-203 — A post's project is set where the post is, not where the project is

**Context.** `Draft.ProjectId` has existed since the module landed, and the API to move a document
between projects with it (ADR-101, `PUT /api/projects/{id}/documents/{draftId}`). No screen ever
called it for a post. A project's hub attaches only the documents it created itself, so every post
written before the module — which is all of them — belongs to no project and had no way to join one.
The reported symptom was "all of my posts don't belong to ANY project".

**Decision.** The Posts Manager's Placement group carries the project the post is in: a select of
every project including archived ones, plus "No project". Setting it calls the attach endpoint;
clearing it calls detach. The control appears only when the module is on and there is at least one
project — a picker over an empty list is a control with nothing to control.

Placement, not Publishing: which project a document belongs to is the same kind of fact as which
folder and which series it is in, and those already live there.

The last-document invariant stays the server's. Emptying a project by moving its final document out
is refused there, and the refusal is what the screen shows — the client does not carry a second copy
of the rule to disagree with.

**Consequence.** A loose post can be filed without the project hub having to grow an "attach an
existing document" browser, which would be a second place to answer the same question. The cost is
that a project's documents are now added from two directions, so "what is in this project" is read
in one place and written in two.

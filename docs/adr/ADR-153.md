# ADR-153 — The bottom edge of the bench: the console becomes a drawer, the status bar dissolves

**Context.** Two pieces of furniture occupy the bottom of the screen today and neither is a bench surface.

The debug console (`shared/debug-console.component.{ts,html,css}`, `core/debug-log.service.ts`, `core/debug-log.interceptor.ts`) is a fixed full-width strip at `z-index: 200` whose host takes `pointer-events: none` so that the page underneath stays clickable. It draws a floating tab on pages that have no bottom bar, and hides that tab on the one page that does — the editor — where a `.console-toggle` button in the status bar opens it instead. The two halves are wired together by `DebugLogService.hostBarHeight`, a pixel count the editor writes on init and clears on destroy, mirrored by a `STATUS_BAR_HEIGHT_PX = 27` constant and a `(max-width: 768px)` media query that must agree with the stylesheet by hand. That arrangement exists because of one incident: the console's strip covered the editor's status bar and swallowed clicks meant for the fullscreen button.

The editor's `.status-bar` is the other. It carries seven things at once — word count, character count, a sync indicator, a retry button that only appears when autosave has given up, an invisibles toggle, the console toggle, and fullscreen — on a 27px bar that no other screen has.

Cedar Bench has a surface for each half, and they stack: `BenchDrawer` is the journal in a drawer with a 32px lip, and `RulerBar` is the brass rule below it. `.design-sync/ds-v2/ui_kits/writer.html` renders them in that order at the foot of the writing screen. `RulerBar.prompt.md` states the rule that makes the split decidable: *"Readouts only — nothing here is clickable."* The component enforces it by taking readouts as strings and offering no content slot at all.

**Decision.** The console's chrome becomes a `BenchDrawer`, and the status bar dissolves into that drawer and the rule below it.

**Attribution.** *This is the implementer's decision, taken under Marty's general instruction to proceed with the port. `docs/design/UI-V2-PLAN.md` §4 listed it as the one conditional ADR of the port and it is written here as that condition being met — it was not put to Marty as a question, and this entry must not be read as his answer.* Both halves are reversible: the drawer is one component swapped back for a tab, and every status-bar item is named below with where it went.

1. **The logging survives untouched; only the chrome changes.** `DebugLogService`, `debug-log.interceptor.ts` and the entry shape are not edited. `DebugConsoleComponent` keeps its selector and its job — turning that ring buffer into rows — and loses its tab, its panel, its close button and its own open/close animation, all of which the drawer already owns.

2. **`DebugLogService.hostBarHeight` is deleted, with the constants that fed it.** It measured a bar that no longer exists, for a strip that is no longer an overlay over a page's own furniture. `STATUS_BAR_HEIGHT_PX`, `STATUS_BAR_HIDDEN_MQ`, the `matchMedia` listener and the `ngOnDestroy` reset go with it; the editor stops injecting `DebugLogService` altogether.

3. **The lip is the toggle, so the console toggle is deleted rather than moved.** Open state stays in `DebugLogService.open` — the drawer is a controlled component and the state has to outlive it — but nothing else in the app opens the drawer. The clear button stays inside the journal, where it acts on what is in view.

4. **Every status-bar item is either a readout or a control, and that decides where it goes.** The rule takes no controls, so nothing is placed by taste:

   | Item | Kind | Goes to |
   |---|---|---|
   | Word count | readout | `RulerBar`, right end |
   | Character count | readout | `RulerBar`, right end |
   | Sync state word | readout | `RulerBar`, right end |
   | Retry save | control | the editor's tool strip, rendered only in the error state |
   | Invisibles (`¶`) | control | the editor's tool strip |
   | Fullscreen | control | the editor's tool strip |
   | Console toggle | control | deleted — clause 3 |

   The retry button is the reason this table is written out rather than summarised. Autosave retries on a widening backoff and then stops; the manual button is what remains, and it is the only way to save a draft whose retries are spent. Dropping it as "the ruler is read-only" would have traded a data-loss path for a tidy sentence.

5. **The two surfaces mount at the root for now, and that is stated as interim.** ADR-139 clause 1 puts the shell in a wrapper route rather than in `app.html`, and it still governs: `bench-shell.component` does not exist yet, so the drawer takes over the mount the console already occupies and the rule hangs below it, both behind the same `PUBLIC_ROUTES` predicate. `T-217` moves the two elements into the shell template without editing either component. The rule reads its content from `RulerService`, a page-publishes/chrome-renders signal holder that a shell needs whichever file the shell lives in.

6. **The strip reserves its own height instead of covering the page.** `--bench-bottom-h` is the lip plus the rule; the root component pads by it while the chrome is shown, and the editor's `.app` subtracts it from `100vh`. A viewport-pinned strip that overlays content is what caused the incident in the context paragraph, and repeating it while deleting the workaround would be the same bug with better materials.

**What was rejected.** *Re-skinning the console in bench tokens and leaving the tab.* It keeps a floating tab, a panel, an animation and `hostBarHeight` — four things `BenchDrawer` already is — and the port would then own two drawers. *Putting the retry button on the rule as the one exception `RulerBar.prompt.md` allows ("except a count that opens the BenchDrawer").* That exception is about opening the drawer, not about acting on the document; taking it here would make the first consumer of the bar the thing that breaks its only rule. *Deleting the sync word instead of moving it,* on the grounds that the editor topbar already shows save state. It is a real duplicate — see the consequence below — but the topbar is `T-218`'s and `T-217`'s to resolve, and thinning a status readout from a screen while its replacement chrome is unbuilt leaves the editor with less than it had. *Keeping the ruler inside `editor.component`* so that no root file is touched. It builds page-local chrome that `T-224` would have to unbuild, and it inverts the kit's stack: the rule would sit above the drawer instead of under it.

**Consequence, and its cost.** Save state is now stated twice on the editor — the topbar's `.save-state` and the rule's sync word — which is what it was before, in the same two places, one of them re-housed. The kit duplicates it too (`writer.html` shows a resin drop in the rail header and "сохранено" (saved) on the rule), so the design system does not settle it either. It is settled when the rail lands: `app-resin-drop`'s inventory row already claims to be the only save indicator in the app, and ADR-139 clause 3 places save state on the `RailHeader`. Whoever builds that header removes one of the two, and this entry is where the choice is recorded as owed.

The rule is empty on every screen but the editor, because no other screen publishes readouts yet. That is the honest state of a port at Stage 3 — a blank rule is what an unported page measures to — and each screen fills it as its stage lands.

The reservation in clause 6 costs a scrollbar. Nineteen page components declare `min-height: 100vh` on their own host, so padding the root by 62px makes those documents 62px taller than the viewport and every short page gains a scroll range it did not have. The editor, which declares `height` rather than `min-height`, is exact. This ends when the shell owns the viewport and the pages stop claiming it.

`src/app/app.spec.ts` asserts the console renders on a non-public route. It is rewritten in the same commit to assert the drawer and the rule, which is the proof the chrome moved — the same role ADR-139 gives the `e2e/10-ui-shell.spec.ts` failure. The smoke suite binds neither, so `T-233`'s list does not grow.

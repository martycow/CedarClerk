# ADR-253 — The New-project dialog is a wizard with a preview, not a list (05.09.2026)

**Context.** The create-project modal was a 760px grid of eight-line buttons: an icon, a name, a
blurb and "Starts with: …", with the user's presets appended to the same list. It answered "which
type" and nothing else. The prototype the maintainer handed over on 05.09.2026 draws the dialog as
the first screen of the product a new account meets: illustrated cards, a shelf switch between the
built-in types and the user's own presets, a search, a door to making a preset, and a right column
that reads the pick back — what it is, and the starter structure it is born with — over a name
field that stays visible the whole time.

**Decision.**

1. The dialog is one screen, not steps. Every choice is visible at once, the name field lives in
   the modal's own action row, and Enter there creates. Width 1080, stacking under 900px.
2. Built-in types and the user's presets are two shelves of one strip (`app-index-tabs`), never
   one list. The preset count is the second tile's badge. Switching shelves does not move the
   selection; the detail column keeps reading it back.
3. Each starting point is a card with a 2:1 cover. The four covers are flat inline-SVG scenes
   painted entirely in design tokens, so both themes own them and the accent follows the user's
   choice. A preset wears the cover of the type it produces. No raster assets enter the bundle.
4. The detail column tells the truth about what the project starts with: the starter document,
   its type, and the headings `StarterTemplates.cs` gives it — "Concept, Core loop, Systems,
   Content, Open questions" for a Game, "Unreleased, Known issues" for a Product, blank for Empty
   and Blog. The prototype's `docs/ assets/ notes/ README.md` tree is not drawn: a project has no
   folders, and a preview that promises files the server never makes is a lie in the first minute.
   The headings are mirrored in `projects.create.outline` for both languages, the same duplication
   `STARTER_DOCUMENT_TYPE` already makes for the document type.
5. The "New preset" control is a door, not a form: `/presets?kind=project&new=1`, and the Preset
   Manager reads those two query parameters on arrival. Presets are still made in one place
   (`.claude/rules/ui-changes.md`).

**Rejected.** *A "Community" shelf and "Browse library"* — the prototype draws them, the product
has no shared preset library, and a tab over an empty room is a promise the backlog has not made.
Add the shelf when the library exists. *Raster illustrations* — a PNG per type per theme is eight
files that drift from the palette the moment the accent changes; the SVG scenes cost a few kB and
recolour with the tokens. *A multi-step wizard* — the name is the only input; a step for it is a
click for nothing.

**Consequence.** `projects.component` grows a source strip, a search, a detail column and the
cover template; `presets.component` reads `kind`/`new` from the query. Strings live under
`projects.create` and each `projectTypes.*.about`. The spec covers the four cards, the read-back,
the outline and the empty preset shelf. The inventory's `/projects` block gains five rows.

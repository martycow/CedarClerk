# ADR-245 — A Showcase is an ordered page of safe blocks

**Context.** The Showcase grew one fixed field at a time: cover, description, links, trailer,
gallery, downloads, Devlog, follow form and roadmap. The author can fill the fields but cannot
decide the page's structure, see the assembled result while editing, or ask for help with its prose.
The `/games/{slug}` address and game-only wording also contradict the wider independent-maker
position established by ADR-243.

**Decision.** A Showcase is a Project's public page, canonically addressed as
`/showcase/{slug}`. Existing `/games/{slug}` links and their child routes remain compatible, while
new links use the canonical path. A custom domain still serves the Showcase at its root.

`Project.ShowcaseBlocksJson` stores versioned layout data for a bounded list of known block kinds:
hero, about, links, trailer, gallery, downloads, Devlog, follow and roadmap. A block has a stable id,
visibility, optional title and optional plain-text body. It never carries HTML, script or an
unvalidated URL. Existing Showcase fields remain the source for media, links, press data and other
structured facts; the JSON controls composition and the prose that is genuinely block-local.
Projects without JSON receive the default order that reproduces the existing page, so the migration
needs no data rewrite.

The editor has three cooperating surfaces: an ordered block list, the live rendered result and an
inspector for the selected block. Authors can add, hide, remove and reorder optional blocks. The hero
always exists because it names the page. The live result is a local projection of the same normalized
model the server renders; Save remains explicit.

AI helpers operate only on the selected block's editable prose. They return a suggestion for Review
and Apply rather than writing the Project directly, run through the existing background-job and
credit/refund path, and never receive links, private project material or unrelated blocks.

Public rendering HTML-encodes every authored string. Unknown, duplicate, oversized or malformed
blocks are dropped by normalization, and an empty/invalid layout falls back to the default. The
press kit stays a generated companion rather than a customizable block.

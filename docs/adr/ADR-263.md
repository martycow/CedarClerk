# ADR-263 — Only the active language ships in the initial bundle (T-363, T-102)

**Context** (05.09.2026). ADR-251 left the production build with two warnings and named the
localization dictionary as the first split candidate: the initial bundle measured 836.16 kB against
a 700 kB warning, and `editor.component.css` 34.24 kB against 34 kB. Both dictionaries were imported
statically by `LocaleService`, so every visitor downloaded Russian before the login screen could
paint — 359 kB raw, because Cyrillic is two bytes a character — and the editor's stylesheet had been
growing as one file since ADR-076 said splitting it was separate work.

**Decision.** English stays in the initial bundle: `en.ts` defines `Dict`'s shape and is the fallback
while any other dictionary is still in flight. Every other language is a lazy chunk behind a loader
table in `core/i18n/locale.service.ts` (`ru: () => import('./ru')`). Three properties are kept so the
rest of the app does not notice:

- **The first paint waits for the active dictionary.** `provideAppInitializer` in `app.config.ts`
  awaits `LocaleService.ready()`, which resolves once the chunk for the cached or browser-suggested
  language is in memory. `t()` therefore never renders a fallback on boot; a Russian user still sees
  Russian on the very first frame, exactly as when the dictionary was eager.
- **`t()` stays synchronous and the API stays identical.** `set()`, `uiLang`, `adoptProfileLanguage`
  and `fmt` are unchanged; components, `LangSwitchComponent` and `LanguageMenuComponent` needed no
  edits. A switch to a language not yet loaded shows English for the duration of one chunk fetch and
  swaps when it lands — the dictionary map is a signal, so the swap is a normal change-detection pass.
- **The other dictionaries are preloaded once the browser is idle**, the way `PreloadAllModules`
  fetches the other routes after the first screen: by the time anyone reaches a picker, the switch is
  as instant as it was when everything shipped eagerly. A failed chunk leaves English on screen and
  caches nothing, so the next `set()` simply asks again.

The pseudo-locale (T-051) wraps whichever dictionary is loaded, keyed by dictionary object rather
than by language, so it cannot serve a cached English inflation after Russian has arrived.

**On the editor stylesheet, in the same pass.** `editor.component.css` is now five files listed in
`styleUrls` in cascade order — the page frame and shared primitives, then `editor-toolbar.css`,
`editor-workspace.css`, `editor-publish.css`, `editor-dialogs.css` — cut by region of the page, not
by size. The split was verified rule-for-rule: every rule survives exactly once, and no two rules of
equal specificity that share a property and could match the same element changed relative order.
The largest piece is now 20.8 kB against the unchanged 34 kB warning.

**Rejected.** *Lazy-load English too* — it would leave `t()` with nothing synchronous to return
before boot, and every unit test that reads a label would have to await a chunk; keeping one
dictionary eager costs 195 kB raw and buys a fallback that always exists. *Block `set()` until the
chunk arrives* — it would make the login picker's highlight lag behind the click and give the
profile-language adoption a second asynchronous step; with idle preloading the window in which the
fallback can show at all is the first second after boot. *Moving the budgets* — ADR-251's reason
stands; both signals are untouched.

**Consequence.** `ng build` is warning-free again: initial **836.16 kB → 477.74 kB raw**
(162.72 kB → 127.72 kB transferred), the 700 kB warning has 222 kB of headroom, and the Russian
dictionary is a 359 kB lazy chunk (40.8 kB transferred) fetched only by the people who read it.
Adding a language is one line in the loader table plus the dictionary file; it never touches the
initial bundle. `LocaleService` has its own spec covering the fallback, the swap, the cached boot
language, preloading and the pseudo-locale.

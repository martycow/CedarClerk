# ADR-234 — A preset's kind decides which record reads it, and nothing else about it differs (01.09.2026)

**Context.** ADR-233 built `Preset { OwnerId, Kind, Name, ConfigJson, SortOrder }` with one kind
wired, and said the next two slices — `project` and `export` — were deliberately left until their
config shapes could be designed against real use. T-331's remainder is those two.

The first shape of the API had prejudged it: `SavePresetRequest(Kind, Name, BaseType, Icon,
Headings)` named a document preset's fields directly, so a second kind could only join by adding
fields no other kind reads.

**Decision.** The request carries a free-form `Config` object and the kind decides which record
parses it — `DocumentPresetConfig`, `ProjectPresetConfig`, `ExportPresetConfig`, all in Core, all
with the same `Parse` / `ToJson` pair. The endpoint re-serialises **from the record**, never from
the request, so a bad base type, an unknown destination or an overlong title cannot reach the
database through a field the validator forgot to name. `PresetKinds` is the frozen list, matching
`ProjectRoles` in shape: a fourth kind is a constant, a record and a UI, never a migration.

Three commitments beyond that:

1. **The kind is fixed at creation.** `PUT` refuses a kind change, because the kind decides how
   `ConfigJson` is read and a row whose kind moved under a config written for the old one is a row
   nothing can read.

2. **A project preset supplies defaults; it never overrides what the caller states.** `POST
   /api/projects` reads the preset first, then lets an explicit `projectType`, `documentType`,
   `documentTitle` or `description` win over it. That is what lets the dialog offer a preset and
   still let it be edited before Create — the alternative, a preset that silently reasserts itself,
   would make the fields beside it a lie.

3. **An export preset names destinations and languages, never channel ids.** A channel can be
   disconnected and reconnected as a new row, so a preset holding one would fail at send time
   rather than at pick time. Which Telegram channel receives the post stays step 3's question,
   asked against what is actually connected now. An empty language list means "whatever the post
   already has", never "no languages": a preset saved when the post had three translations must not
   drop a fourth written afterwards.

**Consequence.** No migration — the table already had the columns. Three kinds on one Preset
Manager screen, switched by an index strip; project presets beside the four built-in types in the
New-project dialog; an export preset offered from the header of the Export modal's step 2, filling
its ticks in one pick. The built-in types stay in code as the always-present baseline, exactly as
ADR-233 left them.

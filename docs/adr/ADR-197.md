# ADR-197 — Glossary coverage and revision comparison are explicit

**Context.** Glossary rendering marks only the first occurrence of a term, and revision history reports
block counts plus the selected version's plain text. Neither answers the annotated questions: where a
term appears throughout a Document, and exactly what a revision added or removed.

**Decision.**

1. Glossary scanning marks every eligible occurrence, still excluding links, code, and already-marked
   glossary markup. Matching remains case-insensitive and longest alias wins at a shared start.
2. A `DraftGlossaryExclusion` row disables one GlossaryTerm for one Draft language. The row is
   owner-scoped and unique on `(DraftId, GlossaryTermId, Language)`. The writer exposes the detected
   terms for the active language and lets each be included or excluded without changing the global term.
3. Blog rendering loads exclusions for the rendered language and omits those terms from the scan.
4. Revision history presents a unified, Git-like text diff. Removed lines and added lines are visible
   independently; unchanged context remains readable. Restore behavior and immutable revision storage
   do not change.

**Consequence.** Glossary visibility becomes a per-Document-language publishing choice rather than a
global mutation. The new entity requires an EF migration in the same implementation chunk. Renderer
escaping and coverage tests remain mandatory.

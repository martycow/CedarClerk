# ADR-308 — Bash release deployment

## Decision

Provide an executable runbook in `docs/for_user/deploy.sh`, beside its Russian
instructions, and a server worker in `Scripts/server/deploy-release.sh`.
Build and test the Angular SPA and framework-dependent Linux server locally.
Desktop installers are a separate release pipeline.

Require clean master, the exact CurrentVersion tag, and a local LIVE tag matching
the running version. Never silently skip tests or change release metadata.
Transfer one checksummed archive using rsync with partial transfers and bounded
retries, replacing ADR-113's custom append protocol. Validate its file count and
required files before downtime. Keep artifacts outside the checkout.

A detached, locked server worker survives client disconnection. Stop the service,
create and verify a SQLite backup, then swap directories. Preserve older app.prev
releases under unique names rather than deleting them. Verify local and public
health, the version and a static release marker before reporting success. On
failure, restore the previous application and verify its health. Never restore the
database automatically: migrations and startup backfills may need a deliberate
recovery, and overwriting the database could discard new writes.

Update local LIVE/LIVE-PREV only after confirmed success. Preserve logs, backups,
failed releases and staging for diagnosis. No deploy is performed by adding or
verifying these scripts.

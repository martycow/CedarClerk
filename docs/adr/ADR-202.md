# ADR-202 — The index reads in one language; a post page does not ask

**Context.** ADR-192 gave the whole blog a language toggle and ADR-193 removed it, pinning the index
to English. Removal was right about the failure — a site-wide switch put an English toolbar over a
Russian post and a Russian one over an English post, because a post's language is the post's and not
the reader's. It was wrong about the index. An index is not a post: it is a list of cards whose
titles and teasers exist in several languages, and it has chrome of its own — order, month headings,
card dates — that has to be in one of them.

**Decision.** The index carries a language pick, in the same query string as its other filters
(`?lang=`), defaulting to English and saying nothing in the address when it is English. It sets two
things and no others: the index's own chrome, and which translation a card previews in. The
languages offered are the ones the posts actually exist in, narrowed to those `IndexLabels` has
words for — offering a language the toolbar cannot speak would rebuild ADR-193's mixed page.

**A post page keeps no such control.** There the language is a property of the thing being read, the
per-post switch already answers it, and a second control in the header would be the site-wide toggle
under another name.

The reading controls (size and face, ADR-181/192) reach the card teaser as well as the post sheet,
two steps under the body measure. A size control that moves nothing on the page it was opened from
reads as broken.

**Consequence.** A Russian reader gets a Russian index and Russian teasers where the translations
exist, without a Russian toolbar ever appearing over an English post. The cost is a second chrome
table to keep in step with the first, and a language that is offered only once the index chrome
speaks it — deliberately, so the failure mode is a missing option rather than a half-translated
page.

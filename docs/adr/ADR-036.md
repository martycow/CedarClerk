# ADR-036 — Phase 8 Step 6: tags extended to the Telegram export path as a trailing hashtag line
**Context**: `Draft.Tags` (flat comma-delimited string) already renders as clickable chips on the blog, but Telegram posts carried zero tag information — confirmed by grep, no prior attempt existed. `docs/ROADMAP.md`'s Step 6 also listed "autocomplete from previously used tags" as not-started, but a 25.07.2026 docs audit found that half already shipped as part of ADR-035's tag "cloud" picker — the doc was stale, not the code.
**Decision** (26.07.2026): `PostEndpoints.BuildHashtagLine(string tags)` — a pure, unit-tested static method — splits tags via the now-`internal` `BlogEndpoints.SplitTags` and joins them as `"#tag1 #tag2 ..."`, stripping internal whitespace from each tag (Telegram hashtags can't contain spaces). Appended as a trailing `RichParagraphBlock` in `PostEndpoints.PublishAsync`, after the post signature and blog cross-link (matching the existing append-order precedent from ADR-034's signature and the blog-link addition). Relies on Telegram's native client-side `#word` auto-linking — no special API entity construction, no escaping needed (`RichRunText` is plain text, not HTML).
**Consequence**: No schema change (`Draft.Tags` already existed). Not yet verified live against `@testingandfun` as of writing — deferred by Marty's choice during this session, flagged for a follow-up verification pass before considering Step 6 fully closed.

# ADR-209 — The legacy blog host is an account too, resolved rather than special-cased

**Context.** `blog.mooexe.dev` has served the maintainer's blog since long before subdomains, and
its URLs are indexed, linked from channel history that cannot be edited, and printed in posts. Once
every account gets `name.cedarclerk.app`, that host is the one that cannot name its owner in its own
hostname. The cheap answer is a branch: "if the host is the blog host, skip the tenant machinery."
A branch is exactly how a host ends up outside every rule the other hosts obey.

**Decision.** The legacy blog host is one account's blog, and the only difference is that its owner
is looked up instead of read off the Host header.

- **`Cedar:BlogOwner` names the account by `TenantUsername`.** A name rather than an id: readable in
  the systemd drop-in, and it survives a restore into a fresh database. Unset means "the one admin
  account", which is what a single-tenant install already is — and *only* when there is exactly one;
  two admins and the answer is null rather than a guess.
- **An owner that cannot be told is a 503, not a 404.** The blog is not gone; this server cannot say
  whose it is. A 404 here is cacheable and reads to a stranger as a blog that was taken down.
- **The legacy owner keeps the legacy host.** `BlogTenant.HostForOwnerAsync` answers
  `blog.mooexe.dev` for that account and `name.cedarclerk.app` for everyone else, so the URLs the
  app hands out — invites, the admin post list, showcase pages, exports, the Telegram cross-link —
  are the URLs that host actually serves. Moving those links would be a break with no undo.
- **The blog a request renders is threaded explicitly, as well as filtered ambiently.** `BlogSite`
  carries owner and host together through every render path. A page that names its owner in its own
  query is a page whose scoping can be tested, and the two mechanisms together are what stop a slug
  from resolving into somebody else's post.

**Consequence.** There is no host in the system that renders a blog without being one account's
blog, which is what lets `MapWhen`, the media door and the blog-only rule ask one question instead
of three. Two costs are known and open: the legacy host resolves its owner twice per page render
where a subdomain resolves it once (`T-291`), and it is not yet held to the blog-only rule the
subdomains are — `/index.html` still answers with the application shell and `/api/*` still answers
401 instead of 404 (`T-287`).

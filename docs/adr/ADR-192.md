# ADR-192 — The blog reader moves to the wood board, and gets search, sort, a site-wide language toggle, blog-wide prev/next and a copy-link button (23.08.2026)

**Context.** Marty imported a Claude Design brief ("Blog pages design brief") built against the same
Cedar Bench vocabulary the blog already speaks (`RailHeader`, `Worktop`, `PaperCard`, `StampBadge`,
`LeafTag`, `BrassPin` — the same component names and the same served token set as ADR-177/178). The
brief redrew the single-post reader on a wood board with brass pins, and its script assumed several
things the real blog does not have: a live search box, a global RU/EN toggle, a newest/oldest sort,
blog-wide prev/next neighbours, and a "copy link" button.

Two of those collide with earlier, deliberate decisions. ADR-179 clause 4 put the post sheet flat on
the wall specifically *without* wood, rotation or a deckled edge — "a published page does not lean"
and "the tear says draft." Put back to Marty in those terms (reopen the wood-frame question outright,
or add it as a second role beside the flat sheet, or confine it to code blocks — the same three-way
framing ADR-191 used for Martian Mono), he chose the direct reopening for the frame, and separately
chose to build every one of the brief's assumed features for real rather than a visual-only port.

**Decision.**

1. **The reader sits on the wood board; the sheet inside it stays exactly as ADR-179 left it.**
   `.post-sheet` is wrapped in a new `.post-reader` container painted with the *same* wood the header
   and footer already use — `var(--tex-wood), var(--surface-rail)` — not a lighter "raw plank" tone
   the brief used, because that second wood family (`--wood-hi`/`--wood-lo`/`--wood-edge`) is never
   served to the blog (it is not on `CONTRACT` or `MATERIALS` in `contract-tokens.mjs`) and reusing
   the rail's own material is more coherent than inventing a second one anyway. Two `.post-pin` brass
   circles sit on the frame's top edge. `.post-sheet` itself is untouched: still flat, unrotated, no
   deckled edge — ADR-179's "Rejected" clauses for rotation and deckling are about the sheet being
   finished work, not about which material sits behind it, and this decision does not reopen them.

2. **A site-wide language cookie (`cedar_blog_lang`), and a header RU/EN toggle that sets it.**
   `LangToggleHtml` renders two plates linking to the current path with `?lang=` swapped; whichever
   explicit `?lang=` a page receives (this toggle, a shared link, the in-post switch) refreshes the
   cookie, and a page with no explicit `?lang=` falls back to it instead of always defaulting to
   Russian. This reaches the index (date-label language) and post pages (translation selection, same
   as an explicit link would) alike — a single mechanism, not a second one per page type.

3. **Index search and sort, server-side, as a GET form and a link.** `?q=` filters the already-
   materialized post list by title and tags (`string.Contains`, ordinal-ignore-case) the same way
   `?tags=` already does; `?sort=old` reverses the newest-first order. Both round-trip through
   `IndexFilterUrl` alongside `tags=`, so changing one parameter never drops the others. A form and
   plain links, not client-side JavaScript filtering the brief used: the index is otherwise full page
   loads with no post content shipped to the client to filter, and the tag bar right beside it already
   works this way.

4. **Blog-wide prev/next, shown only outside a series.** `RenderPostAsync` queries the nearest newer
   and nearest older published post by `BlogPublishedAt` and renders them as two `.neighbour-card`
   tiles below the sheet, inside `.post-reader`. Gated on `draft.SeriesId is null`: a post already in a
   series has `.series-nav` for the identical job, scoped to that series, and showing both would be
   two navigations answering the same question at once.

5. **A copy-link button beside the existing Telegram cross-link**, not replacing it — they answer
   different questions ("read this on Telegram" vs. "give me this URL"). Plain `navigator.clipboard
   .writeText(location.href)`: the address bar's own value, `?lang=` and all, not a canonicalized one.

6. **A face toggle joins the reading menu**, extending ADR-181's mechanism rather than building a
   second one: `data-face` on `<html>`, a third `SETTINGS` entry in the existing generic apply/mark
   JS, a third `localStorage` key read by the same head pre-paint script. Buttons read the faces' own
   names — "Literata" / "Source Sans 3" — unlocalized, the same choice the app's own typeface picker
   makes; only the group label ("Гарнитура"/"Face"/…) is translated, in all nine `ReadingLabels`
   locales.

**Rejected.** *A second `--font-mono`-style role beside the flat sheet for the wood frame*, i.e.
leaving `.post-sheet` itself flat but offering a second, wood-styled post-reading mode. Not what was
asked; the frame changes, the sheet does not. *Deckled edges and rotation on the reintroduced wood
frame.* ADR-179's reasoning for refusing them was never about the material behind the sheet, and nothing
here gives cause to revisit it. *A raw-plank wood tone distinct from the rail's.* Would need three new
served tokens (`wood-hi`/`wood-lo`/`wood-edge`) added to `contract-tokens.mjs` for one container, where
the rail's own wood already reads correctly and keeps the blog's wood vocabulary to one family.
*Client-side search/sort/filtering.* Would ship every post's full content to the browser on the index,
the one thing the current server-rendered, no-framework architecture is built to avoid. *A Worktop
grid-and-lamp background on the index, matching the brief's board treatment there.* Out of the scope
Marty was actually asked about (the post reader specifically) and, by ADR-179's own logic for refusing
a worktop under the post ("the grid is squared paper for a thing being worked on"), the same argument
would apply to a published index of finished posts.

**Consequence.** `.post-sheet` still means exactly what ADR-179 said; only its surroundings changed.
The blog now carries a cookie it did not before (`cedar_blog_lang`, a year-long, `HttpOnly`, essential
cookie — no consent banner, same footing as the existing view-dedup and private-access cookies). Two
navigations can now appear near the bottom of a post — blog-wide neighbours or series nav, never both,
enforced by the `SeriesId is null` gate in code rather than by convention alone. The reading menu grew
its third control without a fourth `localStorage` key's worth of new plumbing, because ADR-181's
`SETTINGS`-map mechanism was built generic enough to extend by one entry.

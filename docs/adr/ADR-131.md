# ADR-131 — Discord publishing over a webhook, no bot and no OAuth (18.08.2026)

**Context.** T-161: Discord is the home of the indie community; Codecks and IndieViral both have the integration. Discord offers three integration depths — a full bot (OAuth, gateway, hosting implications), an OAuth2 app, and a per-channel incoming webhook. Cedar Clerk publishes announcements; it does not need to read anything.

**Decision.**
1. **Incoming webhook, nothing more.** Connect = paste the webhook URL (created by a channel admin in Discord's own UI in three clicks). No app review, no token refresh, no gateway process. The URL contains its token, so it *is* the credential: stored encrypted via `PublishTargetSecrets` like every other network's, `RemoteId` = the webhook id, `DisplayName` = the webhook's name. Verified at connect time by `GET`ting the webhook (Discord answers with its name/channel/guild without auth beyond the URL itself).
2. **A short post with a link, not the document** — the ADR-077 model verbatim: the author's per-network override wins, `DiscordPostBuilder` derives the fallback teaser (2000-char limit), the blog link goes on its own line, and Discord's own unfurler renders the rich card from the blog's OG tags (T-174) — which is why the target attaches no media itself (`MaxMediaItems = 0`): the card already carries the cover image, and a second copy of every screenshot above it is noise, not reach.
3. **`allowed_mentions: { parse: [] }` on every send.** Document text is author-controlled but teaser-derived; without this, a post whose first paragraph contains `@everyone` pings the entire server. No devlog announcement legitimately needs mentions.
4. **No threads** (`SupportsThreads = false`): a thread of webhook messages has no reply structure on Discord — it would be N disconnected messages. The whole document belongs on the blog; the webhook carries the announcement.
5. Sends use `?wait=true` so Discord returns the created message; with the guild and channel ids captured at connect time that yields a real public URL (`discord.com/channels/{guild}/{channel}/{message}`).

**Consequence.** Collecting feedback FROM Discord (reactions, replies) is explicitly out — a webhook cannot read, and that half was excluded from T-161 from the start. If it ever matters, it is a bot and a different ADR.

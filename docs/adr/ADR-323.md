# ADR-323 — The landing is built from sections of typed blocks

**Status**: DRAFT
**Session**: BR-002
**Supersedes**: ADR-309; the "feature list is code" part of ADR-215

## Context

`LandingSettings` is one row: fixed En/Ru columns, six section flags, JSON for shots/roadmap/story and an `EditorialJson` En/Ru dictionary. Section order is hard-coded in `LandingEndpoints.cs`, and the feature list is a code array. The owner wants Admin to choose shown sections, compose each from blocks with their own properties and layout, and localize every text into RU, EN and added languages.

## Decision

1. The landing is an ordered list of sections; each section has a layout and an ordered list of blocks.
2. Block types: Text, Subscribe, Hint, Screenshot, Timeline, Social media, Discovery recommendation, Tools, Pricing, FAQ, Download.
3. Every text field is a language map. RU and EN are required; Admin can add other UI languages.
4. Sections and blocks can be hidden individually.
5. The current content is migrated into the new model so the live page is unchanged on first deploy.
6. Prices, quotas, language count and destinations stay derived from `PlanLimitations` and product definitions; the Pricing block only chooses presentation.
7. All prose stays escaped; headline markup permits only line breaks.

## Consequences

- One new JSON column (or table) and a data migration; `LandingSettings`' fixed columns become vestigial and are dropped later.
- Admin → Landing becomes a block editor with a live preview.
- The Tools block reads an editable feature list; screenshots attach to features by id, not by array position.

# ADR-093 — X-коннектор: OAuth 2.0 PKCE, «сохранить до использования», текст+ссылка в v1 (05.08.2026)

**Context**: T-110. Кошелёк (ADR-092) и `XPostBuilder` готовы; сам коннектор — третья реализация `IPublishTarget`. X API v2: постинг требует user context (OAuth 2.0 Authorization Code + PKCE, scope'ы `tweet.read tweet.write users.read offline.access`); app-only Bearer постить не может. Конфиг-ключи: `Cedar:X:ClientId` / `Cedar:X:ClientSecret` (drop-in на Pi, gitignored локально — как все секреты).

**Ротация refresh token — центральный риск**: X выдаёт новый refresh token при каждом обновлении и инвалидирует старый. Для Bluesky ADR-079 ушёл от хранения токенов вообще (сессия с app-пароля на каждую публикацию) — у X такого пути нет. Правило здесь: **новый refresh token сохраняется в БД ДО первого использования нового access token**; упавший сейв — публикация не отправляется. Потерянный токен = «переподключите X» (та же деградация, что `TryUnprotect`→null из T-084), а не тихо мёртвый таргет.

**v1 постит текст + ссылку, без медиа и без тредов.** Пост в X по ADR-077 — самостоятельный короткий пост (override автора или тизер), ссылка на блог ведёт к полному документу с медиа; загрузка картинок байтами (до 4) и цепочка reply — отдельные строки бэклога, не блокирующие первый работающий пост.

**Валидатор научился сетям-тизерам** (`PublishCapabilities.DerivesShortPost`): для сети, которая сама выводит короткий пост, `too-long`/`too-many-media` — информация («будет тизер»), не блокировка. Это чинит и латентный баг Bluesky: очередь 422-ила любой документ длиннее 300 графем, хотя билдер гарантированно строит влезающий пост. Найден при постройке X, не в проде — Bluesky-путь ещё не был live-verified.

**Списание кредита — после успеха, якорь — id созданного поста** (уточнение ADR-092, где якорем назван PublishJob: id поста ещё точнее — каждый реально созданный пост стоит кредит, ретрай очереди после неуспеха создаёт новый пост и честно платит за него). Недостаток баланса — отказ **до** отправки (402, невоспроизводимый для очереди — ретраи не жгутся).

**Callback**: `GET /api/targets/x/callback` (ровно тот URI, что вбит в портал). State+PKCE verifier живут в памяти процесса 10 минут — одна нода, перезапуск роняет только незавершённые подключения.

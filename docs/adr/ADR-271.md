# ADR-271 — The invite shelf draws the day series it already has (05.09.2026)

**Context.** Wave 2 item 15 shipped named invite links with lifetime totals per link and took
cut #6: no per-day bars, although `ChannelMemberDaily` has been written per day since the
feature landed and `GET /api/channels/{id}/member-flow` already answers the series (T-327). The
Stats tab could say how many people a link brought in, never when — a launch post and a slow
week looked the same in the table.

**Decision.** The invite-links card draws the last 30 UTC days above its table, read-path only:
one request beside the link listing, links summed per day, quiet days filled with zeros on the
client. Two bars a day — joins in `--ok`, leaves in `--danger` — scaled to the window's tallest
value, with no chart library and no new tokens. The figure is a single `role="img"` named by the
totals sentence; the same sentence is printed under the axis, and every day is in the page as a
visually-hidden table. A window with no events prints that one line instead of an empty figure; a
failed fetch leaves the totals table exactly as it was.

**Rejected.** *Per-link bars* — thirty columns cannot carry a per-link breakdown legibly, and
which link a join came through is already the table's answer. *Reuse `app-growth-chart`* — it
draws running totals as lines; a daily count is a different shape and the chart's readout and
open-tail rules would say things a tally does not mean. *A display-zone window* — the server's
days are UTC midnights (`day.slice(0, 10)`, never `Date` parsing), so shifting them into the
viewer's zone would move events across day boundaries that the data does not have.

**Consequence.** `ChannelsService.memberFlow()` and `ChannelMemberFlowRow` join the client API;
the card's inventory row loses its "cut #6 taken" note. Leaves stay unattributed to any link,
as the note under the table has always said, and the series is the sum the table already shows —
a mismatch between the two would be a server bug, not two sources.

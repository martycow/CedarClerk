# ADR-125 — Post series: an entity, not a tag (18.08.2026)

**Context.** "Devlog #1..#N" goes straight to the devlog-first positioning: a reader who arrives at part 7 should reach part 1, and the series' own page, in one click (T-178, PUB-04 from the Input sweep). The cheap option, "a series is a special tag", was considered and rejected: a tag has no identity — no stable slug for a page, no ordering (tags are a flat string), and "part N of M" cannot be derived from it.

**Decision.**
1. **`Series` is an entity**, per-owner: name, slug (via the existing `SlugGenerator`, unique per owner), description; a draft is linked via the pair `Draft.SeriesId` + `Draft.SeriesOrder` (both nullable, set and cleared together — linking assigns `max+1`, unlinking clears both). Display order is `(SeriesOrder, BlogPublishedAt)`: an explicit order wins, the date is an honest fallback for entries from the same wave. Manual reordering is deferred — until it exists, link order matches writing order.
2. **URL — `/series/{slug}`** on the blog host: the first two-segment branch in `HandleRequest` (before this, ≥2 segments meant 404). The series landing page is built on the pattern of the tag landing page and shows **exactly what the index shows**: `IsBlogPublished && (!IsPrivate || IsListedWhilePrivate)`, private cards shown with a lock and no teaser. An empty or fully private series is not a 404 — it's an honest empty landing page.
3. **On the post page**: a series line above the title ("part N of M", N counted over the visible ordered list — a private, invisible post does not shift the numbering for other people's eyes) and a prev/next block over the same neighbors. RSS is unchanged.
4. Management follows the folders pattern entirely (77-line endpoints, a service with a latch, a picker): `GET/POST/PUT/DELETE /api/series` + `PUT /api/drafts/{id}/series`; deleting a series unlinks its drafts without touching them.

**Consequence.** Linking a series to a module project (the showcase, T-159) is the next step, not this one: a series lives per-owner and knows nothing about `Project`. The "part N of M" numbering is recomputed on every render — storing it would mean fixing it on every republish of a neighbor.

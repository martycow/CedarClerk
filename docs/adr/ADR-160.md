# ADR-160 — A hub tile is a door: the wall shows the modules the app has, not the ones the kit draws

**Context.** `.design-sync/ds-v2/ui_kits/hub.html` puts six plates on the wall — Документы, Задачи,
Спринт, Ассеты, Билды, Метрики — each an icon, a name, one mono number and a line of context. The
app has four screens a plate could open: `/projects/:id/tasks`, `/planner`, `/assets`, `/builds`.
The two missing ones are missing for different reasons, and the difference decides what happens to
them.

*Documents* has no screen because the hub **is** it. `project.component` at `/projects/:id` is
today's document list: three featured type cards and a tile row of the rest, every entry opening the
editor. There is no `/projects/:id/documents` route and no per-project view in `/drafts` either —
`DraftMeta` carries no `projectId` at all, which ADR-139 already records as the reason the rail's
project switcher is account-scoped everywhere but the hub.

*Metrics* has no data. `Channel` carries `OwnerId` and no `ProjectId`, blog statistics hang off a
draft rather than a project, and there is no project→channel link table anywhere in the schema, so
no query can answer "views for this project". The number the app can produce is the account's, and
ADR-148 has already placed that number: a tab body inside the Posts Manager, deliberately not a
destination of its own.

**Decision.**

1. **A tile is drawn only when both halves are real: a screen behind it, and a number this project
   can answer.** Four tiles ship — Tasks, Sprint, Assets, Builds. The wall is `auto-fit` rather than
   the kit's fixed three columns, so four plates fill it instead of leaving the hole a 3×2 grid
   would keep for two tiles that do not exist.

2. **Documents are the hub's own panel, under the wall, and get no tile.** A plate that opened the
   screen it is standing on is not a door. The panel is one `ShelfPanel` listing *every* document
   with its type icon, which is strictly more than the three-per-featured-type the old body showed.

3. **Metrics gets no tile at all — not a dashed one.** An em dash would be a promise that the number
   is coming; the account-wide number rendered on a project screen would be the confident wrong
   answer the shell already refused for the project switcher. The Metrics hook on the rail reaches
   the same place from every screen, so nothing is unreachable.

4. **The build count is fetched, not invented, and it fails to a dash rather than to zero.**
   `GET /api/projects/:id/builds` exists; `ProjectSummary` carries no build summary, so the hub asks
   for it beside the detail and the tile shows `—` until the answer lands or if it never does. "No
   versions yet" and "could not ask" are different sentences and 0 says the first one.

5. **The left shelf is a switcher, not the list screen.** It absorbs the projects list as the kit
   draws it — thumbnail initials, name, state — and its header action is a link to `/projects`
   rather than a second create-project modal. Search, the filter chips, the counts and creation stay
   on `ProjectsComponent` until `T-226` retires it, because `.claude/rules/ui-changes.md` rule 1
   forbids the second home more strongly than the kit asks for the `+`.

6. **What the kit's third shelf group wanted does not exist, and the project's own public page takes
   the slot.** The kit's «Каналы» — Telegram, Blog, Steam per project — needs the link table clause
   above says is absent. `Project.ShowcaseSlug` (ADR-134) is the one per-project outbound address the
   app actually holds, so the group names that, and says "not published" when there is none.

7. **Nothing on the worktop's chalk edge is invented.** The kit's right-hand tag reads
   `Unity 6.1 · Windows / Linux` and its subtitle carries a dated milestone; the app stores no
   engine, no target platforms and no milestone. The edge carries the last activity the API does
   report, and the hero's subtitle carries counts.

**Consequence.** The hub is legible against the kit only if a reader knows two of the six plates are
absent by decision. That is what this entry is for. The cost of item 4 is a third request on hub
load; the repair is a build summary on `ProjectSummary`, which is a board row rather than part of a
re-skin. Item 5 leaves two entrances to the project list for one stage — the shelf and `/projects` —
which is the smallest wrong state available while the route tree is `T-226`'s to change, not this
task's.

**Rejected.** *Six tiles with two of them dashed*, which draws two doors into a wall; *a Documents
tile that scrolls its own panel into view*, which is a 200px journey dressed as navigation; *making
`/projects` redirect into the hub now*, which is a routes change outside this screen's files and
would strand the create-project modal, the search and the filter chips with no home; and *a Metrics
tile linking to the account-wide Posts Manager*, which spends a project screen's plate on a number
that is not about this project.

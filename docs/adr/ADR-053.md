# ADR-053 — FI1: the Appearance panel gets a real theme switch and an explicit Apply, reversing part of ADR-035
**Context** (27.07.2026): Marty's live feedback on the day-old Appearance panel (`docs/BACKLOG.md` FI1, 7 sub-items) — it doesn't match the rest of the app's visual language, its narrow scroll column shows a default OS scrollbar, the Light/Dark toggle is confusing, more typefaces are wanted, and there should be an explicit Apply instead of saving on every interaction. Marty also suggested a popup instead of a side panel, as a suggestion rather than a firm instruction.

**Decision**:
- **The Light/Dark toggle now switches the real theme** (`ThemeService.set(...)`, same instant call the topbar's own theme button makes). Previously `appearanceMode` was a panel-local signal that only selected *which* theme's accent the swatches below were about to edit — clicking it visibly did nothing to the app, which is exactly the "real ambiguity" the backlog note names. The accent swatches now simply follow whichever theme `ThemeService.theme()` currently is; no more separate mode state to keep in sync.
- **ADR-035's "applies instantly, no Save button" is reversed for the appearance half of the panel** (sheet width, typeface, font size, line height, table size, the five checkboxes, accent). `AppearanceService` splits into `preview(patch)` (updates the `prefs` signal + accent CSS var live, no request — this is what every control now calls) and `commit()` (sends the currently-previewed value, called only by a new Apply button). The sheet still re-renders on every drag tick — that live preview was ADR-035's whole point and still is — but a slider drag no longer fires a save per tick, and the panel gains a real busy/saved state on Apply, which incidentally closes the "instant-save controls have no loading indicator" gap `docs/UI-INVENTORY.md` had flagged. **The toolbar half of the panel (preset/row drag-drop/button visibility) keeps its old instant-save behaviour** — deliberately out of scope: drag-and-drop reordering doesn't suit an Apply-gated model the way a slider does, and FI1's ask was specifically about "the appearance panel"'s controls Marty was reacting to.
- **Two more typefaces** (`serifClassic`, `rounded`), still system-font stacks only — no webfont loading path exists in this app (`docs/DESIGN.md`) and this doesn't add one.
- **A global thin scrollbar** (`scrollbar-width: thin` + `::-webkit-scrollbar*`, `styles.scss`) rather than a panel-scoped fix — the default chunky OS scrollbar was most visible in the appearance panel's narrow column, but it would look equally out of place in any other scrolling region, and there was no existing scrollbar styling anywhere in the app to begin with.
- **Design-language pass, scoped to this component**: `appearance-panel.component.css`'s hardcoded 11/11.5/12/14px font-sizes now reference `--fs-11`/`--fs-12`/`--fs-14`; the new 5-option typeface row uses a new `.ap-chip-grid` (individually-bordered, wraps to two rows) rather than stretching `.ap-toggle`'s seamless-strip pattern past the 2-4 options it was designed for.
- **Stays a side panel, not a popup.** This was a suggestion, not an instruction, and it cuts against the reason ADR-035/I14 put these controls beside the sheet in the first place: a popup covering the sheet defeats "watch the sheet change while you drag the slider." Flagged back to Marty rather than silently implemented either way.

**Consequence**: `AppearanceService.save()` no longer exists — its one caller (`AppearancePanelComponent`) is rewritten against `preview()`/`commit()`/`dirty`. `en.ts`/`ru.ts` gained `common.saved`, `settings.appearance.apply`, and lost `settings.appearance.themePalette` (the "editing the ⟨theme⟩ palette" sentence no longer applies once the buttons are real theme switches). `ng build`/`ng test` clean. Not yet live-verified in a browser.

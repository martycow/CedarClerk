# ADR-092 — Credit wallet: the author pays for paid networks, with prepaid credits (04.08.2026)

**Context**: Marty decided to build the X connector (T-001 → Phase 12), and since 06.02.2026 X has been pay-per-use: ~$0.015 per post, ~$0.20 per post with a link (Cedar Clerk almost always posts with a link to the blog), and under the shared-app model the app owner pays — for every tenant's posts. The cost needs to be shifted onto the author; Marty chose prepaid credits (04.08.2026, three answers: a universal wallet / a ~2× markup / nothing included in the plans).

**Decision: one universal Cedar Clerk credit wallet**, not an "X posts" counter. A credit is the internal currency for anything that costs real external money: right now an X post (1 credit = 1 post = $0.40 against a cost basis of ~$0.20), later other paid networks and AI-quota overage. Packages: **10 = $4, 50 = $18, 100 = $30** (Stars: 200/900/1500 ⭐ calibrated at 1⭐≈$0.02). The Pro/Pro Plus plans do not include credits — the purchase is strictly separate; bonuses can be added later without breaking the model.

**Mechanism — a ledger, not a balance field**: `CreditEntry` (OwnerId, Delta ±, Reason, Ref, CreatedAt), balance = SUM. Positive rows are written by a purchase (Stripe one-time Checkout / Stars invoice — the same flows as the plans, deduplicated by `Payment.ExternalId`), negative rows by a successful publish. **Debit only happens for a successful post**, idempotent on (Reason, Ref=PublishJob) — a queue retry (T-090) does not debit twice. An insufficient balance is a readable refusal in the export window before sending, next to the capability-matrix warnings (T-086).

**Not done by this ADR**: PayPal purchase of packages (will be added following the same pattern, when there's time), refunding credits when a post is deleted (a post on X is already paid for — no refund), and the X connector itself — it will get its own ADR when built (OAuth 2.0 PKCE with refresh-token rotation, character counting with t.co=23, media by bytes).

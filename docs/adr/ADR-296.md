# ADR-296 — Consolidate authentication recovery

ADR-294 and ADR-295 were implemented independently from the same release.
Both branches are retained in the merge history.

The authentication pages use ADR-294's shared branded layout and localization.
One recovery endpoint pair uses the dedicated one-hour Identity token provider,
confirmed password accounts, generic acknowledgements and fragment-based links.
ADR-295's global limits (20 requests and 60 resets per minute) replace per-IP
limits because the loopback tunnel does not provide a distinct client address.
The process-wide 50-message hourly budget remains in place.

Forwarded protocol handling trusts only the framework's default loopback proxies.
Google uses the canonical scheme and returns failed external login to the form.
Telegram mounts own unique callbacks with cleanup and retry feedback.
Recovery pages suppress both analytics initialization and already-loaded clients;
successful resets discard credentials from component memory.

Validation combines both branches' token, eligibility and failure tests with
responsive authentication page checks and the repository's release checks.

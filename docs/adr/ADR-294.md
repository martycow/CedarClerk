# ADR-294 — Branded authentication and email password recovery

The authentication pages use the approved Sly Cedar artwork, a shared paper layout,
and native forms. Login, registration, external completion and password recovery
share this presentation without changing the authenticated application shell.
The logo comes from the owner's corrected `Logo_Horizontal` SVG export; the mark,
lettering and palette are preserved. Paper surfaces use the pine/coral artwork in
both themes.

Password recovery uses Identity password-reset tokens and the existing email
provider. Only confirmed email accounts with a password are eligible. Requests
return the same acknowledgement for unknown and ineligible addresses. Tokens expire
after one hour, are URL-safe, and become invalid after a successful reset. The email
link carries credentials in the fragment, which the recovery page removes from the
address bar after reading; recovery does not emit analytics. Authentication payloads
are excluded from the client debug log. Recovery does not sign users in or remove
an administrative lockout. Both recovery endpoints
have per-IP rate limits; email requests also have a process-wide rate limit.

Provider availability remains a server configuration fact. Google challenges use
the registered authentication scheme's exact name. Telegram keeps the signed
legacy widget protocol and reports script failures with a retry action. Provider
credentials and BotFather domain registration remain deployment configuration.

Validation covers reset tokens, failed and repeated resets, provider scheme
resolution, native form submission, both themes and narrow layouts.

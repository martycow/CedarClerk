# ADR-158 — The chart cannot claim what the data does not say: a derived readout, an unplotted unfinished tail, and named lines

**Context.** `GrowthChart` is the metrics screen's one chart
(`.design-sync/ds-v2/components/bench/GrowthChart.jsx`), and its `prompt.md` states two hard rules
in prose: the marker's rows must equal the series values at that index, and a period must not end
on an unfinished day, because a partial day plots low and reads as a collapse. Prose is not
enforcement — the mirror's own prop shape makes both easy to break. `marker.rows` is a free list of
`{ name, color, value }` supplied independently of `series`, so a readout slip that contradicts the
curve it points at is not an error, it is the default way to call the component. And the tail is not
modelled at all: `points` is a bare array with no statement about whether its last bucket is closed.

A third thing was measured rather than assumed. The app's categorical palette
(`--series-1…6`, `styles.scss`) was run through the dataviz validator against both grounds — day
`--surface` #F1EADA and night `--surface` #D9CEAE, with night's own `--series-3`/`--series-4`
substituted:

| check | day | night |
|---|---|---|
| contrast vs surface (3:1) | PASS, all six | PASS, all six |
| CVD separation, adjacent | **4.3** protan, `--series-4`↔`--series-3` | **4.4** protan, `--series-4`↔`--series-3` |
| normal vision, adjacent | **9.3**, `--series-2`↔`--series-1` | **8.6**, `--series-4`↔`--series-3` |
| CVD separation, all pairs | **3.0** protan, `--series-5`↔`--series-2` | — |
| normal vision, all pairs | **8.8**, `--series-6`↔`--series-4` | — |

The floor for adjacent CVD separation is ΔE 8, and 6–8 is legal only with secondary encoding; the
normal-vision floor is 15. This palette clears neither, and it clears neither for readers with full
colour vision — pine and ink at 9.3 are the two slots the metrics screen uses first. The palette is
not the thing to fix here: it is a house palette, it is what `check-contrast.mjs` already scores,
and it was chosen to be six inks that look like ink on cream rather than six maximally separated
hues. What follows from the numbers is that **colour alone cannot carry identity in this chart**,
and that is a fact about the chart, not a preference.

**Decision.**

1. **The readout is derived, never supplied.** `marker.rows` does not port. The component takes an
   index and reads the values out of `series` itself, so the slip, the crosshair dots and the
   emitted `readout` are one computation. There is no input through which a caller could state a
   number the curve does not draw. The swatch beside each row takes the same slot→token mapping the
   line does, so the slip's colours cannot disagree with the plot either.

2. **The unfinished tail is a required declaration, and an open tail is not plotted.**
   `openTail` is `input.required<boolean>()`: a call site cannot forget to answer, and the component
   has no safe default to fall back on because both answers are wrong for half the callers. When the
   tail is open, its index is excluded from the line, the wash, the end labels, the axis extent, the
   nearest-point hit test and the keyboard traversal — everything that would draw it as a completed
   day. It is **not** dropped: the table alternative still lists it, tagged in progress. The number
   stays visible; the claim that it is a finished day is what goes.

3. **Colour follows the entity, not its position.** A series carries `slot: 1…6`, and the component
   maps that to `var(--series-N)`. Array position paints nothing. Under ADR-149 the sources are
   multi-select filters, so deselecting one reorders the array on every render; index-keyed colour
   would repaint the survivors and a reader who learned that Telegram is pine would be misled by the
   act of filtering. Six is the capacity; a seventh source folds into one row, it does not get a
   generated hue. Two series sharing a slot is a caller defect and says so in dev mode.

4. **Every plotted line is named at its end.** This is the secondary encoding the measurements above
   make mandatory, not a decoration: the name sits in `--t2` beside the line's own end dot, which is
   the coloured mark that carries identity — text never wears the series colour. Labels are pushed
   apart when two lines end close together, and the right gutter is reserved from the longest name
   so a label cannot be clipped by the plot edge. The legend proper is the LeafTag filter strip
   above the chart (ADR-149); the component does not grow a second one.

5. **The ruled ground is `--grid-graph` and the value grid is solid.** The paper's rules are the
   background token, unredefined — a locally-authored `repeating-linear-gradient` would be a surface
   `check-contrast` cannot name, which is the defect ADR-136's grid tokens exist to prevent. Over it
   the value gridlines are drawn as solid hairlines in `--rule-ink`, not the mirror's dashed ones: a
   dashed rule reads as a threshold or a projection when it is only a grid, and the chart already
   spends dashing on two meanings that are real — the previous-period comparison line and the
   hover crosshair.

6. **The wash belongs to a series, not to index 0.** The mirror fills under `series[0]`. Under
   multi-select that fill would jump from one source to another as sources are switched off, which
   is item 3's defect wearing a different hat. `wash` is a per-series flag.

7. **The chart is `data-surface="chrome"`.** It is an instrument, like the ruler bar: mono numerals
   at 11px, ticks, a readout. Declaring paper would be a lie the lint would catch — paper's floor is
   14px type — and the alternative, leaving the sizes in a selector that names no surface, is worse
   than either: `check-density` scores declared values inside `[data-surface="…"]` blocks and
   nothing else, so an unqualified `font-size` is a number no rule ever reads. Chrome is both the
   honest answer and the one that puts the axis type inside a band something measures. Its ground is
   still paper, and the inks on it are the pairs `check-contrast` already scores over `--grid-graph`
   under `--surface`.

8. **Accessibility: the chart is data, so the data is in the DOM.** A visually hidden table carries
   every point of every series, always — not a toggle, not a fallback. The plot is one focus stop
   with a group name, and every point is reachable from it with Arrow/Home/End; the active point is
   announced through a polite live region carrying the same numbers the slip shows. The SVG itself
   is `aria-hidden`, because a second reading of the same numbers in the accessibility tree is
   noise, not redundancy.

**Rejected.** *One focusable element per point* — the honest-looking version of item 8 — is rejected
twice over: at 180 days it is 180 tab stops, and under `@media (pointer: coarse)` every `button` and
`[role="button"]` inside a surface takes `min-width: var(--hit-surface)`, so on a touch device 180
hit columns would demand 30px each and burst the plot. Nearest-point resolution over one surface is
also what the dataviz rule asks for on a dense series. *Making `openTail` optional with a safe
default* was rejected because there is no safe default: defaulting to `true` silently deletes the
last day of a series that was complete, defaulting to `false` is the collapse the rule exists to
prevent, and a caller that has not thought about it should not compile. *Fixing the palette instead
of naming the lines* is out of scope here and probably out of scope entirely — the six inks are
scored, shipped and user-visible, and a chart that needs its lines named is a smaller cost than a
palette that stops looking like ink on cream.

**Consequence.** The right gutter the end labels need is reserved from an estimated mono character
width rather than a measured one, and the names are truncated at twelve characters. The estimate is
deliberate: measuring SVG text means a render pass and a second layout, and a chart that reflows
after it paints is worse than one whose longest label ellipsises. A wash has no token of its own —
it is the series ink at a fixed low opacity — which is the one value here that a future token would
improve.

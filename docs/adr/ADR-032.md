# ADR-032 — Compression-level control, per-draft files list, and profile social links
**Context**: Follow-up feedback after ADR-031's auto-compression fix: Marty wanted to (1) control the compression degree instead of it being fully automatic, (2) see which media files a draft actually references (name/size/location) so they're manageable, and (3) store links to other social profiles in Settings — plus assorted UI polish (mobile topbar overflow, bigger/clearer toolbar icons, blog comment form always stacked, Facebook added to the export mockup row).
**Decision** (19.07.2026):
- **Compression level**: `AssetEndpoints.EnsureTelegramSafeAsync` now takes an explicit `targetMaxBytes` instead of hardcoding `Consts.FileSizes.TelegramSafeImageBytes` — a cached derivative is reused only if it already fits the *requested* budget, otherwise regenerated (so switching levels can't silently reuse a looser-target derivative that's too big for a stricter one, and never wastefully recompresses a derivative that already fits a looser one). New `Consts.FileSizes.TelegramCompressSmallBytes` (2MB) / `TelegramCompressHighBytes` (6MB) sit alongside the existing 4MB "standard" default. `ExportRequest` gained `CompressionLevel` ("small"/"standard"/"high", default "standard"), resolved via `PostEndpoints.ResolveCompressionTargetBytes`. Scoped to the **immediate** `/api/posts/export` path only — scheduled posts (`ScheduledPost`/`PublishDueScheduledPostsJob`) always use the "standard" default, to avoid a second entity/migration for what's a secondary flow; this is a deliberate scope cut, not an oversight.
- **Files list**: new `GET /api/drafts/{id}/assets` (`DraftEndpoints.cs`) returns every `Asset` referenced by the draft's RU content **and** its EN translation if one exists (via `CedarPackage.FindReferencedMediaPaths`, already used for `.cedar`/Markdown import), with size and Telegram-derivative status. Shown in the export modal's new "Files in the draft" list. "Manage" is scoped to **detach, not delete**: `removeAssetFromDraft` walks the live TipTap doc (`state.doc.descendants`) and deletes matching `image`/`video`/`audio` nodes via a ProseMirror transaction (positions processed highest-to-lowest so earlier positions stay valid) — it does not touch the `Asset` row or the file on disk, since no delete-asset endpoint exists and the same upload could in principle be referenced elsewhere; this keeps the action safe/reversible-via-undo rather than a destructive storage operation. Carousel/collage image arrays are not covered by this removal (only top-level media nodes) — a known, accepted v1 limitation.
- **Social links**: five new nullable `ApplicationUser` columns (`SocialTwitterUrl/InstagramUrl/FacebookUrl/YoutubeUrl/GithubUrl`, migration `AddUserSocialLinks`) — plain named columns, matching the existing flat-column convention for profile fields (`AuthorDisplayName` etc.) rather than a JSON blob. Extended the existing `/api/auth/profile` endpoint and `ProfileRequest`/`/me` response rather than adding a new endpoint, since it's the same "save my profile" action. **Purely informational for now** — not wired into any blog/header display; `HeaderSlotType` (which already has a single generic `Url` slot) was deliberately left alone rather than expanded to cover these, since there's no decided design yet for *how* (or whether) these should surface publicly.
- **UI polish**: `.topbar` had zero mobile-specific CSS (confirmed by reading every `@media` rule in `editor.component.css` — only two existed, neither touched `.topbar`), so on narrow screens reaching Settings (behind the last item, the account avatar) required scrolling the whole page sideways. Fixed by hiding purely decorative/duplicated text at the existing 768px breakpoint (`.brand-name`, `.divider`, save-state text, the Export button's text label, the account menu's email text) — every icon stays, nothing becomes unreachable, just denser. `.mini` buttons (import .cedar/Markdown, new draft, refresh chats) grew from 20px→28px with a matching icon bump (14px→16px) and an accent-colored hover state. Blog comment form (`.comment-form` in `BlogEndpoints.cs`'s `ShellTemplate`) now stacks name-above-comment unconditionally instead of only below 480px — the narrow-viewport override that used to do this was folded into the base rule and removed as redundant.
**Consequence**: The compression-level/files-list features add real surface area (a new query endpoint, a document-mutating client action) but no new tables — only `AddUserSocialLinks` is a schema change this round. Cycling status captions (`EXPORT_STATUS_MESSAGES`/`BLOG_STATUS_MESSAGES`, following the existing `TRANSLATE_STATUS_MESSAGES` pattern from auto-translate) were added to the Telegram-publish and blog-publish buttons so a slow operation reads as "still working through a stage" rather than a bare spinner — applied to the two genuinely multi-step async actions in the export flow, not attempted for every async call in the app (asset upload already has real percentage progress; schedule/import already had *some* busy indication and got a minor consistency pass, not a full rebuild).

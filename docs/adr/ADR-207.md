# ADR-207 — A tenant context and a platform context compile to two different models

**Context.** With `OwnerId` as the tenant id (ADR-206), the filter itself is one line per entity:
`HasQueryFilter(e => e.OwnerId == TenantId)`. But some paths legitimately read across owners — the
admin panel, the publish queue, the Quartz jobs, the bot, provider webhooks, startup — and EF offers
two ways to let them through. `IgnoreQueryFilters()` at every such call site is opt-out written 200
times, and one forgotten call is a cross-tenant read. The other is a filter that carries the flag:
`e => platform || e.OwnerId == TenantId`, one model for everybody.

**Decision.** Two models. `TenantModelCacheKeyFactory` keys the compiled model on
`CedarDbContext.IsPlatformModel`, and `ApplyTenantFilters` returns immediately for a platform
context — so the filter is *absent from the query* rather than disabled inside it.

The OR-ed alternative was rejected on what SQLite does with it, not on taste. The flag is a
parameter, so the plan is `WHERE @p0 OR "OwnerId" = @p1`, and a constant-for-the-life-of-the-context
condition the planner cannot see through turns every owner-leading index in the schema into a table
scan — on every query, for every account, to express something that never changes after the first
statement. Two cached models cost one extra compile, once per process.

Deciding late is the dangerous case, so it is refused rather than absorbed. `TenantProvider.IsPlatform`
locks on read: the model has been picked by then, and a caller that opts out afterwards would hold
the filtered model while believing otherwise, and find the rows it came for simply missing.
`UsePlatform()` after that first read throws.

**Consequence.** A platform query is an ordinary query with no tenant predicate in it, and a tenant
query keeps using the indexes the schema was built around. The cost is that the mode is a property
of the *scope*, fixed before its first statement, so a request cannot change its mind halfway — and
the choice has to be made before `UseAuthentication`, because Identity's security-stamp check queries
`AspNetUsers` on every authorized request and that first query is what compiles the model. That is
why `PlatformPaths` is a prefix list read by middleware rather than an attribute on an endpoint.

# ADR-181 — A reading menu is not a tool: the blog's theme and text size share one home (22.08.2026)

**Context.** ADR-179 clause 3 refused the tool's chrome on the blog — no hook rail, no shelves, no
drawer, no tabs — on the ground that *a reader has no commands*. Marty then asked for a pop-up with
font settings, which sounds like the thing that clause forbids and is not.

The distinction the clause was really drawing: a control that acts on **the content** does not exist
for a reader, and a control that changes **how the page is read** already did. The theme toggle has
been in the blog's header since long before this port, it is remembered per browser in
`localStorage['cedar-blog-theme']`, and nobody has ever called it a tool. Text size is the same kind
of thing by the same test.

What settles the shape is `.claude/rules/ui-changes.md` rule 1 — *read before you add; if a panel
for that concern exists, the new control goes there*. There is no panel; there is a lone toggle. Two
sibling buttons for one concern is how the X and Bluesky controls ended up in two homes and had to be
moved (ADR-095), so the toggle becomes the panel rather than gaining a neighbour.

**Decision.**

1. **One `Aa` trigger in the rail opens a *Reading* popover, and the standalone theme toggle is
   gone.** The button keeps the theme toggle's place, its 30px chrome box and its paper face
   (ADR-175). The popover is paper on the wall — the same stock, edge, radius and shadow as every
   other sheet — and it holds two groups, **Тема** (Theme) and **Размер текста** (Text size), nothing else.

2. **Theme gains its third state, which the toggle could not express.** Day, night, and *system*.
   The old control flipped between two values and, once clicked, could never hand the page back to
   `prefers-color-scheme`; the key now stores `light`, `dark` or nothing, and a segmented control can
   show which of the three is in force. This is a fix the popover pays for, not a feature added
   beside it.

3. **Text size scales the reading column and nothing else.** Three steps written on the root as
   `data-read="s|m|l"`, resolving `--fs-read` to 16, 17 and 19px — integers, from the scale, with 17
   the unchanged default. It moves the post body, the excerpt and the gate's intro; it does not move
   chrome, the rule, the leaves or any number, because those are instrument faces at fixed sizes and
   a reader scaling them would break the surface split (ADR-138) from the outside. Persisted in
   `localStorage['cedar-blog-text-size']` and applied by the same pre-paint script that applies the
   theme, so neither setting flashes.

4. **No face picker.** Three reasons, in the order they matter. Literata at `--fs-read`/`--lh-read`
   is a decision the design system made and measured; a picker hands it to someone who has not read
   the pair table. Departure Mono, the face this arrived beside, is bound to an 11px grid (ADR-180
   clause 2) and is not a reading face at 17px — offering it would be offering a broken option. And
   a serif/sans switch is the only honest entry on such a list, which is one row: not enough for a
   control, and a real accessibility need is better served by the reader's own browser, which
   already overrides both.

5. **The header learns the page's language.** `RenderHeader` took a channel and nothing else, so its
   strings could only be English; every one of its nine call sites already has the page language in
   hand. It takes `lang` now, and the popover's four labels join the per-language chrome the gate and
   the back-link already use. A menu that says *Reading* over a Russian post would be the same defect
   `T-094` fixed three times.

**Rejected.** *A size stepper beside the toggle.* Two homes for one concern, and the rule cited above
exists because that has already cost a rebuild once. *Putting the menu in the footer.* The rule is a
readout strip — `RulerBar.prompt.md` says readouts only, and a control on it is the invitation the
prompt refuses. *Line width and line height as further rows.* Both are real preferences and neither
has a measured range here; the column is 760px because that is a measured line length, and widening
it by reader choice would produce lines nobody checked. *Remembering the settings server-side.* The
blog has no reader accounts (`T-004`), and a cookie for a font size is a cookie the privacy page
would have to describe.

**Consequence.** The blog has exactly one reader-facing control surface, and it is honest about what
it contains: two things that change how the page is read, and no way to reach the content. The theme
key keeps its name and its old values, so a browser that already holds `light` or `dark` carries the
setting across this change; only the *absent* value is newly reachable.

ADR-179 clause 3 is unchanged and this decision does not soften it. What the clause refuses is a
command surface; what this adds is the reading preferences a public page has always been allowed to
own — and it now owns them in one place instead of one and a half.

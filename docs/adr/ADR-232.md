# ADR-232 — Feedback is a stored, owner-scoped entity, not an email (31.08.2026)

**Context.** T-191 (a beta gate) asked where bug reports, feature requests and churn reasons land.
The blog's public "Report" control (T-360) is a `mailto:` because the reporter has no account
there. But an in-app reporter is signed in, and triage wants a name attached and a way to mark an
item handled — an inbox, not a mail folder.

**Decision.** A `FeedbackEntry` table, owner-scoped like every other user-owned row (it carries the
tenant query filter). A signed-in account POSTs `/api/feedback` with a coarse kind (bug / idea /
other), a message and the path it was sent from (context for a bug report). Admin reads every
entry under the platform-scoped admin context (`GET /api/admin/feedback`, the reporter's email
joined in) and flips one flag (`HandledAt`) to mark it done. The submit modal is hoisted in the
shell and opened from the tray, so it is reachable from every authenticated screen.

**Consequence.** One table, one migration (`AddFeedbackEntry`), no new infra — deliberately not
email, so the maintainer can list and mark items handled instead of managing an inbox by hand. The
public blog Report stays `mailto:` (T-360): there is no account there to scope a row to. If volume
ever warrants categories, assignment or replies, this is the row they hang off; today it is the
smallest thing that closes the "there is no channel" gap the analysis flagged.

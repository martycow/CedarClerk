# ADR-134 — Public project showcase: a game page on the blog host, opt-in per item (18.08.2026)

**Context.** T-159: every public page advertises the service (the Open Decks lesson), and indies currently assemble a game's public profile from Linktree and Carrd. The blog host already renders public pages with the right visibility rules; the module holds the material (devlogs, tasks, builds).

**Decision.**
1. **`/games/{slug}` on the blog host** — the third routed branch after posts and `/series/`. The page: cover, name, description, store links, the project's devlog feed, and a public roadmap. Server-rendered like everything else on that host.
2. **Publicity is opt-in at every level.** A project is public only when `Project.ShowcaseSlug` is set (null = no page, 404). The devlog feed uses the index's exact visibility filter — `IsBlogPublished && (!IsPrivate || IsListedWhilePrivate)`, locked cards for listed-private — so the new surface makes nothing visible the blog index does not already show (the PRD's "decide private-post behaviour before shipping" rule, decided here). The roadmap shows only tasks the owner ticked (`GameTask.IsPublicRoadmap`), and shows **title and status only** — never the description, which is working material.
3. **Slug is globally unique** across owners (one blog host today, Q-5's tenant domain later) and slugified server-side; the settings dialog suggests one from the project name.
4. **Store links are lines of `Label|URL`** in one text column — a wishlist button is a Steam link with a label, not a mechanism. Structured per-store fields would be a schema commitment to stores we have not researched (T-127).
5. The three columns ride one migration (`AddProjectShowcase`); defaults follow the T-120 rule (declared on the model, not property initialisers).

**Consequence.** Screenshots from the asset index are deliberately absent: `AssetEntry` rows are fingerprints of files on someone's machine, not servable bytes — the honest image sources are the cover and the published posts' own media. The "Published via Cedar Clerk" footer the showcase feeds traffic to is the blog shell's existing attribution; nothing new. Archiving a project hides its page (404), same as unpublishing.

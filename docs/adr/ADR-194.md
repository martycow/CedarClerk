# ADR-194 — The tool wall follows the active project context

**Context.** The rail currently presents the remembered Project on every authenticated route and
keeps account-wide destinations beside Project-specific ones. The result is misleading on Settings
and incomplete inside a Project: Planner and Builds are only reachable through the Project hub,
while Admin is hidden in the overflow tray and the account popover repeats it.

**Decision.**

1. The Project switcher is shown only where Project context changes the work: the Project hub and
   its child screens, Documents, the writer, the Project asset index, and Metrics. Account surfaces
   such as Settings, Admin, Glossary, and the global media library carry no Project tile.
2. Before a Project is selected, the wall offers Hub plus account destinations only. Project tools
   appear after a Project is selected and point at that Project: Documents, Board, Planner, Builds,
   Assets, and Metrics.
3. Planner and Builds become first-class hooks. Admin becomes a hook for an administrator. The wall
   may scroll vertically when the contextual set exceeds the original seven-hook guideline; hiding
   a frequent Project destination behind the hub is a higher cost than the longer wall.
4. The account popover contains Profile and Log out only. Admin belongs to navigation, not identity.
5. The remembered Project remains session state. This decision changes where that state is exposed,
   not how it is persisted or validated.

**Consequence.** ADR-183's overflow tray remains the home of theme, Appearance, Glossary, and
developer tools, but no longer Admin. ADR-186's remembered Project remains, while its rule that the
tile appears on every screen is superseded. The UI never suggests that Settings depends on a Project,
and every Project workflow is reachable without returning to the hub.

# ADR-206 — The tenant is the account: `OwnerId` is the tenant id, and there is no `TenantId` column

**Context.** Every table in the schema already carried `OwnerId`, a string key into `AspNetUsers`,
because the app was built as one operator's tool that happened to have accounts. Giving each account
its own public blog at `name.cedarclerk.app` needs a tenant, and the textbook move is a `Tenant`
table plus a `TenantId` column beside every `OwnerId` — two identities for the same thing, a join to
get from either to the other, and a migration that rewrites 27 tables to introduce a column whose
value would be a function of one that is already there.

**Decision.** The tenant *is* the `ApplicationUser`. `OwnerId` is the tenant id; the filters read it
directly and no second column exists.

- **The account gains a name, not an id.** `ApplicationUser.TenantUsername` holds a DNS label —
  a–z, 0–9, inner hyphens, at most 63 characters — under a unique index filtered on `NOT NULL`, so
  the accounts that predate it stay legal. The name is deliberately not called `Username`: Identity
  owns `UserName` (which holds the email here), and EF's differ matched the two case-insensitively
  and generated a rename that would have emptied every account's login identity.
- **One set of rules for two callers.** `Core/Usernames` decides what a name may be, and both the
  Host-header resolver and registration ask it, so a name that can be typed as a subdomain is
  exactly a name that can be registered. `Consts.ReservedSubdomains` holds the labels the platform
  keeps (`www`, `api`, `admin`, `blog`, mail and DNS names, …). Registration now requires a name
  rather than accepting one, and the filtered unique index — not the availability check — is the
  guarantee: two registrations racing for one label both pass the check, and the loser is answered
  from the `DbUpdateException`.
- **Eleven child tables gained an owner of their own.** `Comment`, `Reaction`, `PollVote`,
  `PostInvite`, `PostRegistration`, `DraftTranslation`, `DraftRevision`, `DraftStatSnapshot`,
  `DraftTargetText`, `ChannelPost` and `ChannelStatSnapshot` used to belong to a draft or a channel
  and to nothing else. Every endpoint reaches them by parent id rather than through the parent's
  navigation, so a filter on the parent would never have run — the column is denormalised and
  indexed, and the migration backfills it from the parent.
- **Uniqueness that used to be global is per owner.** `IX_Drafts_OwnerId_BlogSlug` and
  `IX_Projects_OwnerId_ShowcaseSlug` replace the single-column indexes. Two accounts can both
  publish `/hello-world`, which is the whole point of giving each one a host.

**Consequence.** Whose row this is can be read off the row, at every level, without a join — which
is what makes a query filter cheap enough to put on 34 entities. The costs are real and accepted.
An account and a tenant can no longer be told apart, so a team or an organisation owning one blog
between several logins is a decision this one would have to be reopened for. And a name is written
once: there is no rename endpoint anywhere in the server, and adding one would have to answer for
every published URL that carries the name, plus the host→owner cache of ADR-212, which invalidates
by expiry alone.

# ADR-126 — Словарь событий метрик: контракт до провайдера аналитики (18.08.2026)

**Context.** T-153 (аналитика) упирается в выбор провайдера (Plausible/Umami/GA4 — влияет на `/privacy`), но словаря продуктовых событий не существует нигде, и это отдельная беда: первый день подключённой аналитики соберёт не те события, а «задним числом не добирается» — принцип, уже записанный на самих сущностях-снапшотах (`DraftStatSnapshot`, `BlogViewGeoDaily`: «History starts the day this ships»). Четыре метрики `docs/product/BUSINESS.md` §4 сегодня считаются кто как: три по базе, активация — наполовину. Паника «каждый день без словаря = потеря данных» преувеличена — регистрация закрыта, воронки нет; но словарь обязан существовать **до** T-153 (T-193).

**Decision.**
1. **`docs/product/METRICS.md` — единственный источник истины по событиям и метрикам**: что уже пишется в базу (и какой сущностью), чего не пишется (и потому не минабельно задним числом), и как каждая из четырёх метрик §4 выводится из имеющегося. BUSINESS §4 остаётся владельцем списка «какие метрики важны»; METRICS отвечает на «как именно они считаются».
2. **Имена событий — стабильный контракт.** Провайдер из T-153 только транспортирует события с этими именами; смена провайдера не меняет словарь. Имена — `snake_case`, объект действия первым: `signup_completed`, `draft_created`, `post_published_first`.
3. **Активация выводима задним числом уже сейчас** — без явного события: join `AspNetUsers.CreatedAt` × min(`PublishJob.FinishedAt` со `Status=Succeeded`, `Draft.BlogPublishedAt`) по владельцу. `PublishJob` — полный append-only лог публикаций без retention, `BlogPublishedAt` — first-publish семантика; поэтому «first publish» минабелен за всю историю, и событие `post_published_first` в провайдере — оптимизация, а не спасение данных.
4. **No-cookie позиция фиксируется до выбора провайдера**: собственная блог-статистика уже работает без кук (`VisitorHash` с солью, ADR-016; `BlogViewGeoDaily` — агрегат, не трейл), и провайдер обязан её не ухудшить — вариант с баннером согласия принимается только осознанным решением Марти, не дефолтом.

**Consequence.** Подключение провайдера (T-153) начинается с маппинга словаря, а не с придумывания событий; события «нет в базе» (воронка регистрации, feature-usage) начнут существовать только с момента подключения — METRICS.md честно помечает их неминабельными. Файл обязан обновляться в том же коммите, что добавляет или переименовывает событие.

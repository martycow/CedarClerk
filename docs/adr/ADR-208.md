# ADR-208 — An unset tenant reads nothing, and reading across owners has to be said out loud

**Context.** A filter is only as good as its default. Whatever `TenantProvider` answers when nobody
told it who the request is for decides what a forgotten call site does — and the code has plenty of
places where nobody tells it: a Quartz job, the bot's update loop, a webhook, startup, an AI job
that outlives the request that started it.

**Decision.** Three states, and the default is the strict one.

- **Unset — the filters answer "nothing".** `TenantId` is null, `OwnerId == null` matches no row,
  and the path that forgot to say who it is for gets an empty list. The opposite default — unset
  meaning "no filter" — turns the same mistake into a silent cross-tenant read, which nobody
  notices, ever. An empty list is a bug report.
- **`UseTenant(id)` — an ordinary request**, filled in from the resolved subdomain, from the blog
  host's owner, or from the signed-in user's claim, in that order.
- **`UsePlatform()` — a path that legitimately spans owners**, which has to declare itself. In an
  HTTP request that declaration is the `PlatformPaths` prefix list (`/api/admin`, the Stripe and
  PayPal callbacks, the local import bypass) — the gate as data, in one file, rather than as a habit
  spread across the endpoint files. Off the request thread it is `CreatePlatformScope()`, which
  opens the scope and says what it is for in one call, so a background path cannot get half of it
  right. A plain `CreateScope` gets the strict default and reads nothing.

**Writes are held to the same rule.** `SaveChanges` refuses an added entity whose `OwnerId` is empty
in a scope with no tenant to take one from. A row saved with an empty owner matches no tenant
afterwards, so it would be written successfully and then be invisible to everyone including the
account that wrote it — a loud refusal at insert time beats a row nobody can find.

**Consequence.** Every leak-shaped mistake in this design fails closed: it produces missing data,
not somebody else's. The price is paid by the background paths, which now have to name their intent,
and by the one class of bug this creates — a job that quietly processes nothing because its scope was
opened the ordinary way. `TenantScopes` exists so that mistake is hard to make, and `UsePlatform()`
throwing after the first query (ADR-207) is what keeps it from being made late instead.

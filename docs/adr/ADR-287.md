# ADR-287 — View transitions: the router cross-fades except around the editor, the blog carries a cover into the post (05.09.2026)

**Context.** T-185. Two surfaces, two mechanisms. The SPA switches routes with a hard cut;
Angular's router has shipped `withViewTransitions()` since 17, and the one screen whose DOM is
not Angular's to snapshot is the editor (TipTap owns it). The blog is server-rendered pages, so
its transition has to be the cross-document kind, and the one thing worth animating there is
the cover on the index becoming the first picture of the post.

**Decision.**

*SPA.* `withViewTransitions({ skipInitialTransition: true, onViewTransitionCreated })` on the
router. The callback calls `transition.skipTransition()` when either end of the navigation
carries `data: { viewTransition: false }` — the editor route does — or when
`prefers-reduced-motion: reduce` matches. Either end, because leaving the editor snapshots the
editor too. The route data flag is the whole opt-out surface; the predicate
(`skipViewTransition` in `app.config.ts`) is exported and tested.

*Blog.* `ShellTemplate` declares `@view-transition { navigation: auto }` with 180 ms for the root
cross-fade and 280 ms on the `post-cover` group. The index names the clicked card's cover
`post-cover` from a click handler — a plain click only, and `pageshow` clears every name again,
because a bfcache return would otherwise leave two covers with one name and the browser would
skip the transition. The post names its first `img[src*="/media/"]` inside `article.post-sheet`
from a script placed right after the article (`HeroTransitionScript`), so the name is on the
element before the footer parses. Reduced motion sets `navigation: none` and stills every
transition pseudo-element. Firefox has no cross-document transitions and simply navigates.

**Rejected.** *Naming the hero from the renderer* — `CedarToBlogHtmlRenderer` is Core and does
not know which image the card chose; the selector reproduces `CedarImageRefs.LocalFileName`'s
`/media/` rule instead. *Keeping the name on the card for the back navigation* — a nicer
morph, at the price of the two-covers case above; the row asked for removal on `pageshow`.
*Blog motion tokens* — the blog's token contract is colours only, and the blog's own
transitions are already written in milliseconds; the values are the app's `--motion-base`,
`--motion-slow` and `--ease` written out. *`<link rel="expect" blocking="render">`* — the
correct fix if a very long post ever paints before the hero script runs; not needed for the
sizes posts have.

**Consequence.** Every SPA navigation but the editor's cross-fades; a route that fights it opts
out with one data flag. `BlogViewTransitionTests` holds both halves of the blog side present, since
either one missing degrades silently to a plain navigation.

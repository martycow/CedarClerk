# ADR-252 — Rust operations console with configurable programs

## Decision

Replace the Spectre.Console .NET CLI and its test project with `cedar-cli`, a Rust binary named `cedar` using Ratatui and Crossterm. This supersedes the implementation choices in ADR-118 and ADR-119; `cedar` remains the entry point for build, test and deploy.

The console prioritizes deploy, local tests and serving the published artifact. A versioned JSON configuration contains named programs, working directories, command actions and optional SSH deployment settings. Actions run explicit executables and argument arrays. Interactive actions temporarily release the dashboard and inherit the terminal. New programs and actions require configuration, not recompilation. Cedar Clerk is the bundled first profile.

The terminal dashboard has a selectable program, actions, command output, elapsed time, cancellation and confirmation dialogs. Its animated title uses a cedar, forest layers, aurora and particles. Reduced motion and narrow terminal layouts remain usable. Non-interactive commands have stable exit codes, help and dry-run output.

## Deployment invariants

- Preserve branch and clean-tree checks, version validation, SSH-agent authentication, resumable checksummed archives, staging before downtime, rollback and health/version verification.
- Ask immediately before swapping production directories, defaulting to no. A failed upload cannot stop the service. Update local LIVE/LIVE-PREV tags only after verified health.
- Keep deploy data outside the replaced application directory. Desktop downloads publish the manifest last.
- Dry-run launches no process, makes no network request and writes no file.
- Validate managed local output paths before clearing them. Reject symlink traversal and unsafe remote roots.
- Local Cedar Clerk runs bind loopback, retain the development data directory, force the `LocalNoBot` environment and disable the Telegram bot with `Cedar__Telegram__BotToken`. The server treats whitespace as an absent token before creating a Telegram client. Cancellation terminates only children owned by this invocation.

## Configuration and installation

Use `--config`, then a discovered repository `cedar.json`, then the user configuration under the platform configuration directory. Relative paths resolve against the configuration directory. Read the previous single-program JSON format as a Cedar Clerk profile; migration is explicit and preserves the old file.

`Scripts/install-cli.ps1` builds and verifies the Rust release before replacing the installed .NET tool. The Rust executable installs into the existing per-user command directory. Source recovery is `cargo run --manifest-path cedar-cli/Cargo.toml -- <command>`.

## Verification

Rust tests cover configuration, command planning, dry-run, process failures, cancellation, deployment scripts and terminal rendering at multiple sizes. Exercise the real terminal interaction and the repository's build/test entry points. Deployment transport and rollback are tested without changing production; live deployment requires its own operator request.

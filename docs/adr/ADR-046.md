# ADR-046 — Posts Manager: one page, existing screens demoted to tab bodies
**Context**: Brainstorm v2 item N7 — comments, likes, statistics and private-post form management move onto a new "Posts Manager" page with four sections: post management (pick a post, make minimal edits), reactions & comments, statistics, forms. Two of those sections already existed as full top-level pages (`/comments`, `/stats`), each with its own header, theme toggle and back link.
**Decision** (26.07.2026):
- **New `/posts` route** (`posts-manager.component`). `CommentsComponent` and `StatsComponent` are **reused as child components, not copied** — their page chrome (header, logo, theme toggle, back link, `avatarInitial()`, and the now-unused `AuthService`/`ThemeService` injections) was deleted outright rather than hidden behind an `embedded` flag, because after this change there is exactly one owner of that chrome and a flag would imply a second caller that doesn't exist.
- **`/comments` and `/stats` stay as redirects** to `/posts` — they're what existing bookmarks and any pasted link point at. The editor's account popover drops its two separate entries for one "Posts Manager" link.
- **"Minimal edits" is deliberately metadata-only**: title, tags, folder, private toggle, archive/unarchive, delete, plus links out to the blog post, the Telegram post and the editor. Body text stays the editor's job. Note the rename path has to `GET` the draft and hand its `cedarJson` back untouched, because `PUT /api/drafts/{id}` replaces title and body together — a metadata screen must not be able to blank a post.
- **The forms tab is read-only in this step**: it lists private posts and their submissions (`GET /api/drafts/{id}/registrations`). Editing the form, per-question breakdowns and the answer-distribution pie chart are N10; presets are N12. Submissions can only honestly render "answer key → value" today, since `AnswersJson` is keyed by question id and the labels live in the form definition (ADR-042) — resolving them properly is part of N10.
- **Strings are English, not Russian.** The page is new, so it could have gone onto `t()` (ADR-044) directly; it didn't, because the surrounding screens it absorbs (`/stats`, comments) are still untranslated English, and a Russian-only new page would look broken to any account whose UI language is English. It joins the pending localization pass as one more screen instead of becoming a third state.
**Consequence**: `/posts` duplicates the base page-chrome CSS (header, avatar, buttons) the same way every other page in this app does — component styles aren't shared here, `drafts.component.css` carries the identical block. Extracting a shared chrome component would be a real improvement and is not part of this change. No backend work was needed: every action on the page uses endpoints that already existed. Not yet live-verified in a browser as of writing.

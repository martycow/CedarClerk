# ADR-143 — Fonts stay self-hosted; the mirror's Google @import is not ported

**Context.** `.design-sync/ds-v2/tokens/fonts.css` is three lines: a comment naming the four faces — Vollkorn (display), Source Sans 3 (UI), Literata (long-form), Caveat (notes) — and one `@import url('https://fonts.googleapis.com/css2?…')` pulling them from Google. The app already ships all four self-hosted: sixteen `@use '@fontsource/…'` lines at `cedarclerk-web/src/styles/_forest.scss:7-22`, one file per weight per named subset (latin, cyrillic), against `@fontsource` 5.3 in `cedarclerk-web/package.json:27-30`. Bench moves the type tokens onto the bare `:root`, so the question is whether the mirror's font file travels with them.

**Decision.**
1. **The sixteen `@fontsource` imports survive the partial and move into `cedarclerk-web/src/styles.scss` unchanged; `tokens/fonts.css` is not ported at all.** ADR-136 deletes `_forest.scss`; this is where its font block lands and what it costs once it is no longer scoped to a skin nobody has switched on. The subset list stays explicit — latin and cyrillic, per weight — because it is the thing that keeps the payload bounded, and a whole-family import is exactly what it was chosen against.
2. **The shipped set is deliberately smaller than what the `@import` asks for.** Self-hosted today: Vollkorn 600/700, Source Sans 3 400/600/700, Literata 400/600, Caveat 500 — 16 woff2, 323 028 bytes. The `@import` additionally requests Vollkorn 500 and 500 italic, Source Sans 3 500 and 400 italic, Literata 500 and 400 italic, and Caveat 600; across the same two subsets that is 299 124 bytes, and it is a floor rather than a total, since Google serves latin-ext, cyrillic-ext, greek and vietnamese by `unicode-range` on top. The mirror's own CSS declares `font-weight` 400, 600 and 700 and nothing else, and it declares no `font-style` but `normal` — `italic` survives in it only as the name of an editor-toolbar glyph (`assets/bench-icons.js:41`, `ui_kits/writer.html:150`) and inside the `@import` URL. Roughly 292 KB buying nothing any kit draws.
3. **One origin.** Everything the browser fetches comes from `cedarclerk.mooexe.dev` through the Cloudflare Tunnel; Kestrel listens on loopback and the droplet exposes only SSH. An `@import` inside the stylesheet puts two third-party hosts on the critical path *and* makes them serial — the font CSS is not discoverable until `styles.scss` is parsed, the woff2 not until that CSS is. Four faces are the entire type system now, so a slow or blocked `fonts.googleapis.com` renders every screen in the fallback stack. It also hands the visitor's IP to Google on every public blog and landing hit, which is an answer the product would rather not owe once registration opens.
4. **The desktop shell is not one of the reasons, and should not be cited as one.** `CedarClerk.Desktop/main.js:48` sets `UPSTREAM = 'https://cedarclerk.mooexe.dev'` and `main.js:420` loads it; there is no local copy of the SPA and no offline fallback. With no network there is no app, so "the shell must work offline" does not hold. Point 3 is the argument; this point exists so nobody re-derives the wrong one.

**Consequence.** Three costs, taken knowingly. **No real italic ships.** The editor exposes an italic mark (`cedarclerk-web/src/app/core/toolbar-layout.ts:28`) and `CedarClerk.Core/CedarToBlogHtmlRenderer.cs:655-656` emits `<em>`, so author emphasis renders as a browser-synthesised oblique. Two italic faces would close it for about 100 KB; revisit by measuring how much emphasis real posts carry, not by taste. **Every visitor now pays for the faces.** Under the skin they were referenced only by scoped rules, so the default look downloaded zero font bytes; with one look, most of those 323 028 bytes are on the ordinary path. **The server-rendered surfaces name a face they do not serve.** `font-sans`/`font-serif`/`font-mono` are on the generator's `WANTED` list (`cedarclerk-web/tools/generate-design-tokens.mjs:20`), reach `CedarClerk.Core/DesignTokens.generated.cs:33-35`, and are consumed by `CedarClerk.Server/BlogEndpoints.cs:1846` and `LandingEndpoints.cs:131` — but `@fontsource` puts its `@font-face` rules in the Angular bundle only. Once the bare `:root` says `'Source Sans 3'`, the blog and landing will ask for it and fall through to the stack while the app draws the real face: the two surfaces diverge in type the way they once diverged in colour, which is the failure ADR-071 principle 6 and the generator exist to prevent. Fixing it is not a pasted `@font-face` — the build content-hashes the files (`publish/wwwroot/media/caveat-latin-500-normal-XNJ4DF4N.woff2`), so a hand-written URL dies at the next build. It is left open on purpose, and it is the one thing the Google `@import` would have solved in a single line.

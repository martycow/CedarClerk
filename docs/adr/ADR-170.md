# ADR-170 — Dead is measured, not remembered: what nothing matches goes, what one template uses stays

**Context.** `T-230` was written to delete the control CSS the bench components replaced, and it
carried a count taken before any page was ported: `.btn-accent` in twelve stylesheets, `.btn-ghost`
in sixteen, `.btn-danger` in two, `.icon-btn` in seven, `.status-badge` in five, tab strips in
eight. Five stages of porting later that count describes a tree that no longer exists, and a bulk
deletion driven by it would delete rules that are still painting.

Re-measured against the tree, by whole-token search over `cedarclerk-web/src`, `e2e`, `tools` and
`CedarClerk.Server`: `.btn-accent` is defined in six page stylesheets and `.btn-ghost` in eight,
every one of them matched by its own template; `.status-badge` survives in one; the hand-rolled tab
strips are down to `.picker-tabs` in the media picker, the rest being `app-index-tabs` with a page
class for margin; `.btn-danger` has no definition and no use anywhere; and `.icon-btn` has neither,
except for a single fragment of one global selector.

Two facts about the tree decide what that measurement is worth. Angular's emulated encapsulation
scopes a component stylesheet to the template that declares the markup — projected content keeps the
declaring component's scope, so a rule in one component sheet cannot reach another's — and nothing
in the app sets `data-skin`, so every rule in `styles/_forest.scss` matches nothing whatever its
selector says. A class is therefore dead when it is absent from its own template, and only then.

**Decision.**

1. **`.icon-btn` is gone, and the last thing spelling it goes too.** The class survives nowhere in
   the app: not in a template, not in a component sheet, not in a spec, not in the server's markup.
   What was left is `a.icon-btn` inside the global coarse-pointer selector in `styles.scss` — the
   one hook by which an anchor could ever claim the touch floor, standing over no anchor. This
   **amends ADR-169 clause 5**, which read the rule as reaching `[data-surface] button`,
   `[role="button"]`, `summary`, `select` and `a.icon-btn`: the list is now four, and an anchor
   control gets its floor from the page that draws it or from `.btn`, which declares its own. The
   fragment was not coverage, it was the appearance of coverage, and the two page rules ADR-169 had
   to add exist because it never matched.

2. **`.btn-danger` is closed by measurement, not by deletion.** It has no definition to remove. The
   styleguide's own spec already forbids it from coming back on that page; nothing forbids it
   elsewhere, and nothing needs to, because no page has a danger button that is not `.btn-ghost
   danger`.

3. **A rule one template still uses is not dead CSS, however many copies of it exist.** The six
   `.btn-accent` and eight `.btn-ghost` blocks are duplicates of each other and each is live. They
   are modal footers, and a modal footer is the markup the bench does not yet cover: `app-button`
   draws the buttons, but the dialogs around them also want a select, a textarea and a checkbox the
   kit never drew (`T-252`). Collapsing the copies before that exists would mean inventing a
   fourteenth global control class, which is the thing the port was for ending. They stay, counted
   and named, until the components that replace them exist.

4. **The landing page's copies are not duplication of this kind.** `LandingEndpoints.cs` spells
   `.btn-accent` and `.btn-ghost` in a stylesheet it serves itself, for markup it renders itself.
   The server-rendered surfaces are a second style system fed from the same tokens, by design; a
   bench component cannot reach them, so there is nothing here to collapse into one.

5. **A string with no reader is deleted with the code that stopped reading it.** Four keys defined
   in both dictionaries — `editor.state.watermarked`, `projects.noDocumentsOfType`,
   `projects.assetsLink`, `projects.planner.endsOn` — are referenced by nothing. Every dynamic
   lookup in the app indexes a nested map (`docTypes[…]`, `status[…]`, `kindOne[…]`), never the
   objects these four sit directly in, so no reference can be hiding behind a computed key. The
   pseudo-locale walks the dictionary by shape and needs no entry to exist.

6. **A class attribute with no rule is a defect, not a deletion.** Four shared components —
   `folder-picker`, `series-picker`, `tag-picker`, `glossary-term-form` — put `.btn-ghost` and
   `.btn-accent` on real buttons whose own stylesheets define neither, and no global sheet does. The
   CSS was deleted during the port; the markup was not converted with it, so eight modal buttons are
   drawn by the browser today. Stripping the class would remove the only record of what those
   buttons are supposed to be; converting them is a port, and it touches the markup a sibling
   rebinding of the smoke suite is reading. It is filed (`T-262`), not quietly tidied.

**Rejected.** *Trusting the plan's counts*, which is how a live rule gets deleted. *Deleting a rule
because five other files declare the same one* — sameness is the argument for a component, not for
removal, and removal without one leaves the control unpainted, which is exactly what clause 6 found
already done to eight buttons. *Deleting the dead class attributes in clause 6 on their own*, which
would turn a visible defect into an invisible one. *Keeping `a.icon-btn` as an escape hatch for some
future anchor control*, which is a selector kept for a call site that does not exist; ADR-169
clause 5 already settled that such a control declares its own floor.

**Consequence.** The bulk deletion `T-230` was written as turns out to be one selector fragment and
four strings, and the reason is that the porting stages did the work as they went. What is left
under the name is a decision about modals rather than a cleanup, and it is stated as such on the
board. Anyone re-running the measurement should note the two facts it rests on: component sheets are
scoped to their own template, and `data-skin` is set by nothing — if either changes, every "dead"
answer here has to be taken again.

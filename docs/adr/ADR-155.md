# ADR-155 — The tally: a badge for the hook rail, which the kit does not define

**Context.** Before the bench shell, two places carried the same control on the Posts link —
`page-header.component.html` and the editor topbar — each an `app-count-badge` reading
`feedback.newComments() + feedback.newReactions()`. Both were retired with the header. The rail that
replaced them has no badge: `HookRailItem` carries an icon, a caption, a title, a link and a tail
flag, and `bench-shell.component.ts` did not inject `CommentsService` at all. The only badge left in
the app is inside `posts-manager.component.html`, on the tab strip of the screen the count points at
— it tells you there is new feedback once you have already arrived.

Verified in Chromium before the fix: on `/drafts`, with `/api/comments/new-count` answering three
new items, the rail drew six hooks, zero badges, and never issued the request. `editor.component.ts`
still called `refreshNewCount()`, so on that one screen the number was fetched and rendered nowhere.

**The kit gives us nothing here.** `.design-sync/ds-v2/components/bench/HookRail.prompt.md` describes
the wall, the five-to-seven-tool budget and the 30px floor, and stops. `HookRail.d.ts` has no badge
field and `HookRail.jsx` renders none. Nothing else in the system carries a count either: `StampBadge`
says what STATE a thing is in and is explicitly not a quantity, `LeafTag` is a lifecycle, `TaskTag` is
a task. **This is our extension, not something the kit specifies**, and it is written down here for
that reason.

**Decision.** `HookRailItem` gains `badge` and `badgeTitle`, and the rail draws a **tally**: a work
ticket hung on the tool's own peg, notched over its top-right corner.

1. **A tag, not a dot.** A workshop says a station has work waiting by hanging a ticket on it — the
   wall already speaks in hardware (brass hooks, sign tiles, a brass bar for "you are here"), and a
   red notification dot would be the one thing on it borrowed from a phone. The tally is a small
   rectangle at `--radius-stamp`, the shape every other stamped thing in the app takes; the workshop
   has no pills, so the old badge's `999px` radius does not come across.
2. **It hangs where a ticket hangs.** Top-right of the tool, riding up into the gap the brass hook
   occupies and overlapping the tool's top edge, so it reads as pegged to the same hook rather than
   floating over the icon. It paints in front of the hook, because a ticket hangs in front of the
   hardware it hangs on.
3. **One badge across the chrome.** Ground `--tab-badge`, ink `--rail-edge`, `--font-mono` at
   `--text-chrome-sm` — byte for byte the pair `IndexTabs` already uses, so a count looks like the
   same object wherever chrome carries one. Deliberately not `--accent`: `appearance.service.ts`
   injects that from the user's preset, and a signal that something needs attention should not change
   colour because someone picked a different accent.
4. **The two counter rules come from the one function.** `indexTabBadgeLabel` — nothing at zero or
   below, `99+` past ninety-nine — is called by both the tabs and the rail rather than copied a third
   time. T-231 folds `app-count-badge` into the same rule.
5. **The number stays in the accessible name.** An `aria-label` on a badge replaces its text, so
   `badgeTitle` alone would leave the link reading "Metrics, new comments and reactions" with the
   count gone. The label is the count and the title together: "Metrics 3 New comments and
   reactions". This binds both consumers of the pair, not the tally alone — an `app-index-tabs`
   tile labelled by its title alone is announced "Checks unresolved checks" over a visible
   "Checks 2", which is the same failure on the component the tally borrowed the badge from.
6. **The shell asks for the number.** `BenchShellComponent` refreshes the count on construction. The
   count used to be fetched by whichever screen happened to open, which is why landing on `/drafts`
   showed nothing over unread comments. A global signal has to be fetched globally.

**Consequences.** The tally is not a control and declares no `min-height`; chrome's 30px floor is a
floor for things you press, and `tools/check-density.mjs` measures `min-*` only, so this is a
deliberate absence rather than an exemption. At `99+` the tag is 28px wide on a 44px tool and covers
the brass hook and the top corner of the icon — the caption and `aria-current` still name the tool,
and the case needs a hundred unread items to reach. The rail's CSS test no longer asserts that every
inked rule takes `--rail-ink`; it asserts that every ink matches the ground under it, with an ink
required for each ground. Both forms score the same three inked rules, so the strengthening is in
the question and not in the count: a ground with no measured ink fails here, which the old form
could not ask at all. What it gives up is this one pair, and this one pair is scored by
`tools/check-contrast.mjs` as `--rail-edge` on `--tab-badge` over each of the three grounds it
overhangs.

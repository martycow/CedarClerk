# ADR-327 — Desktop provider sign-in runs in the system browser and returns by a one-time code

**Status**: DEVELOPED
**Session**: BR-004
**Supersedes**: none. Narrows the "Electron does not handle authentication at all" line of ADR-117.

## Context

A Google or Discord sign-in started in the desktop window cannot finish (`T-442`). The challenge sets its correlation cookie in the window's cookie jar; the provider's next navigation is off-origin, so `will-navigate` hands a mid-flow URL to the system browser; the callback arrives there without the cookie. Keeping the provider's pages in the window is not available: Google refuses embedded browsers, and the navigation block is what keeps a window with disk access from becoming a general browser (ADR-117). The shell and the system browser share no cookies, so a session made in one has to be carried to the other.

## Decision

A provider sign-in from the desktop shell happens entirely in the system browser, and the session is handed to the shell by a one-time code over a `cedarclerk://` link.

1. The shell generates a random verifier, keeps it in memory, and opens the browser on the ordinary provider challenge with `returnUrl=/auth/desktop?challenge=<SHA-256 of the verifier>`. The page cannot name the address: the bridge takes a provider name and a return path only.
2. Everything ADR-237 defines — the invite gate, linking by password, onboarding — runs in the browser unchanged and ends on `/auth/desktop`, behind `authGuard`.
3. `/auth/desktop` names the signed-in account and asks for one click. The click calls `POST /api/auth/desktop/code`, which needs a session and returns a code bound to that account and that challenge. The page then opens `cedarclerk://auth?code=…`.
4. The shell posts the code and the verifier to `POST /api/auth/desktop/redeem` as a navigation of its own window, so the session cookie lands in the window's jar, and the server redirects to the return path.

Rules the code is held to:

- **A code is single-use, lives two minutes, and is worthless without the verifier.** Another application can register the same scheme; it receives a code it cannot redeem. A wrong verifier burns the code.
- **One live code per account.** Asking again replaces the previous one.
- **Codes live in process memory, not in the database.** One process serves production; a restart inside the two minutes fails one handoff, and the person presses the button again. No migration, nothing to clean up.
- **Redeem requires the `X-Cedar-Desktop` header.** The endpoint is anonymous and creates a session. A web page can post a form to it but cannot add a header to a navigation, so nobody can be signed into an attacker's account by a link. `SameSite=Lax` does not cover this case, because no cookie is involved.
- **The click on `/auth/desktop` is consent, not decoration.** Without it, any link to that page would mint a code for whoever is signed in.
- **The shell acts on a link only while a sign-in it started is pending** (ten minutes), and takes a single-instance lock so the link reaches the running copy on Windows and Linux.

Password sign-in stays in the window. Telegram sign-in is not changed by this ADR.

## Consequences

- Google and Discord sign-in work from the desktop app, with the browser's own Google session and passkeys.
- The shell now takes part in authentication: one bridge function, one protocol handler, one request. `docs/tech/DESKTOP.md` and `docs/tech/SECURITY.md` say so.
- Two clicks follow the provider's own screen: the consent button and the browser's "open the app?" prompt.
- The browser ends up signed in too. That is the ordinary result of signing in there.
- The scheme is registered only for a packaged build. `npm start` cannot receive the link, so the handoff is not testable from a development run.
- Linux AppImage registers the scheme only where the desktop integrates AppImages; elsewhere the password form is the way in.
- Needs both a server deploy and a new desktop build. A shell older than this ADR has no `signIn` on its bridge, and the page falls back to the in-window navigation that fails as before.

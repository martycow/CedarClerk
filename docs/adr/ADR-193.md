# ADR-193 — ADR-192 follow-up: no site-wide language toggle, English by default, pagination, dropdown sort (23.08.2026)

**Context.** Marty used ADR-192's shipped blog for a session and reported nine things back. Most are
plain bugs or polish (tag chip height, copy-link placement, post width) with no decision behind them
to record. Four are real reversals of ADR-192 clauses, made with reasons attached, so they get an
entry rather than a silent diff:

- The site-wide RU/EN cookie toggle (ADR-192 clause 2) was reported as *not working* — pressing EN on
  a post switched it, pressing RU on the same post did nothing, yet the top-bar RU worked. The
  mechanism was doing what it was built to do (an explicit `?lang=` always won over the cookie, and
  the in-post RU pill, when RU was already the primary language, linked to the canonical `/slug` with
  no `?lang=` at all — a no-op by design, not a bug). Put back to Marty as "fix the sync" vs. "remove
  the toggle, index defaults to English, a post keeps its own language set" — he chose removal outright
  rather than a fix, which is simpler code besides.
- Search (ADR-192 clause 3's other half) was reported as not finding an actual word from the last
  post's body — correct, because it only ever matched title and tags, never body text, and that scope
  was never stated where a reader could see it. Rather than build real full-text search (a bigger
  feature with its own indexing questions), it is removed.
- The plain "newest/oldest" sort link is asked to become a dropdown covering order, popularity, and
  "posts available in language X" — a real feature addition, not a fix.
- Rendering every published post on one page was flagged as a lag risk once a blog has more than a
  handful of entries; pagination did not exist as a question before this.

**Decision.**

1. **`LangToggleHtml`, the `cedar_blog_lang` cookie, and `RenderHeader`'s `ctx` parameter are all
   removed.** The index renders in English, unconditionally (`const string indexLang =
   Languages.English`) — not as a fallback chain, a fixed choice. `RenderPostAsync`'s own `?lang=`
   handling reverts to exactly what ADR-181/ADR-065 already had: an explicit query string only, no
   cookie fallback. The per-post `.lang-switch-track` — which already worked, was never the reported
   bug, and is exactly the "each post may have their own set of languages" Marty asked to keep — is
   untouched.

2. **The index shows an English preview when a post has one.** For each card, one batched
   `DraftTranslations` lookup (keyed by post id, filtered to `Language == "en"` — no N+1) supplies the
   title and body a translation exists for; a post whose primary language already is English, or that
   has no English translation, renders exactly as before (`ArticleTitle ?? Title`, primary
   `CedarJson`). This is the same substitution `RenderPostAsync` already makes for an explicit
   `?lang=`, applied to the index's fixed English instead of a per-request query value.

3. **Pagination: 10 posts, "Show 10 more."** `?shown=N` (default 10, only ever read upward) slices the
   already-filtered, already-sorted list before rendering; the tag bar and the sort/language dropdown
   still compute over the *full* set, so neither undercounts while the cards themselves are capped.
   Changing any filter (tag, sort, language) drops `shown` back to its default — a narrower or
   reordered list starts from its own top rather than the previous scroll position's page count. A
   plain link, not client-side JS revealing pre-rendered DOM: the HTML this page sends is only ever as
   big as what the reader has asked to see, which is the actual fix for the lag report (rendering
   fewer post-card partials, not hiding already-rendered ones).

4. **Search is deleted outright** — `.index-search`, the `q` query parameter, `BlogIcons.Search` — no
   replacement. `IndexFilterUrl` drops its `q` parameter (tags/sort/avail/shown only).

5. **The sort control becomes a dropdown**, reusing the reading menu's exact open/close mechanism
   (button + `hidden` popover, click-outside and Escape both close it) as an independent instance
   (`#sortBtn`/`#sortMenu`) rather than a shared helper — two call sites is not enough to justify
   generalizing a dozen lines of vanilla JS that already appears once. Two sections: **Order** (newest
   / oldest / most popular / least popular, by `ViewCount` for the latter two — the metric the card
   already shows) and **Language** (all / each language actually in use across posts, `?avail=`,
   matching a post whose primary language or any translation is that code). The month-heading spine on
   the index only draws under "newest/oldest first" — under a popularity sort consecutive cards are not
   chronologically adjacent, and a month heading there would claim an order the list is not in.

6. **Three unrelated fixes, bundled here because they landed in the same pass, not because they are
   one decision:**
   - Tag chip height drops from the 44px paper touch-floor to a 28px minimum with tighter padding — a
     leaf is read in passing, not aimed at, and the standalone-control minimum read as too tall next to
     its own text.
   - The copy-link button moves from the bottom of the post (`.post-footer-row`, beside the Telegram
     link) to the top (`.post-meta-row`, beside the date/views) — a reader who wants the link rarely
     wants to scroll for it first.
   - The post reader gets its own, wider `.site-main` variant (`site-main--post`, 820px vs. the
     product's 760px measured line length everywhere else) via a new optional `mainClass` parameter on
     `PageShell` — it was reading as mobile-width on a desktop screen.

**Rejected.** *Fixing the language-toggle sync bug instead of removing the toggle.* Offered; Marty chose
removal. *Real full-text search (indexing post bodies).* A bigger feature than "the search box is
broken" calls for on its own; revisit if a reader-facing need for it shows up again. *A shared JS helper
for the reading menu and the sort dropdown's identical open/close logic.* Two instances, not a pattern
worth abstracting yet — matches how the rest of this file's dozen-plus independent IIFEs already work.
*Widening `.site-main` globally instead of only for posts.* The index's measured 760px line length
(ADR-179) was never the complaint; only the post reader was.

**Consequence.** ADR-192 clause 2 (the site-wide toggle) is fully superseded and its code deleted, not
just deprecated — nothing references `Consts.General.BlogLangCookieName` any more, and the constant is
gone with it. ADR-192 clause 3's search half is gone the same way; its sort half survives as the
dropdown's "Order" section, extended rather than replaced. The index now issues one extra batched query
per request (English previews) and reads a bit less per request than before (`Take(shown)` instead of
the full filtered set) — a wash or a net win depending on how many posts a given install has, which is
exactly the lag complaint this was meant to address.

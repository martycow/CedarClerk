# ADR-314 — The emoji modal keeps its hand-picked Favorites and adds the full Unicode set, self-hosted

Resolves issue #8 ("Emoji list too small").

## Context

The editor's emoji modal offered 149 hand-picked emoji (`CedarClerk.Localization/Web/emoji.ts`) plus flag sequences Unicode never encoded. That is a deliberate shortlist, but authors write about things the shortlist does not hold, and typing an emoji from the OS picker is not an option on every device.

Research for this issue (07.10.2026):

- Telegram renders emoji with its own set, so what an emoji looks like **in the post** is decided by the reader's client, not by Cedar Clerk. What Cedar Clerk decides is which codepoints the author can pick.
- Emoji 17.0 is on iOS/macOS 26.4 and Samsung One UI 8.5, rolling out on Windows 11 from 28.08.2026, and on Pixel 11 only. A newest-version emoji can show as a box for part of the audience; the picker therefore hides emoji the *author's* browser cannot draw (its built-in check), which is the same test the reader's device would fail more often, not less.
- Windows Chrome and Edge draw no flag emoji (two letters instead). The existing grid works around this by printing the ISO code under each flag.
- Custom emoji in channels need a Fragment username, and Premium-owner custom emoji (Bot API 9.4) work only in private chats and groups. They are out of scope.

## Decision

1. **Keep the Favorites grid as the default view.** It is the 149-entry set with English and Russian search and the flag sequences; nothing about it changes.
2. **Add "All emoji".** A link under the grid swaps it for `emoji-picker-element`: the full Unicode set with search, skin tones, "frequently used" and category tabs. It reports a glyph and the editor inserts it through the same `insertEmoji` as the grid.
3. **Lazy.** The picker, the flag polyfill and the data are `import()`ed or fetched on first open of "All emoji"; nobody else pays for them.
4. **Self-hosted.** The data files (English `emojibase`, Russian `cldr-native`) and the flag font are copied by `angular.json` asset globs to `assets/emoji/<lang>/data.json` and `assets/fonts/`. The libraries' defaults point at a CDN; a writing tool should not call out to one. Any UI language other than ru gets the English set.
5. **Flags on Windows.** `country-flag-emoji-polyfill` adds a flags-only font when, and only when, the browser draws emoji but not flags. It is applied in the app only; **the public blog is not covered** (a reader on Windows Chrome still sees letters). Tracked as T-431.
6. **No version cap.** The idea of capping the picker at an older Emoji version was dropped: the library's own render check already hides what this browser cannot draw.

## Consequences

Two small packages and one font join the front-end dependencies (`STACK.md`); the build output grows by about 1 MB of lazily fetched assets and nothing in the main bundle. Colours come from the app tokens, so the picker follows the light/dark theme and the accent. The modal's width (360 px) is unchanged. Emoji newer than the readers' devices can still reach Telegram; that is the reader's platform lag and cannot be fixed here.

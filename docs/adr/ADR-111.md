# ADR-111 — Sprint state is derived from dates, the number is stored (11.08.2026)

**Context**: T-124, the planner. ADR-106 already decided a sprint is a separate entity with its own dates and name. Two questions came up during implementation that that ADR didn't touch.

**Decision 1: a sprint has no "status" column — "current / planned / completed" is computed from the dates.** A stored status diverges from reality the very second the clock crosses `EndsAt`, and from then on needs something to fix it: a background job, a check on read, a "close sprint" button. All of that is machinery serving a copy of a fact that's already recorded in two dates. A sprint is "current" if today falls inside `[StartsAt, EndsAt]`; if several qualify, the one that started later is considered current (overlaps aren't forbidden: a ban wouldn't protect anything, it would just get in the way when dates shift).

A direct consequence: **a sprint has no "overdue" state.** Tasks inside it are overdue, and the UI says exactly that — "1 overdue" — rather than coloring the whole sprint. This is the same rule already in force on the board: only a date turns red, never a card or a column.

**Decision 2: `Sprint.Number` is a sequential number within the project, assigned at creation and never reused.** The design shows an `S14` chip on a task card and a "Sprint 14 — Ferry Terminal" line on the dashboard, meaning the number and the name are different things: the number answers "which one," the name answers "about what." The alternative — extracting the number from the name with a regex — breaks on the very first sprint named "Polish."

The number isn't reused after deletion: a gap in the numbering is more honest than a second `S7` meaning a different stretch of time.

**Decision 3: deleting a sprint unlinks tasks, it doesn't delete them.** The same rule as deleting a project: deleting the container is not a request to delete the contents. Tasks return to "No sprint."

**Nothing to verify here, but worth stating**: "completed" here means "the time period ended," not "everything is done." A sprint with open tasks still ends on the calendar — and the planner shows those tasks rather than hiding them. Hiding them would mean lying that the work vanished along with the date.

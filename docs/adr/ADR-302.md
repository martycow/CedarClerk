# ADR-302 — Database command logs are warnings by default

## Context

Production storage exhaustion blocks Draft translation creation and AI result persistence.
SQLite can automatically roll back a transaction after `SQLITE_FULL`; a subsequent rollback
can then report `cannot rollback - no transaction is active`, hiding the storage failure.
Successful EF Core commands inherit the application's `Information` level and emit SQL for
every query. Application logs pass through the host's journal and syslog.

## Decision

Set `Logging:LogLevel:Microsoft.EntityFrameworkCore.Database.Command` to `Warning` in the
shared application configuration. Failed commands and warnings remain visible. Other
application categories retain their existing levels. Operators may temporarily override
the command category to `Information` for a bounded investigation.

Host log retention must have a size limit as well as time-based rotation. Recovering an
already-full host requires a separate operator action; changing the application log level
does not reclaim existing files. Preserve a recent diagnostic sample before clearing a
log, and do not remove database, media, backups or the previous application release.

## Verification

Check the configured category and run the backend suite. After host recovery, verify free
space, database integrity and creation of an empty language version before retrying AI
translation. An HTTP health response alone does not establish database write readiness.

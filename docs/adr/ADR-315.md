# ADR-315 — "Send preview to me" replaces the test-channel send

Resolves issue #4 in part. Amends the "Preview = send to test channel" line of `.claude/rules/telegram-bot.md` §5 for the editor UI.

## Context

Issue #4 asked for scheduled posts to be sent as Telegram *scheduled messages*. The Bot API has no scheduling parameter on `sendRichMessage` (or any send method), so a scheduled message cannot be created by a bot; Cedar Clerk's own queue (Quartz) stays the scheduler. What the author actually needs from that request is to **see the real thing on a real phone before it goes out**.

The Preview footer already had "Send test to @testingandfun" for that, but it had two problems:

- It went through the real `POST /api/posts/export`, so a test also stamped `LastTelegram*` and wrote a `ChannelPost`: the draft looked published, and the Posts Manager showed it live.
- It existed only for the maintainer, whose account has that channel connected.

The maintainer decided on 07.10.2026: **replace** it.

## Decision

1. **New endpoint** `POST /api/posts/{id}/preview-to-me` (`{ language? }`). It builds the message with the same `TelegramPublishTarget.BuildContentAsync` as a real send — signature, blog link, hashtags, CTA buttons, media by `file_id` — and sends it with `SendRichMessage` to the author's `TelegramUserId`, i.e. their private chat with the bot.
2. **It records nothing.** `SendPreviewAsync` writes no `LastTelegram*`, no `ChannelPost`, no pin, no revision and no `PublishTarget` row (the target it passes is never added to the context).
3. **Errors are explicit.** No linked Telegram account → 409 `PreviewNeedsTelegram`. A user who never pressed Start in the bot (Telegram answers 403, or 400 "chat not found") → 409 `PreviewBotNotStarted`. Both are in every `ErrorMessages.*` table.
4. **UI.** The button "Send preview to me" takes the old button's place in the Preview footer and appears when a Telegram account is linked. The `@testingandfun` lookup (`testChannel()`) is deleted. The result is a toast, as before.
5. **No stickers.** A rich message has no sticker block, so nothing is added for them. Offered separately as an optional follow-up (a `sendSticker` after the post in the same chat); not built.
6. **Scheduling stays ours.** Telegram's native scheduled messages remain unavailable to bots; if the Bot API gains a `schedule_date`, this is revisited.

## Consequences

A preview can no longer mark a draft as published, and every author, not only the maintainer, gets a real-device check. It sends a real message, so the bot must be running (one long-poller per token still applies; a send does not conflict, `telegram-bot.md` §1). A developer who wants to preview into `@testingandfun` still can via the Export modal; the editor no longer offers a shortcut to it.

# ADR-167 — The reading screens: an index shelf, one sheet, and the facts on the inspector — and feedback stays under its post

**Context.** `docs/design/UI-V2-PLAN.md` §3 groups `posts-manager`, `glossary` and `comments` as
*writer-like*: the writer's shape — a list to pick from, one object lying on the lit top, and a shelf
describing that object — is the shape all three want. ADR-159 built that shape for the editor and left
the pattern behind it: a page publishes its rail contribution as data, the meta strip becomes the
inspector, and the inspector obeys `SpecRow.prompt.md` — *it shows the selected object, and falls back
to the document when nothing is selected, never both at once*.

None of the three had been touched beyond the deletion of `page-header`. The Posts Manager still
carried a hand-rolled tab strip, two bordered `div`s standing in for a list and a detail card, and its
own single-metric SVG line chart written before `GrowthChart` existed. The glossary carried a chip row,
a second tab strip, a term list and a preview modal. `comments` is not a screen at all: N7 folded it
into the manager, `/comments` has been a redirect since (`app.routes.ts:121`), and the only place it
renders is `posts-manager.component.html`, scoped to the selected post.

The plan's line for the third one — *"comments (a fragment → drawer tab, never its own screen)"* — was
written before ADR-153 spent the drawer on the request journal, and before it was checked what the
fragment actually is.

**Decision.**

1. **The manager's tab strip is `IndexTabs`, and the feedback tally is its badge.** `IndexTabs.prompt.md`
   gives the component exactly this jurisdiction — it switches what a panel shows and never navigates —
   which is what `.manager-tabs` was doing by hand. The `app-count-badge` that hung off the Posts tile
   goes with it: `indexTabBadgeLabel` already carries the hide-at-zero and `99+` rules that component
   exists for, so this page stops being one of `T-231`'s call sites rather than acquiring a second badge.
   The element keeps `class="manager-tabs"` so the strip is still addressable by the name the smoke
   suite binds.

2. **The manager publishes no primary action to the rail.** ADR-148 clause 4 refuses a rail button that
   changes with the selected tab, and every command this screen has belongs to one tab: *New form* to the
   presets list, *Open in editor* and *Delete* to one post. The list commands go into their
   `ShelfPanel`'s `[actions]` slot, which is where `ShelfPanel.prompt.md` puts a panel's own commands.
   The rule takes the screen-level counts, which do not change with the tab.

3. **The posts tab is an index shelf, one sheet and an inspector — and what the inspector states leaves
   the sheet.** The left shelf is the post index (search plus cards, `flush` so the rows rule to the
   panel's edge); the worktop carries the selected post; the right shelf carries that post's facts as
   `SpecRow`s. The *Where it went* group is deleted from the sheet rather than duplicated: its blog,
   Telegram and elsewhere links are facts about the post and now live in rows, and the two things in it
   that were commands rather than facts — editing the slug and unpublishing — stay on the sheet under a
   heading that says so. Same for the folder picker, which moves into a row exactly as ADR-159 clause 8
   moved the editor's three pickers. `.claude/rules/ui-changes.md` rule 1 is the whole argument: one
   control, one home.

4. **The inspector's fallback subject is the library, and the scope is exclusive.** `inspectorScope()`
   returns `'selection'` when a post is picked and `'document'` when none is, every `app-spec-row` in the
   panel carries the matching `scope`, and the template switches on it — so a mixed sheet is assertable
   rather than a convention. `SpecScope` is reused unchanged: the selected post is the selection, the
   whole library is the document.

5. **The forms tab gets the index shelf and the sheet, and no inspector.** A preset has no second
   subject to describe: an empty third column would assert that one exists. This is the same refusal as
   ADR-159 clause 6 — a row that cannot be filled is not drawn.

6. **The per-post growth chart becomes `GrowthChart`, and its metric buttons become the legend.** The
   page's own `historyChart()` built two SVG paths for one metric at a time inside a fixed `600x160`
   viewBox with no axis, no readout and no table alternative. `GrowthChart` draws all three nightly
   series at once on their fixed palette slots, and the three metric buttons become the `LeafTag` strip
   that filters them — ADR-149's shape, one line per metric and never a sum. `openTail` is `false`:
   every snapshot is a running total read at a moment, so no bucket is left unfinished. Nothing new is
   fetched; the same `statHistory` response feeds it.

7. **The glossary's languages are `IndexTabs` and its scopes are `LeafTag`s.** The two strips did
   different jobs with the same chip: the language row picks which set of terms the list shows, which is
   an index tab; the scope row filters that set and doubles as *where a new term goes*, which is a
   legend-as-filter. *New term* is the screen's one primary action and goes to the rail; *Translate all*
   acts on the language currently indexed and stays beside the tabs.

8. **The glossary's preview modal becomes the inspector.** The preview is the blog's tooltip shown as a
   reader meets it, with the term's translation group as a switcher — a description of the selected
   object, which is what the right shelf is for. Rendering it as a window over the list was the meta
   strip's mistake at a smaller scale: reading matter behind a dismissible layer. The group switcher
   becomes the `LeafTag` row ADR-159 clause 7 made of the editor's language tabs, the term's own
   properties become `SpecRow`s, and with nothing picked the shelf describes the glossary itself. The
   shelf carries no commands: edit, translate and delete act on one row and stay on the row they act
   on, which is also what stops the modal's *Edit* button from becoming a second home for the pencil.

9. **`comments` is not moved into the drawer, and this is the entry that says why.** Three facts the
   plan's line predates. The drawer is mounted once by the shell and carries the request journal
   (ADR-153); a Feedback tab on it would hang on every screen in the app, including the four that have
   no post. The fragment is scoped by `onlyDraftId` to the post selected in the manager, so a
   shell-level drawer would need a global "current post" holder — chrome reaching into a page's
   selection, the inversion ADR-159 clause 1 exists to stop. And ADR-046 clause 4 deliberately put
   feedback *under the post it belongs to*; the drawer would take it back out. The half of the plan's
   line that matters — *never its own screen* — has held since N7 and is unchanged: `/comments` stays a
   redirect, nothing links to it, and no notification path names it. What the fragment gets here is the
   port it never had: the page chrome left in its stylesheet from the screen it stopped being is
   deleted, and it inherits paper's numbers from the sheet it now sits on.

10. **The manager drops `data-density="compact"`; the glossary never had it.** ADR-164 rule 6 keeps
   the knob on the four screens that are tables you scan. Under this port the manager is not one: its
   list is a shelf and its detail is a sheet on the worktop, which is a screen you read — the hub's
   reason, in ADR-160's words. The surface split governs the chrome inside it either way, and the two
   vocabularies do not meet.

**What was rejected.** *A rail action per tab.* ADR-148 clause 4, verbatim. *Keeping the destinations
group and adding the links to the inspector.* Two homes for one link. *A third shelf on the forms tab,
listing the preset's questions.* The sheet already is that list; a shelf mirroring it is a second index
of one thing. *Deleting the unscoped branch of `comments`.* It costs nothing, it is what makes the
component whole on its own, and removing a working mode is not a re-skin. *Replacing the manager's
`<details>` groups with a second `IndexTabs`.* The groups are open at once by design and their open set
is remembered per browser; tabs would make that state unrepresentable.

**Consequence.** The manager now measures nine `SpecRow`s it did not have, and the sheet is shorter by a
group. A post whose only interesting property is a URL is now read on the right without opening
anything, which is the affordance the *Where it went* group was and never fitted on a card.

The reading screens claim nothing the API does not answer. The manager's inspector has no row for reach,
retention or a per-post channel, because `BlogStatSnapshot` is the only per-post series that exists.
`GrowthChart`'s `events` input is left empty: a publish date is on the draft, but a nightly snapshot
series has no index to hang it on without a lookup nobody wrote. The glossary's inspector shows no
"used in N posts" count — the term-to-post match happens in the blog renderer at render time and is
never stored, so the number does not exist to be shown. Each is a board row, not a blank.

Two smoke-suite selectors move with this: `.manager-tabs button` keeps working because the class is kept
on the `app-index-tabs` element, and `.post-card` / `.post-search` are kept byte-identical for the same
reason `input.title` was in ADR-159. The glossary's preview modal is gone, and nothing in the suite
bound it.

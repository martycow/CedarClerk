# ADR-290 — Project layouts respond to their available width

## Context

The iPad sidebar leaves less room than viewport breakpoints assume. The Project hub
compresses its document title, filters and journal. Showcase columns exceed the
work area. Empty task columns consume the entire screen height.

## Decision

- Use named inline-size containers for the Project hub, Showcase builder and task board.
- Stack hub content when the remaining width cannot hold a readable document area
  and sidebar. Wrap filters, journal entries and destination addresses within their cards.
- Keep three Showcase columns only when all three remain usable. Use two columns
  with the inspector below at medium widths, and a single column at narrow widths.
- Fit four task statuses at tablet landscape widths. Narrower boards retain one
  horizontal scroller. Empty columns use compact messages within bounded columns.
- Preserve the sidebar, data, navigation, typography and touch target sizes.

## Verification

Check 1024x768, 1180x820 and 1366x1024 landscape viewports and 820x1180 portrait.
Enable touch input and check both interface languages. Verify populated and empty
states, reachable controls, and that horizontal scrolling stays inside the task board.
Browser emulation does not establish physical iPad or Safari acceptance.

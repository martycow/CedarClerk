# ADR-148 — Metrics stays a tab: the kit is adapted to the app here, not the app to the kit

**Context.** All three reference screens treat metrics as a screen of its own. `.design-sync/ds-v2/ui_kits/stats.html` gives it a breadcrumb (`Cedar Quest / Метрики`), its own lit hook on the rail (`«Метрики»`, `:101`), a `RulerBar`, and a rail-level primary action — `Выгрузить CSV` sitting where every other kit puts the screen's one main command. That is the full dress of a destination.

The app deliberately took it away. ADR-046 folded `/stats` and `/comments` into a new `/posts` Posts Manager with four sections, deleted their page chrome outright rather than hiding it behind an `embedded` flag, and left `/stats` and `/comments` as redirects for existing bookmarks (`app.routes.ts:113-114`). `StatsComponent` is still a real component (`pages/stats.component.*`) and still says so in its own first line — `<!--N7: tab body inside the Posts Manager — the page header moved there.-->` — and the manager renders it at `posts-manager.component.html:419`.

Half of ADR-046's reasoning dissolves under this port and must not be leaned on. Its argument was that two top-level pages each carried a header, a theme toggle and a back link, and that one owner of that chrome is better than three. The bench shell supplies chrome to every route for free (ADR-139), so under Stage 3 a route costs no chrome at all. Whatever keeps metrics a tab has to be a different reason.

**Decision.** This is Marty's answer to Q-19, in his words: «Остаётся вкладкой» — metrics stays a tab body inside the Posts Manager, and the kit is adapted to the app.

1. **No hook for metrics, no crumb for metrics.** The rail crumb names the Posts Manager and stops there; the tab strip inside it names the tab, which is what a tab strip is for. Adding a crumb segment for a signal that is not in the URL would make the breadcrumb say something the address bar cannot.

2. **The surviving reason is subject, not chrome.** Posts, metrics, feedback and forms are one object seen four ways — ADR-046's own fourth clause moved reactions and comments *under the post they belong to* rather than keeping them as a section, on exactly this argument. "How did this post do" and "which posts are there" are one question asked twice, and a route boundary between them puts a page load in the middle of it.

3. **The hook the rail spends here is the Posts Manager, not Metrics.** ADR-139 clause 4 listed the sixth hook as "Metrics (`/posts`)" because the kit calls it that; with metrics a tab, the hook's label would name one of four tab bodies and land on a different one. The hook takes the manager's own name and icon. *This rename is the implementer's, derived from Marty's answer — he was asked whether metrics is a route, not what the hook is called.*

4. **The kit's rail-level CSV action moves down into the chart panel's header.** ADR-139 clause 3 puts a panel's own commands in its `ShelfPanel` header and reserves the rail for the whole screen's one primary action; a rail button that changes with the selected tab makes the rail a tab-dependent surface, which is the placement rule inverted. Export belongs to the thing being exported. (It also does not exist — there is no CSV path anywhere in the repository; building it is `T-222`'s own work, not part of a re-skin.)

**What was rejected.** *Restoring `/stats` as a route because the shell makes it cheap.* True and not sufficient: it would re-split a subject that was deliberately joined, and it spends one of the rail's 5–7 hooks against ten destinations to do it. *A seventh hook, so both the manager and metrics get one.* ADR-139 left two hooks unspent on purpose because the budget is a legibility limit rather than a quota — spending one to give a tab strip a second entrance is precisely the second home for one control that `.claude/rules/ui-changes.md` rule 1 exists to stop. *Keeping the metrics crumb without the route*, so the kit's breadcrumb still renders: a breadcrumb that cannot be linked to or navigated back through is a label wearing a crumb's costume.

**Consequence.** The stats kit is the one reference screen that is not portable as drawn, and every future reading of it has to remember that: its rail row, its crumb and its top-level export button describe a screen this app does not have. `T-222` ports the *body* of that kit — the multi-series chart, the leaf-tag filter strip, the audience shelf — into a tab, and the chrome around it belongs to the Posts Manager.

One affordance the kit had is missing and is cheap to restore: the manager already accepts a `?tab=` deep link (`posts-manager.component.ts:145`), but `/stats` redirects to a bare `posts` and drops the tab, so an old bookmark to the metrics page lands on the posts list. Pointing that redirect at the stats tab gives the kit's linkability back without a route. *That is an implementation note for `T-222`, not part of Marty's answer.*

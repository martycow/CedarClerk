# ADR-180 — Departure Mono is the readout face, and it is bound to its 11px grid (22.08.2026)

**Context.** Marty asked for Departure Mono. It is a monospaced *pixel* font by Helena Zhang, SIL
OFL, v1.500 — 1,186 glyphs, and the copy in this repo was read rather than trusted: its `cmap`
carries А, я, Ё, ё, Ж, щ, №, the em dash and the middle dot, so the product's first-class Cyrillic
requirement is met in the file and not only in the release notes. One weight, one 22 KB woff2 for
every script it covers, which is small enough that no subsetting and no `unicode-range` split is
needed — and therefore none of ADR-178 clause 3's shadowing hazard applies.

Its README states the constraint that decides this entry: **"For pixel-perfect results, set the font
size to increments of 11px."** A pixel font off its grid does not look stylish, it looks broken —
the strokes go soft and uneven, and a reader reads it as a rendering fault rather than as a choice.

That was measured against the codebase before anything was decided. Of the 53 rules that pair
`font-family: var(--font-mono)` with a font size, **11 sit at 11px** (`--text-chrome-sm`, `--fs-11`)
and the rest sit at 12, 13, 14, 15, 18 and 21 — `--fs-ui` alone accounts for twenty. Replacing
`--font-mono` outright would put the face off its grid in roughly four call sites out of five, and
putting it *back* on the grid would mean moving the app's mono typography to 11 and 22, which breaks
ADR-138's surface split (chrome 11–13, paper ≥14) at both ends.

**Decision.**

1. **Departure Mono enters as `--font-readout`, a new named role beside `--font-mono`, and never
   replaces it.** `--font-mono` keeps its system stack — `ui-monospace, Menlo, Consolas, monospace`
   — and keeps every call site that is not 11px. The system stack is what a code block wants: at
   13px in a post body the reader needs a coding face, not a texture.

2. **`--font-readout` may be used only where the declared size is 11px** (or an exact multiple).
   This is the whole of its contract, and it is what makes the role nameable: a readout is a small
   number read off an instrument, and that is precisely the size band the design system already puts
   such numbers in. The call sites, enumerated because the rule is only checkable against a list:
   the carpenter's rule and its numerals, the chart's readout slip, the drawer's journal summary,
   the version on the rail, and the three counters (index tab, hook, shelf panel). On the blog: the
   footer rule, comment timestamps, the language stamp and the comment anchor.

   Three things a size test alone would have swept in are deliberately **not** on that list.
   `Input`'s chrome field is 11px mono and is a thing you *type into*: a value being edited is not a
   reading. `.path` and `.tile-name` in the assets screens are 11px mono because, as their own
   comment says, machine text is compared character by character — which a pixel face makes harder,
   not easier. And the chart's axis and end labels carry no size of their own; they inherit whatever
   the page hands the SVG, and a pixel face at an unknown size is precisely what this clause
   refuses. Giving the axis an explicit 11px so it could qualify is a change to the chart, not to
   the font, and belongs to whoever makes it.

3. **`--text-readout` is not moved to 22px to make the big metric on-grid, and this clause is the
   refusal.** 21px is the kit's own number (ADR-138 clause on `--fs-21`), the prototype is the law
   for this port, and buying one pixel-perfect numeral with a deviation from the prototype is the
   wrong trade. The large readout stays `--font-mono` at 21px. If it should ever be Departure, the
   kit changes first.

4. **The file is committed, and that is not a contradiction of ADR-178.** That decision refused to
   commit woff2 because `@fontsource` already owned the files and a copy in git would fall behind
   the package. Departure Mono has no package — the official distribution is a zip on a GitHub
   release — so there is nothing to fall behind, and a build step that downloads a font from the
   internet is a worse dependency than a 22 KB file in the tree. It lives at
   `cedarclerk-web/public/assets/fonts/departure-mono-1.500.woff2`, version in the name so a bump is
   visible in a diff, with the OFL text beside it as the licence requires. `public/` is copied
   verbatim into the build output, so the app and the blog resolve the same URL.

5. **Both surfaces declare it the way each already declares a face.** The app gets an `@font-face`
   in `styles.scss` beside the `@fontsource` imports; the server gets one in
   `DesignTokens.FontFaces` (ADR-178). `--font-readout` joins `MATERIALS` (ADR-177) so the blog can
   name it. No `unicode-range`: one file covers every script, so there is no second rule to shadow.

**Rejected.** *Making it `--font-mono` product-wide.* Costed above: four call sites in five off the
grid, or a typography rewrite that breaks the density contract. *Blog only.* It splits the two
surfaces again — the exact failure ADR-071 principle 6 and the generator exist to prevent, and the
one this branch just finished repairing. *Offering it as a reader-selectable body face.* A pixel
font at 17px with a 1.75 leading is not a reading face; see ADR-181 clause 4. *Subsetting it.* 22 KB
whole is smaller than most subsets of the other four, and a subset would have to be re-cut on every
version bump.

**Consequence.** The product has a fifth face, which ADR-143 did not anticipate when it said four
were the entire type system — that sentence is amended here and nowhere else. The face is confined
to a size band by a rule a reader of the CSS can check: if a declaration names `--font-readout` and
its size is not 11px, it is wrong. Nothing enforces that automatically today; `check-density.mjs`
scores sizes by surface and does not know about faces, and teaching it this rule is a board row
rather than a part of this decision.

The lo-fi voice is now audible in the one place the merge always meant it to be — the instrument
readings on the bench — and stays out of the reading column, which is Literata's.

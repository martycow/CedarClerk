# ADR-284 — Server errors speak every UI language, from one table per language keyed by member name (T-194)

**Context** (05.09.2026). T-050 put the server's error sentences into `ErrorMessages` and had each
member choose between two literals: `Ru("Черновик не найден.", "Draft not found.")`. That shape
was honest about what existed — Russian and English — and the closing comment said so. Two things
had drifted since. The endpoint files had grown **56 interpolated `$"…"` answers** in fourteen files
(plus a ternary of two plain literals in `ChannelEndpoints`) that the localisation guard could not
see, because it only matched `error = "`: every one of them answered in English regardless of the
reader. And `Languages.UiLanguages` names nine languages while the messages knew one translation;
seven UI languages fell back to English by design, which was the right call for a month and a
wrong one for a product about to open registration.

A ninth positional argument to `Ru` is not a mechanism. Nine literals in one call cannot be read,
a language cannot be added without touching every member, and a missing translation is a missing
argument the compiler insists on — so somebody pastes English into the slot and the fallback the
design promised becomes a lie nobody can find.

**Decision.**

1. **The English text is the member; every other language is a table keyed by the member's name.**
   `public static string DraftNotFound => T("Draft not found.");` — `T` reads its own caller's
   name (`[CallerMemberName]`) and looks it up in the table for `CurrentUICulture`'s language.
   Each language is one partial-class file, `ErrorMessages.ru.cs`, `.de.cs`, `.fr.cs`, `.es.cs`,
   `.ja.cs`, `.uk.cs`, `.be.cs`, `.ka.cs`, holding
   `[nameof(DraftNotFound)] = "Черновик не найден."`. The key is `nameof`, so a renamed member
   breaks the build in eight files rather than silently going English in eight languages.
   English is never a table: there is nothing to keep in sync with itself.

2. **A parameterised message is a format string, and its arguments travel as one array.**
   `T("At most {0} buttons", [max])`. The array is the point, not a style: with an `object?`
   parameter beside the `[CallerMemberName]` string, `T("…{0}", name)` would compile and bind
   `name` to `key` — the message would be looked up under the wrong name and answer in English.
   A collection expression cannot bind to a string, so the mistake is unwritable. Formatting uses
   `CurrentUICulture`, because the sentence around a date is in that language.

3. **Missing means English, and the test says nothing is missing.** `Translated(key)` returns null
   for a language or a key it does not hold and the member answers with its English. That is the
   behaviour for a language the app does not know and for the first minute after a member is
   added; `ErrorMessageLocalizationTests` is what stops the second case from lasting longer. It
   enumerates every public member by reflection and, for each of the eight translated languages,
   fails when a row is missing, names no member, drops an argument, or when the member invoked
   under that culture does not answer in the row's shape — the last check is what catches a table
   that exists but was never wired in, or an argument that landed in the key.

4. **The guard now sees interpolation.** `No_endpoint_answers_with_a_hardcoded_english_string`
   matches `error = $"` as well as `error = "`; the 56 call sites it would have caught are the
   34 new members at the end of `ErrorMessages.cs`. One member per meaning, not per call site:
   five endpoints that said "File is too large (NMB maximum)" with five different constants share
   `FileTooLarge(maxMb)`, and the two that said "Unknown network" use the member that already
   existed.

**What is deliberately still English.** `AiJobService` (`Cancelled`, `Unexpected error: …`) and
`PublishJobRunner` (the restart notice) write into a job row from a background thread that has no
reader's culture to answer in; the desktop agent stays exempt as ADR-117 decided; and the
last-resort handler in `Program.cs` that prints an exception type and message is a diagnostic,
not a sentence for an author. Each of these is a different question from "which language" and
none was asked here.

**Consequence.** A language is a file, and adding a tenth is one file plus one row in the
constructor's dictionary — the test then lists every member it lacks. The translations shipped
with this decision are native-quality first passes, not reviewed by a native reader of each
language; corrections are edits to one row and need no code change. Static initialisation across
partial files runs in no defined order, so the language dictionary is assembled in a static
constructor rather than a field initializer — the compiler warned, and it was right.

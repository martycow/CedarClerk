# ADR-096 — Export window: version → where → network parameters (07.08.2026)

**Context**: Marty's request — "the Export menu isn't intuitive." The window grew from one network to four, and each new one brought its own column with its own publish button: Blog and Telegram went out via the shared Publish button (B5), while Bluesky and X had their own buttons inside their own sections. Language was picked via checkboxes inside the Telegram section, even though it's a property of the post, not of Telegram. The result: two publishing models in one window, and it wasn't clear what the big button at the bottom would do.

**Decision: the window reads top to bottom as three questions — which version, where, with what parameters.**
1. **Version** — a language selection at the top, one for the whole window. Telegram/Bluesky/X send one message per checked language; the blog publishes all existing versions at once (the page has its own language switcher) — and says so with a line of text, not by staying silent.
2. **Where** — a row of destination cards with a checkbox and status. An unconnected network doesn't disappear and doesn't pretend to be available: its card is inactive and leads to Settings (ADR-095).
3. **Parameters** — a panel for each checked destination, collapsed for the unchecked ones.

**One publish button for the whole window.** Bluesky's and X's own buttons are removed: the publish checklist (T-090) already knows how to show a step per network and language, and this is the one place where sending to four networks in parallel reads honestly. `canPublishAll` requires at least one destination and that every checked one is feasible (Telegram — a selected channel, X/Bluesky — a connected account).

**Short-network mode is a two-way switch, not a checkbox.** For X and Bluesky, choosing "an announcement with a link to the blog" (ADR-077) versus "the whole post as a thread" (ADR-094) is two different publications, not an option of one; a "split into a thread" checkbox next to the text field read as "then what's the text field even for." A segmented switch shows exactly the parameters of the selected mode: in link mode, a text field with the network's limit counter; in thread mode, the number of parts (and the cost in credits for X, ADR-092) — and the text field is hidden, because a thread doesn't use it.

**Short-post text is per language.** The field used to be a single one, writing the override for "the editor's current language"; with two versions selected, this silently sent the same text to both. Now the panel holds a language→text map with mini-tabs that appear only when more than one version is checked.

**What stayed put**: photo compression, scheduling and Telegram's thread preview are that network's own parameters and live in its panel; invites and the watermark moved inside the blog panel (they describe the private blog page, not the publish act itself); file exports (.cedar/.zip/file list) are a separate panel at the bottom, because it's the one part of the window that doesn't publish anything anywhere.

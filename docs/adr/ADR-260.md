# ADR-260 — The bench draws the whole form: select, textarea, checkbox, and what a field passes through (05.09.2026)

**Context.** `T-251`, `T-252`, `T-262`, `T-263`. The bench had one field, `app-input`, and it passed
through neither `maxlength` nor an accessible name, so Settings kept seventeen native fields and the
project-tasks modal dressed five selects, a textarea and a checkbox by hand. ADR-170 clause 3 held
fourteen `.btn-accent`/`.btn-ghost` blocks open on the same ground: a modal footer is markup the bench
did not cover until the dialogs' other controls existed.

Re-measured against the tree before anything was written, the way ADR-170 requires:

- The four shared dialogs `T-262` names — `folder-picker`, `series-picker`, `tag-picker`,
  `glossary-term-form` — carry no `.btn-ghost`/`.btn-accent` any more. Their footers are
  `app-button` paper + danger. The row was closed by an earlier port and never struck off.
- `.btn-accent`/`.btn-ghost` are defined in **four** page stylesheets, not six and eight:
  `editor`, `posts-manager`, `project-builds`, `project`. Every one is live: its own template puts
  the class on roughly sixty real buttons, thirty-five of them in the editor's modal footers.

**Decision.**

1. **`app-input` passes through `maxlength` and takes `ariaLabel`.** Both are attributes on the
   native field, absent when empty. A field with a visible `label` needs no `ariaLabel`; a search
   box whose only visible name is its placeholder now has somewhere to put the real one.
2. **Three sibling controls, one API.** `app-select`, `app-textarea` and `app-checkbox` live beside
   `app-input` in `bench/forms/` and copy its shape exactly: `label`, `hint`, `inputId`, `disabled`,
   `dense`, `ariaLabel`, a full `ControlValueAccessor` for `[(ngModel)]` and reactive forms, plus
   `value`/`valueChange` for a signal host. `app-textarea` adds `rows`, `maxlength`, `serif`;
   `app-select` and `app-textarea` take `title`, because the Pro-gated slot and signature already
   explain their lock through it and a port that lost the sentence would be a regression.
3. **`app-select` takes an `options` array, not projected `<option>` children.** Each option is
   `{ value, label, disabled? }` and the component keys the native element by index, so the value
   handed back is the one the consumer put in — typed. A native `<select [value]>` under `ngModel`
   hands a string back for every option, which is how a `TaskPriority` of `2` became `'2'` on the
   first change of the task modal's priority field. Projection would also leave the selection to
   the order in which the parent's `@for` and the child's `writeValue` happen to run.
4. **`app-checkbox` keeps the platform control.** styles.scss already decided that a paper stock on
   a checkbox is a widget bent out of shape and sets only its `accent-color`; the bench wrapper
   sizes the box on the icon scale, lays the label beside it and gives it the `label`/`hint`/CVA
   surface the other fields have. The label is `label` or projected content, so a rich row (a bold
   line over a small one) is still one control.
5. **A field can be named by a label it does not draw.** Settings lays a label in a grid column at
   the left and the control at the right; `inputId` puts the id on the native element, the page's
   `<label for>` binds to it, and the component's own stacked `label` is simply not used there.
   The stacked label is for forms that stack (the task modal); it is not a requirement.
6. **Two Settings fields stay native, and it is a choice this time.** The timezone field feeds a
   `<datalist>` and the custom-credits field carries `min`/`max` on a number; neither passthrough
   exists on `app-input` and neither has a second caller to justify one. They are named on the
   inventory as native by decision.
7. **`app-task-tag` takes `queryParamsHandling`.** Unset, the tag replaces the query set, which is
   what the board and the sprint shelf do today; `'merge'` is for the screen that hangs a tag beside
   a filter. The default preserves behaviour, the input exists so the trap `T-254` names has a
   handle before the next screen falls into it.
8. **The four `.btn-accent`/`.btn-ghost` sheets stay until their templates are ported.** ADR-170
   clause 3 still holds: a rule one template uses is not dead. The port is now unblocked — the
   footers' selects, textareas and checkboxes have components — but it is a markup change across
   four page templates, each with its own smoke bindings, and it belongs to the lane that owns those
   pages. Deleting the CSS first would unpaint sixty buttons, which is the defect clause 6 of ADR-170
   found already done once.

**Rejected.** *A global `.btn-accent`/`.btn-ghost` in styles.scss* — the fourteenth global control
class ADR-170 refused. *Projecting `<option>` elements* — see clause 3. *Painting the checkbox* —
see clause 4. *Adding `list`, `min` and `max` passthroughs for one caller each* — an input with one
consumer is a page rule with a longer name. *Converting Settings to the stacked label* — a
two-column form would become a one-column one for no reason the design asked for.

**Consequence.** The bench covers every control a modal footer or a settings card draws. Settings
keeps two native fields by decision and none by gap; the task modal is entirely bench. `T-262` and
`T-263`'s old counts are corrected on the board, and what is left of `T-263` is a port of four
templates, not a CSS deletion.

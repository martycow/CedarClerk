# ADR-204 — An uploaded file belongs to a project, or to nobody, and follows the document that uses it

**Context.** ADR-127 made the media library owner-wide, and the indie-dev module later gave the word
"assets" a second meaning: `AssetEntry`, a read-only index of a folder on the author's own machine.
Two reports land on that seam. Filing a post into a project (ADR-203) moves the document and leaves
its images where they were, because `Asset` has no project at all. And with the module on, the tool
wall's Assets hook points at the folder index, so `/library` — where every uploaded file actually
lives — has no entry point on any screen. A glossary illustration is reachable by nothing.

**Decision.** `Asset` gains a nullable `ProjectId`.

- **Null is a real answer, not a missing one.** It means the file belongs to no project — a glossary
  illustration, a signature image, anything used outside a project's documents — and the library
  shows that as its own bucket rather than as a gap.
- **A file follows the document that uses it.** Whenever a draft's project changes, the media it
  references is filed to the same project. Only unfiled assets move: the first project to claim a
  file keeps it, because a file used by two projects has one honest home and picking the newest
  claim would make the answer depend on edit order.
- **The backlog is swept on demand, never silently.** `POST /api/projects/{id}/assets/refile` walks
  that project's documents and files what they reference, and says how many moved. It is idempotent
  and it is a button, because a filing rule applied retroactively without asking is indistinguishable
  from files moving on their own.
- **The two meanings stay two meanings.** The project's Assets screen keeps the folder index and
  gains the uploaded half beside it as a second source, rendered by the library component with a
  project scope rather than by a second copy of it. The library page keeps its own address and gains
  the project strip, which is what makes the unfiled bucket reachable.

**Consequence.** The images in a blog project's posts are in the blog project, and a file that
belongs to nothing can be found. The cost is that "which project is this file in" now has an answer
that can be wrong — a file shared between projects sits in the first one that claimed it, and only
the library, which shows every bucket, is complete. That is stated on the screen rather than left to
be discovered.

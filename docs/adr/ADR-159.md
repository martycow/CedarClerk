# ADR-159 — The writer keeps no chrome of its own: a published primary action, and a meta strip that becomes the inspector

**Context.** ADR-139 clause 3 adopts the mirror's placement table verbatim, and two of its rows have
had no implementation since the shell landed. *RailHeader — brand, project switcher, breadcrumb,
save state, the screen's one primary action.* *The right shelf — the selected object's properties,
or the document when nothing is selected.* The shell renders `app-rail-header` with its `[menu]` and
`[account]` slots filled and its default slot — the one `RailHeader.prompt.md` reserves for exactly
those two things — empty, because a page rendered into `<router-outlet />` cannot project into a
component that sits above the outlet.

So the editor kept its own 44px `.topbar` carrying the draft title, `.save-state` and the Export
button, and kept a horizontal meta strip above the sheet carrying eleven more controls: the
private/watermark/live chips with their two outbound links, the language tab row, re-translate,
delete-version, make-primary, translate-all, revision history, the document's tree crumbs, the tag
picker, the folder picker, the series picker and the backlinks popover. Both are page-local chrome
that the kit does not draw: `.design-sync/ds-v2/ui_kits/writer.html` puts the save state and the
publish button on the rail and everything else in a 330px inspector shelf on the right.

ADR-153 named the first half of this as a debt in its own consequence paragraph — *"Whoever builds
that header removes one of the two, and this entry is where the choice is recorded as owed."*

**Decision.**

1. **A page publishes its rail contribution; the shell renders it.** `core/rail-actions.service.ts`
   is a signal holder of the same shape and for the same reason as `RulerService` (ADR-153 clause 5):
   the shell must not know which screens exist, and a screen must not reach into chrome it does not
   own. It carries **data, never a template** — a save state, and at most one primary action as
   `{ label, icon, hint, disabled, run }`. A `TemplateRef` portal was rejected: it would let any page
   put any markup on the rail, which is the placement rule ADR-139 clause 3 exists to stop, one
   indirection later.

2. **One action, enforced by the type.** The field is a single object and not an array, because the
   placement table says *the screen's one primary action*. A second button on the rail is not a
   near-miss to be caught in review; it is unrepresentable.

3. **The editor's `.topbar` is deleted.** Save state goes to the rail as `app-resin-drop`, whose
   inventory row already claims to be the only save indicator in the app; Export goes to the rail as
   the one primary action. The duplicate ADR-153 recorded — save state on the topbar *and* on the
   rule — is settled the way that entry said it would be: **the rule keeps the sync word, the rail
   carries the drop** and spends the word on the drop's accessible name rather than printing it a
   second time, and the topbar that held a third copy is gone.

4. **The draft title moves onto the sheet, not into the rail crumb.** The kit's crumb reads
   `Devlog #12 — Свет и туман` and its sheet opens with the same words as an `h1`; in the kit those
   are one document heading shown twice, because the kit's title *is* a node of the document. In
   Cedar `Draft.Title` is a column, the outline's H1 is not it, and the title is typed rather than
   read — so it lands where it is typed, as the sheet's first line, inside the worktop. The rail
   crumb stays the shell's route crumb. `input.title` keeps its class: the smoke suite binds it, and
   the field is the same field.

5. **The meta strip becomes the inspector, and the inspector obeys `SpecRow.prompt.md`.** *"It shows
   the selected object, and falls back to the document when nothing is selected. Never show both at
   once."* This is implemented as an exclusive computed rather than as a convention: one
   `inspectorScope()` returns `'selection'` or `'document'`, the template switches on it, and every
   `app-spec-row` in the panel carries the matching `scope`, so a mixed sheet is a thing a test can
   assert against rather than a thing a reviewer has to notice. Only a ProseMirror `NodeSelection`
   counts as an object being selected — a caret inside a paragraph is the document being written.

6. **A selection is described from the node's own attributes and from nothing else.** The kit's
   inspector shows an image's resolution, its byte size and the asset path it came from. None of the
   three is on a TipTap image node, and no client-side pass produces them. They are not shown, not
   guessed and not left as an empty row that reads like a missing value — the rows that exist are the
   ones the node answers: its type, its source file name, its alt text and its caption, with alt
   drawn `warn` when it is absent, which is the one claim in the kit's image panel the document can
   actually support. `core/selection-spec.ts` is a pure function over a node's shape so that this is
   checkable: its spec asserts the key set, not just the values.

7. **The language tab row becomes the inspector's `LeafTag` row, and it stays the switcher.** The
   kit draws `RU · исходный` and a dried `EN · 18.08`; the app's tabs are the same set with a click
   behaviour. `app-leaf-tag` has `interactive` and an output, so the two are the same control. Its
   `dried` state is **not** used for a stale translation: `dried` means "no data" and refuses the
   click, while a stale translation is exactly the one a writer reaches for — so staleness stays the
   dot it already was, projected into the leaf, and the warning stays on the leaf's tooltip. The
   version commands (re-translate, delete, make primary, translate all, history) stand under the
   leaves inside the panel rather than in the shelf header's `[actions]` slot: they act on one
   language, not on the panel.

8. **What is projected into a `SpecRow` stands on chrome; what sits on the sheet stands on paper.**
   The row declares `data-surface="chrome"` and the shelf's sheet declares `paper`, so a control's
   numbers follow where it is put and not who put it there. The crumb buttons and the two outbound
   links go inside rows and take `--text-chrome-sm`; the language leaves, the version commands and
   the backlinks popover sit directly on the sheet and take paper's floor. The backlinks control was
   moved out of a row for exactly this reason — a panel of document titles is reading matter, and
   reading matter does not belong on chrome's 11px. Every one of these declarations is written under
   its surface's attribute rather than bare, so `tools/check-density.mjs` rule 5 scores it; both
   blocks were verified to go red on a wrong size before being left green.

9. **The rule gains the block index, because the document answers it.** `block 5 / 10` is read off
   `state.doc.childCount` and the selection's own top-level index — no endpoint, no pass, nothing
   claimed that is not already in the editor's state. It sits behind the same `showWordCount`
   preference as the two counts beside it. The rule's *check* count is a different thing entirely
   and is not drawn: see the consequence.

**What was rejected.** *Leaving Export on a slim page-local bar.* It is the sentence ADR-139 clause 3
already answered, and a second bar under the rail is the editor's topbar with fewer things on it.
*Putting Export in the inspector's `[actions]` slot.* `ShelfPanel.prompt.md` gives that slot to the
panel's own commands; publishing is not a property of the inspector. *Keeping the meta strip and
adding the inspector beside it.* Two homes for one control is `.claude/rules/ui-changes.md` rule 1,
and the strip is what the shelf is for. *Showing the kit's resolution/size/asset-path rows as
`не заполнено`.* An empty row asserts the field exists and is blank; these fields do not exist.

**Consequence.** The rail now shows different contents on different screens, which is new: until now
its right side was the same everywhere. A screen that forgets to clear on destroy would leave its
button on the next screen's rail — the service clears the same way `RulerService` does, on the page's
`ngOnDestroy`, and the router destroys the outgoing component before activating the next, so the
ordering is the one that already works for the rule.

The three shared pickers — folder, series, tags — now sit inside spec rows and therefore inside
chrome, while each carries type sizes from its own stylesheet written for paper. Nothing is broken by
it and nothing measures it either: their sheets name no surface, so the lint cannot see the mismatch.
Whoever ports those three components is the one who resolves it, and this sentence is where the
mismatch is recorded rather than discovered.

The inspector is a 340px column the editor did not have, taken out of the sheet's own width on a
1440px screen. The sheet keeps the width the Appearance preference gives it and the worktop centres
it; below roughly 1100px the column and the sheet start to fight, and nothing in this port addresses
that — ADR-147 defers every width rule to the commissioned designs, and this is one more thing
`T-236` has to answer.

What the kit draws and this does not: the drawer's **Checks / Translation / Publications** tabs and
the rule's check count. The pre-publish check system behind them has no endpoint and no client pass,
so the affordance is left out rather than drawn over a number nobody computes. It is a board row.

Six smoke-suite selectors bind to chrome this entry deletes — `.save-state .save-label` in five
files plus `e2e/helpers.ts`, `.export-trigger` in three, and `.toolbar button:has(.invisibles-glyph)`
— and they are `T-233`'s to rebind. `input.title`, `.block-dropdown`, `.retranslate-btn`, `.tiptap`
and `app-tag-picker button` were kept binding-compatible on purpose, and the rail's primary button
carries `class="rail-primary"` so the replacement for `.export-trigger` is a name and not a
structural guess.

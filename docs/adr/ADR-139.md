# ADR-139 — The bench shell is shared chrome: one wrapper route, navigation on the hook rail

**Context.** The app has no shell. `cedarclerk-web/src/app/app.html` is a `<router-outlet />` and the debug console, `app.scss` is empty, and chrome is drawn once per page: `app-page-header` appears in twelve page templates and the editor draws its own `.topbar` with a second copy of the same nav row (`pages/editor.component.html:38-67`). ADR-052 built that shared header for a real reason — four screens had drifted into two visual styles and the only route from Glossary to Settings was the account popover — but the wall it had to hang navigation on was the header itself. Cedar Bench supplies the wall the header was standing in for: a 52px `HookRail` down the left edge, and a 56px `RailHeader` that keeps only what belongs to the whole screen. `.claude/rules/ui-changes.md` rule 1 — one home per control — is already violated today by a nav row living in two components; porting screen by screen without a shell would leave it violated for the length of the port.

**Decision.**

1. **The shell is a route, not the root component.** `app/bench/chrome/bench-shell.component.*` becomes a parent route in `app.routes.ts` whose children are the existing authenticated routes with their paths, guards and `loadComponent` calls unchanged. Not `app.html`: today the pre-auth pages are handled by `PUBLIC_ROUTES` (`src/app/app.ts:8`), a list of four URL strings matched by prefix, which has to be remembered every time a route is added. A parent route makes the boundary a fact of the route tree instead of a string comparison, and the pages outside it have no chrome to suppress rather than chrome to hide.

2. **Outside the shell: `/login`, `/register`, `/terms`, `/privacy`** — the same four. The rail carries a project switcher, save state and hooks into guarded screens; every one of them is meaningless without a session, and terms/privacy must render for a reader who has none. `/dev/styleguide` and `/dev/icons` stay inside: the styleguide's whole job is showing chrome components in their chrome.

3. **Where controls live is the mirror's placement table** (`.design-sync/ds-v2/readme.md`, `guidelines/placement-map.html`), adopted verbatim: RailHeader — brand, project switcher, breadcrumb, save state, the screen's one primary action; HookRail — moving between screens; ShelfPanel header — that panel's own commands; the right shelf — the selected object's properties, or the document when nothing is selected; BenchDrawer — journal, checks, build output; RulerBar — read-only counts and state words. The chrome/paper split those surfaces sit on is ADR-138's, and every component named here carries its `data-surface` from the commit that creates it. The clause that makes it enforceable rather than decorative is the last one: *if a control does not fit the split, it is on the wrong surface.* That is rule 1 with an address for every answer.

4. **Six hooks against ten destinations.** `app.routes.ts` has ten authenticated top-level paths (`/editor`, `/drafts`, `/settings`, `/posts`, `/glossary`, `/library`, `/projects`, `/admin`, `/dev/styleguide`, `/dev/icons`) plus five `projects/:id/*` children. The rail takes Hub (`/projects`, hidden when `auth.indieDev()` is false — the condition `page-header.component.html` already uses), Text (`/drafts` and `/editor`), Board (`/projects/:id/tasks`), Assets (`/library`), Metrics (`/posts`), and Settings anchored at the bottom. Glossary, Admin and `/dev/*` go behind a `dots` button in the rail's right slot. Two hooks of the 5–7 budget stay unspent deliberately: Phase 13 is unfinished, and the budget is a legibility limit, not a quota.

5. **The header nav row goes, both copies.** `shared/page-header.component.*` and its twelve call sites are deleted, and so is the editor topbar's `.export-btn.nav-btn` block. This reverses ADR-052's nav-row and glass-header clauses; what ADR-052 decided correctly — one chrome instead of five hand-rolled ones — is not reversed but taken further, to one chrome instead of twelve. The account menu keeps the shape ADR-052 left it in (profile, admin-if-applicable, logout) and moves to the rail's right slot, which `RailHeader.d.ts` documents as "save state, primary action, account" and all three kits render as an avatar.

6. **The Electron default menu bar goes too.** `CedarClerk.Desktop/main.js` constructs no menu at all — the File/Edit/View bar exists because nothing replaced Electron's built-in default, so removing it is a line in `createWindow` (`main.js:381`), not a deletion of code we wrote. The design system's reason applies with extra force here: the desktop window renders the production page (ADR-117), so any menu it grows is a command surface the browser build does not have, and a command that exists in one client only is a command nobody documents.

**Consequence.** The rail's project switcher has nothing behind it on four of the six hooks. `Draft.ProjectId` exists on the entity (`CedarClerk.Server/Data/Entities.cs:312`, ADR-102), but the drafts list never projects it — `DraftMeta` (`core/drafts.service.ts:107`) has no such field — so on `/drafts`, `/editor`, `/posts` and `/library` the tile can only be account-scoped. It is a projection gap, not a schema one, and until the list DTO grows the field the switcher shows a project only where the route already names one. This is stated rather than discovered because a switcher reading "no project" on most screens looks like a broken control, not a missing field.

Two smaller costs are accepted with it. The active hook can no longer be read off an input the way `PageHeaderComponent.page` was — Text covers two paths and Board a child path, so it is computed from a route-prefix table, and a wrong prefix is a silently unlit hook. And the shell has no responsive specification to inherit: the mirror has zero width breakpoints and all three kits are fixed 1440×900, so anything below V2 proportions falls back to the app's existing breakpoint ladder, which is our decision and not the design system's — the same is true of the `dots` menu and the theme toggle, which the prose names but no component defines.

The chrome the shell replaces is load-bearing for tests: `src/app/app.spec.ts:19-24` asserts `app-debug-console` renders on a non-public route, and `e2e/10-ui-shell.spec.ts:43` waits on `app-page-header`. Both must be rebound to the shell — the second one breaking is the proof the chrome moved. The glass goes with it: `page-header.component.css:15` uses `backdrop-filter`, which the material rulebook forbids outright, and dropping it also retires the editor's `.topbar::before` workaround, which exists only because blur creates a containing block. New chrome enters the Shared components table of `docs/design/UI-INVENTORY.md` in the commit that adds it; the deleted rows go in the commit that deletes them.

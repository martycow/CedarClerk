# ADR-250 — Author social links appear at the public blog header (02.09.2026)

**Context.** Profile settings collect Website, X, Instagram, Facebook, YouTube, GitHub, Telegram,
Threads, Bluesky, Reddit, Steam and itch.io URLs, but the public product never reads them. A saved
link that has no public presentation is misleading. Rendering every icon in the blog header would
turn optional identity into permanent chrome and would fail on narrow screens.

**Decision.**

1. A public blog header shows one *Author links* control when its owner has at least one valid
   social link. Hover or keyboard focus reveals the link card on pointer layouts; press toggles it
   on touch and for keyboard users. Escape and outside press close it. The trigger exposes expanded
   state and controls the labelled card.
2. The card lists only configured absolute `https://` or `http://` URLs, with the service name as
   visible text. Values using another scheme or invalid syntax are omitted. Links open in a new tab
   with `rel="noopener noreferrer"`.
3. The control renders on the public blog surfaces that share the blog header. It does not appear
   on a private preview merely to bypass that preview's access rules, and it does not expose email,
   account IDs or unconfigured services.
4. Social links remain account profile data. No document node, publication job, renderer or schema
   is added. Removing a URL removes it from the next public response.

**Rejected.** *Show twelve permanent icons* — the header becomes noisy and empty services look
broken. *Copy links into each post* — identity would drift between documents. *Accept arbitrary URI
schemes* — a profile field must not become an executable public link.

**Consequence.** The profile copy explains where these links appear. The server-rendered blog gets
one shared author-links model, safe URL parsing, accessible interaction and tests for configured,
empty and unsafe values. Public metadata and subscription behaviour remain unchanged.

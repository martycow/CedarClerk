# ADR-152 — The accent picker survives, and every tone downstream of it is derived, never held

**Context.** Cedar Bench is built on the idea that pine is the one colour that acts: primary buttons, active hooks, the lit tab, the link. Read as a slogan about a hue, that argues for making pine a constant and deleting the Appearance accent picker along with the skin mechanism ADR-136 retired. The design system offers no second accent, so nothing in the mirror contradicts the reading.

What contradicts it is the app. `ACCENT_PRESETS` (`core/appearance.service.ts:25-31`) carries five presets, each a *pair* — a day tone and a darker night one: Cedar `#39543C`, Bark `#755934`/`#624B2C`, Slate `#4A5A6B`/`#425160`, Ink `#3A3730`, Rust `#914A29`/`#7A3F22`. ADR-141 clause 6 is why they are pairs: the old dark branch lightened towards `#E8F0E8`, which on night's binding surface `--surface` `#D9CEAE` put the five shipped presets at **1.53–2.23:1**, and it now mixes towards the ink with every preset held to the same 4.5:1 as the default — "a preset that cannot clear it stops being a preset". `presetFor` (`:37-38`) resolves any stored hex outside that list to the bench accent, so an unmeasured colour cannot reach the page.

The contract leans on the picker too, in a way that is easy to miss. ADR-137 clause 5 — where a material name and a contract name are the same swatch, the contract name wins — gives as its reason that only the contract name "is moved by the user's accent preset", and spells out the failure: a primary button painted `--pine` looks identical today and stops following the chosen accent the moment either value moves. Remove the picker and that clause loses its argument.

**Decision.** The Appearance accent picker survives the port.

**Attribution.** *This is the implementer's default, taken under Marty's general instruction to proceed. He was told it was being defaulted so he could override it, and did not; it was never put to him as a question and this entry must not be read as his decision.* Reversing it is a deletion, not a rebuild — one control, one settings block, and a constant where a variable was.

1. **The picker stays**, on the five vetted pairs ADR-141 left it with. Deleting a working, measured, user-facing control to make a slogan literally true is a loss with nothing on the other side of it; "pine is the one colour that acts" is a claim about which *role* carries action, and it survives a user painting that role Rust.

2. **The constraint the picker imposes: every accent-derived tone is derived from `--accent` at use, never held.** `styles.scss:262-270` is the shape — `--pine: var(--accent)`, `--pine-hi: color-mix(in srgb, var(--pine) 92%, var(--paper-bright))`, `--pine-deep: color-mix(in srgb, var(--pine) 76%, #000000)`, `--grad-pine` built from the two. The mirror holds the same three as fixed hexes (`tokens/colors.css:40-41`, night `:96-97`); ported as authored, picking Bark leaves the lit face of a primary button pine and turns one object into two colours.

3. **A new accent-derived token is added to `ACCENT_DEPENDENT` in the same commit** (`tools/check-contrast.mjs:566`). That set — `--accent --asoft --abord --pine --pine-hi --pine-deep --grad-pine` — is what makes the gate re-run every accent-touching pair against all five presets in both themes, and it reads the presets out of `appearance.service.ts` rather than a copy, failing outright when it cannot (`:589`). A derived token missing from the set is measured once, in Cedar, and never in the four colours the user can actually choose.

**What was rejected.** *Making pine a constant.* It deletes a control that works, and it does not simplify the token layer by one line, because `--pine-hi`/`--pine-deep` would still be derived — from a constant instead of a variable. *Keeping the picker but holding the derived tones as the mirror does*, on the argument that they are "the material" rather than "the accent": the checker's set is a list of *names*, so a held `--pine-hi` stays in it, the `--accent` override no longer moves it, and `--text-on-pine` on `--grad-pine` (`:424`) is then measured against a ramp whose top stop never changes — a green run over a Bark button whose lit half is still pine. A pass that describes a colour the app does not paint is worse than no pair at all. *Widening the picker to a free colour input*, which the design system does not offer and `presetFor` deliberately refuses: an arbitrary hex has no vetted night tone, and there is no way to measure one at pick time.

**Consequence.** Every bench component that leans on `--accent` can be drawn in a colour the user chose, and none of them may assume pine. That is enforced, not merely asked: the contrast gate runs each accent-dependent pair ten times — five presets in two themes — and the census resolves accented combinations through the same five (`:1034-1036`), reporting the worst preset by name. The cost is a screenshot of the styleguide showing one of five possible products, and a reviewer who eyeballs a bench component in Cedar has seen a fifth of it.

The mirror's pine hexes stay reference only, like its night block (ADR-141) and its fonts (ADR-143). That is now three places where the mirror is read for shape and not for values, which is what ADR-144 means by calling it a cache rather than a document.

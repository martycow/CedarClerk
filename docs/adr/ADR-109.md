# ADR-109 — Bluesky actually sends images, YouTube rides along as a text link, X honestly says "I won't accept it" (10.08.2026)

**Context**: Marty's report after testing export — "images didn't send, the YouTube link didn't send." A code review showed this wasn't one bug but three different ones, and the worst of them isn't the one that catches the eye.

**What was actually going on:**

| What | How it was | How it looked from outside |
|---|---|---|
| Images to Bluesky | `Capabilities.MaxMediaItems = 4`, `MaxImageBytes`, `SupportsAltText = true` — but the `app.bsky.feed.post` record only contained `text`/`facets`/`reply`, and `uploadBlob` was **never** called | **The app promised and silently didn't deliver.** The preflight check reads `Capabilities`, so four images passed as "all fine" |
| Images to X | `MaxMediaItems = 0` — declared honestly, media not implemented (ADR-093, "text+link v1") | The warning was there, but it read like "media: 3, and the network accepts 0" — arithmetic where a sentence was needed |
| YouTube | The `youtube` node never appeared in either `CedarPlainText` (short-post text) or `PublishValidator` | The video disappeared **entirely, without a single signal** — no link in the text, no warning |

**Decision, one row at a time:**

**Bluesky now genuinely gets images.** `uploadBlob` + an `app.bsky.embed.images`-type embed, up to four, in reading order, with alt text (the network supports and expects it). The blob limit is 1 MB, which is below almost any real screenshot, so it uses the same `ImageCompressor` as the Telegram path. **An image failure doesn't break publishing**: a post without an image is worth incomparably more than not publishing at all — but every skip is logged. Images go out only with the **first** part of a thread: repeating the same four snapshots in every part isn't how a thread looks anywhere.

**The YouTube link rides along as text.** Neither Bluesky nor X will embed video, but they will carry the link, and a link is all the viewer needs. `CedarPlainText` now renders a `youtube` node as a paragraph "`caption + watch-URL`," caption first, so a thread part reads as a sentence rather than a bare address. This also fixes the thread: previously the video simply dropped out of the middle of the document.

**X stays without media, but says so in words.** Implementing upload to X is a separate mechanism (media/upload with a different auth scheme) and separate money per post; starting that silently as part of a bug report would be wrong. The declared zero is true, what changed is the wording: "media: 3 — this network doesn't accept them at all, they will not go out."

**A conclusion worth more than the three fixes**: `PublishCapabilities` is a promise the preflight check reads. A gap between it and the implementation produces neither an error nor a warning — it produces silently lost content. Any new capability must appear in `Capabilities` **together with** the code that fulfills it, never ahead of it.

**What is still unverified**: an actual live send of an image to Bluesky. The mechanism is covered by unit tests for building the image list and the text, but `uploadBlob` against a real bsky.social requires Marty's account — to be verified by the first real post.

# ADR-212 — The host → owner answer is cached, and expiry is the only invalidation

**Context.** Two lookups now sit in front of nearly every request. A subdomain has to be turned into
an owner before anything else runs, and a `/media` file has to be turned into its owner before it is
served. A blog page pulls its stylesheet, its fonts and every image from the same host, so uncached
this is a dozen `AspNetUsers` queries per page view, each on a freshly built context and its own
SQLite connection — on a 1 vCPU droplet with 2 GB and no swap. An unknown subdomain is worse: it is
the same cost, chosen by an anonymous caller, repeatable as fast as they like.

**Decision.** One small cache class, `TenantOwnerCache`, used by both lookups.

- **Misses are cached too**, on a shorter lifetime than hits (10 s against 30 s) — a subdomain that
  has just become real should start answering, and a name nobody owns should not cost a round trip
  per guess. Names that cannot parse at all never reach the cache: they are a 404 before a query is
  opened.
- **Nothing invalidates an entry; it expires.** Which is exactly why the lifetimes are seconds
  rather than minutes. The alternative is every path that could move a name between accounts
  remembering that this class exists, and the one that forgets serves one blog under another's host.
- **The bound is a name count, not a request count** (10 000), swept expired-first and then
  oldest-first rather than emptied, because emptying hands the next burst the miss storm the cache
  exists to absorb.

**Consequence.** Warm static assets and warm `/media` on a blog host cost zero database commands,
measured, which is the win this was built for. Three costs are known, and two are on the board.
A deleted account keeps answering — an empty blog, not another account's — for up to 30 seconds
(`T-292`); rename cannot cause that, because no rename endpoint exists (ADR-206), so the reachable
variant is delete-then-re-register inside the window. Distinct well-formed guesses still cost one
query each and now also occupy the bound, so random enumeration evicts the legitimate entries the
cache exists to hold — and the class is not DI-registered, so several independent instances each
carry their own budget (`T-288`).

# ADR-281 — The hub nudges with a sentence, and prints one account number it names as the account's (05.09.2026)

**Context.** `T-166` asked for publishing-discipline nudges on the project dashboard: how long
since the last post, and the streak the Stats tab already wears (`GET /api/stats/publishing`,
ISO publishing weeks). ADR-160 clause 3 refused account-wide numbers on a project screen — a
metric rendered where it looks like the project's is the confident wrong answer — and clause 7
refused inventing anything on the hero's edge that the API does not report.

**Decision.**

1. **Days since the last post are the project's own fact and go on the header's meta line.**
   `ProjectSummary.lastPublishedAt` (the newest blog, Telegram or network publish of any document
   in the project) is the source; the hub floors the difference to whole days. Under seven days it
   is plain text beside the last edit; from seven it becomes a `muted` tag; from fourteen the tag
   is `warn`; a project that never published says so in a `muted` tag. There is no score, no
   counter that resets, nothing that can be lost — a sentence that changes tone, the way the
   sprint card's overdue line does.

2. **The streak is the one account figure the hub prints, and it says whose it is.** One kv row
   in the "where it goes" card, labelled *Your streak*, worded "N weeks in a row, across every
   project". It comes from the same endpoint the Stats tab reads and is hidden for zero and for a
   failed call: a `0 weeks` row is a reproach dressed as a number, and "could not ask" must not
   read as "never".

3. **This is the narrow exception to ADR-160 clause 3, not its repeal.** The clause forbade a
   number that *looks like* the project's. A row that names the account in its own label cannot
   be misread that way, and the streak is the one metric the row asked for by name. Views,
   followers and every other account total stay where ADR-148 placed them.

**Rejected.** *A streak per project* — the weeks are counted over every destination of the
account, and slicing them per project would need the project-to-channel table ADR-160 clause 6
records as absent. *Any XP, badge or "keep it going" copy* — the row's own brief was quiet
mechanics; a game layer on a work tool is the thing indies leave other tools over.
*Hiding the nudge on an archived project* — an archived project prints its state tag first, and
the sentence after it is still true.

**Consequence.** The hub gains one field on the summary row and one request it already made
elsewhere; nothing new is stored. The reader of ADR-160 has to know clause 3 now has one named
exception, which is what this entry is for.

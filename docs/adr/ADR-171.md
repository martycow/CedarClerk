# ADR-171 — A smoke test binds to the role and the name, not to the class (20.08.2026)

**Context.** T-233. Sixteen of the fifty-seven behavioural tests were red against the ported app, and
not one of them was red because a behaviour had been lost. Fourteen were bound to a class name the
repaint moved or deleted — `.btn-accent` on a toolbar that now holds an `app-button`, `.search-input`
on a field that is now an `app-input`, `.admin-tabs` on a strip that is now `app-index-tabs`,
`.export-trigger` on a control that the page no longer draws at all, `.save-state .save-label` on an
indicator that dissolved into the rule and the drop (ADR-153, ADR-159). The remaining two had been
red since ADR-135 rewrote the landing on `master`, and nobody noticed, because a suite that is red
for one reason hides every other reason it is red.

A class name is a fact about a stylesheet. A suite bound to one measures the stylesheet, and a
repaint is indistinguishable from a regression. The port had already re-bound the shell-level
selectors onto `app-rail-header .dots` and `.theme-toggle` — another class, one stage of quiet.

One prediction in `docs/design/UI-V2-PLAN.md` §5 was wrong and is worth recording: `.tiptap`, the
twenty-one-site selector the plan expected to be the biggest casualty, never broke. It is TipTap's
own class on the editable element, not app markup, so no repaint of ours could move it.

**Decision.**

1. **A selector names the role and the accessible name a person would use** — `getByRole('button',
   {name})`, `getByRole('tab' | 'tablist', {name})`, `getByPlaceholder(...)`. That is the same pair
   a screen reader announces, so a binding that breaks is a control whose meaning changed, which is
   what a smoke test is for.
2. **A class is allowed only where the element has neither a role nor a name, and then only a
   structural class its own component owns**: TipTap's `.tiptap`, the blog's server-rendered
   markup, `.drafts-title` on a row that is a `div` with a click handler. A *shared control* class
   is never a binding — `.btn-accent`, `.icon-btn`, `.status-badge` and the tab strips belong to
   whichever stylesheet last defined them, which is exactly why the port could delete them out from
   under four tests.
3. **A component element name is a selector of the second kind.** `app-modal`, `app-rail-header`,
   `app-ruler-bar`, `app-shelf-panel` are the components' public API; renaming one is a code change
   with a compiler behind it, not a repaint.
4. **Where a page publishes into shared chrome, the test asserts on the chrome.** The save word is
   read off `app-ruler-bar` because that is where ADR-159 clause 3 put it, not off whatever the
   editor happens to hold.
5. **Green bindings are not churned.** `.manager-tabs button`, `.post-card`, `.post-search`,
   `.primary-btn`, `#cc-login-email` are still bound by class and still pass; three of them are
   recorded in `docs/design/UI-INVENTORY.md` as kept for this suite. Rewriting a passing test
   produces no evidence, and dropping the classes those rows promise is a UI change that needs its
   own row, not a side effect of a test repair.

**Consequence.** The suite and `e2e/12-a11y.spec.ts` now pull the same way: a control with no
accessible name is not only announced as "button", it is also a control no new test can reach. The
cost is that a renamed label is a red test — correctly, since a label is what the user reads, but it
means the English dictionary is now load-bearing for the suite, which is why `pinEnglish` runs in
every `beforeEach` and must keep doing so.

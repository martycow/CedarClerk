# ADR-243 — Discovery is an opt-in public commons for projects and independent blogs (02.09.2026)

**Context.** Cedar Clerk's public surfaces belong to one account at a time: a blog answers on the
owner's tenant host and a Showcase lives under that blog. The landing sells the tools but gives a
visitor no way to discover what people make with them. The selected public direction changes that
front door: projects, devlogs and independent blogs share one editorial page; `#ScreenshotSaturday`
gets a stage; projects can be browsed by category. A simple blog that belongs to no Project must not
become a second-class version of the indie-development module.

The public/private boundary is stricter here than on a tenant blog. `IsListedWhilePrivate` lets an
owner list a gated post on their own index, where the surrounding site already belongs to them. A
cross-account feed would turn that title, author and image into a platform-wide disclosure. The
platform also cannot infer consent from publishing a blog or enabling a Showcase: those actions
publish to an address the owner controls, not to Cedar Clerk's front page.

**Decision.**

1. **Discovery is a first-class server-rendered page at `/discovery` on the app host.** It is
   indexable, has its own canonical and language links, and uses the same generated design tokens,
   fonts and icons as the landing and public blogs. It is not an Angular route and never needs an
   account to read. The landing links to it and carries a smaller live preview of the same public
   pool; it remains the product's acquisition page rather than becoming a duplicate feed. The
   selected direction is light-only: the app's dark material tokens use paper ink inside framed
   surfaces and cannot be dropped onto this page's unframed canvas without a separate design pass.
   `PlatformPaths.ExactPaths` grants `/discovery` the cross-owner database model before
   authentication, without granting any future child route the same access; the Landing middleware
   declares the same platform scope before loading its preview.

2. **An account is absent until its owner opts in.** `ApplicationUser.DiscoveryOptIn` defaults to
   false and is edited in Settings → Profile. The switch covers all otherwise eligible work owned by
   the account; turning it off removes the account from the next uncached response. Platform Admin
   may enable or pause the whole page and its Projects, Blogs and `#ScreenshotSaturday` sections,
   but cannot opt an author in.

3. **Existing publication state remains the item-level consent.** A project is eligible only when
   its owner opted in, `ShowcaseSlug` is set and it is not archived. A post is eligible only when its
   owner opted in, `IsBlogPublished` is true, `BlogSlug` is set and `IsPrivate` is false. In
   particular, `IsListedWhilePrivate` never qualifies a post for Discovery. Media links are written
   against the owner's tenant host so the existing media gate resolves the same owner as the page.

4. **Blogs and projects are separate lenses over one pool.** A published post with no `ProjectId`
   is an independent Blog entry. A published post whose Project has a live Showcase is a Devlog and
   links to both the post and the Project. Project-less blogs get their own column and filter; they
   are not filed under a synthetic Project. A blog card names the author and links to the blog root,
   using the latest eligible post as its preview.

5. **Project categories are a fixed public vocabulary.** `Project.DiscoveryCategory` is one of
   Games, Apps & Tools, Comics & Art, Film & Animation, Music & Audio, Hardware and Other. The owner
   chooses it on the Showcase screen; unknown or old values render as Other. The list is code because
   filters, URLs, English and Russian labels must stay in lockstep. Tags remain author vocabulary and
   are used for Blog topics instead of being forced into the Project taxonomy.

6. **`#ScreenshotSaturday` is a publication convention, not a new document type.** An eligible post
   whose comma-separated tags contain `ScreenshotSaturday` (with or without `#`, case-insensitive)
   can lead the stage when it has a cover image. Project gallery and cover images can support its
   related category rail; no private or merely uploaded asset is inspected. When there is no tagged
   post, the page promotes an eligible Project instead of showing fabricated community content.

7. **The mix is intentionally shuffled.** Each response samples recent eligible rows and shuffles
   within that bounded set; the Shuffle action adds a throwaway query value so an edge cache cannot
   return the same selection. Public responses may be cached briefly and vary by `Accept-Language`.
   Search, ranking, follows and moderation queues are separate decisions; this page starts as
   editorial discovery, not a social network.

8. **Discovery's editable public copy and section switches live in one `DiscoverySettings` row.**
   The row has bilingual title and introduction plus Enabled, ShowScreenshotSaturday, ShowProjects
   and ShowBlogs. Null copy falls back to code. Admin → Discovery edits that row and reports the
   number of opted-in authors and eligible public items. This is separate from `LandingSettings`:
   pausing a community feed is not the same act as rewriting the marketing page.

9. **The production initial-bundle error ceiling moves from 800 kB to 820 kB.** Discovery adds
   bilingual copy to the shared localization dictionary and one account-level consent signal to the
   authenticated shell; those bytes are present before its three lazy editors open. The build was
   already tracked at 742 kB against the unchanged 700 kB warning threshold in T-363. The new error
   ceiling leaves less than two percent headroom over the 805 kB measured build instead of turning a
   feature-sized localization change into a deployment failure. T-363 remains open: this records the
   present measurement and does not call the existing warning healthy.

**Rejected.** *Treat every published post as consent* — it changes the audience after publication.
*List `IsListedWhilePrivate` posts* — it makes a tenant-local teaser a platform-wide disclosure.
*Require a Project for every Blog* — it erases the independent blogs the direction explicitly keeps.
*Free-text Project categories* — spelling variants would make the public filters lie. *An Angular
Discovery screen* — the page is for strangers and search engines, like the blog and landing.

**Consequence.** The schema gains one account flag, one Project category and one platform settings
table. The Showcase editor and Profile settings gain one field each; Admin gains a Discovery tab.
The public query must always state all three gates — owner opt-in, public item state and tenant host —
and its tests must prove that private, unlisted-owner and unpublished rows never appear. The initial
bundle warning remains visible while the hard ceiling reflects this feature's measured footprint.

# ADR-224 — Blog search rides SQLite FTS5 outside the EF model (29.08.2026)

**Context.** T-176 wanted body-text search on the public blog and across the app's documents; ADR-193 had deleted the old `q=` search precisely because it only ever matched titles and tags. SQLite's answer is FTS5 — but an FTS5 virtual table cannot be described by the EF model: EF has no notion of a virtual table, and `SchemaDriftGuardTests` (EF 8's `HasPendingModelChanges()`) would either fight a table the model cannot express or force the model to lie about it.

**Decision.** The `DraftSearch` FTS5 table lives **outside the EF model entirely**:

1. It is created by a raw-SQL migration (`AddDraftSearchFts`) — hand-written `CREATE VIRTUAL TABLE` and triggers, no entity, no `DbSet`, invisible to the model snapshot, so the schema drift guard stays honest about the tables EF does own.
2. It is kept in sync by three mechanisms, each covering what the others cannot: SQLite **triggers** on the source tables catch writes that bypass the change tracker (`ExecuteDelete`/`ExecuteUpdate`); a **SaveChanges interceptor** maintains the index for tracked writes, where the composed searchable text is only known app-side; and a **startup backfill** populates rows for databases that predate the table or drifted while it was absent.
3. Reads: the public blog `/search` page (result pages `noindex`), `GET /api/search/drafts` for the app, and the Ctrl+K overlay in the bench shell. Every query joins back through the real tables, so the tenant owner filter and the blog's visibility rule stand on search exactly as on the index — search must never surface a private post the index would hide.

**Consequence.** Full-text search over titles and bodies with no new infrastructure — the database it already has does the searching. The price is stated plainly: the migration is hand-written SQL that EF will never regenerate, and index correctness rests on triggers, interceptor and backfill agreeing — three mechanisms instead of one, each with a reason to exist. Snippet/term highlighting via FTS5's `snippet()` is deferred (T-321), not forgotten.

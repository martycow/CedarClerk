# ADR-120 — Скин «Лесная мастерская»: измерение data-skin, ортогональное теме (18.08.2026)

Оформление получает вторую ось: `data-skin="forest"` на `<html>`, ортогонально существующему `data-theme="light|dark"`. День = forest+light, ночь = forest+dark. `ThemeService` держит `skin` signal (сигнал) по тому же образцу, что и `theme`: localStorage `cedar-skin`, применение в конструкторе — логин-страница уже в скине до авторизации. Для стандартного скина атрибут **отсутствует**, а не равен `default`: `:root[data-skin="forest"]` тогда просто не матчится, и дефолт не может измениться ни на пиксель.

Весь скин — CSS: `src/styles/_forest.scss`, каждое правило под `:root[data-skin="forest"]` (ночь — `[data-theme="dark"]` сверху). Ключевое решение ночи: **бумага остаётся кремовой, темнеет только «дерево»** — поэтому ночной блок обязан переопределить каждый токен, который тёмная тема переворачивает в светлый-на-тёмном (текстовые ярусы, статусы, series, glass), иначе выигрывает по порядку исходника блок `:root[data-theme="dark"]` той же специфичности. Инжектируемый акцент пользователя (`AppearanceService.applyAccent`) перебивается специфичностью, а не порядком — поэтому сосна не перекрашивается сохранённым пресетом.

Шрифты (Vollkorn/Source Sans 3/Literata/Caveat) — self-hosted через @fontsource, латиница+кириллица повесово. Подключены безусловно, но `@font-face` скачивает файл только когда семейство реально использовано в отрендеренном тексте, а ссылаются на него только правила под скином — стандартный скин не грузит ни байта шрифтов.

`tools/check-contrast.mjs` парсит только два базовых блока `styles.scss` и скин-блоков не видит (партиал он не читает); контраст лесных пар проверен вручную по худшим поверхностям (--t2 на --canvas, крем на сосне ночью, rail-ink на тёмной планке).

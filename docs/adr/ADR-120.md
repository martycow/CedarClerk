# ADR-120 — "Forest Workshop" skin: a data-skin dimension orthogonal to the theme (18.08.2026)

The look gains a second axis: `data-skin="forest"` on `<html>`, orthogonal to the existing `data-theme="light|dark"`. Day = forest+light, night = forest+dark. `ThemeService` holds a `skin` signal following the same pattern as `theme`: `cedar-skin` in localStorage, applied in the constructor — the login page is already in the skin before authentication. For the standard skin the attribute is **absent**, not equal to `default`: `:root[data-skin="forest"]` then simply does not match, and the default cannot change by a single pixel.

The whole skin is CSS: `src/styles/_forest.scss`, every rule under `:root[data-skin="forest"]` (night — `[data-theme="dark"]` on top). The key decision for night: **the paper stays cream, only the "wood" darkens** — so the night block must override every token that the dark theme flips to light-on-dark (text tiers, statuses, series, glass), otherwise the `:root[data-theme="dark"]` block wins by source order at the same specificity. The user's injected accent (`AppearanceService.applyAccent`) is overridden by specificity, not by order — so the pine is not repainted by a saved preset.

Fonts (Vollkorn/Source Sans 3/Literata/Caveat) — self-hosted via @fontsource, Latin+Cyrillic per weight. Connected unconditionally, but the `@font-face` only downloads the file when the family is actually used in rendered text, and only skin rules reference it — the standard skin loads zero bytes of fonts.

`tools/check-contrast.mjs` only parses the two base blocks of `styles.scss` and does not see the skin blocks (it does not read the partial); the contrast of the forest pairs was checked by hand against the worst surfaces (--t2 on --canvas, cream on pine at night, rail-ink on the dark rail).

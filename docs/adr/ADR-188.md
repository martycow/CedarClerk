# ADR-188 — Fullscreen is the window's, not the writer's: it moves to the rail (22.08.2026)

**Context.** The fullscreen control is an unlabelled icon at the tail of the editor's tool strip,
beside the retry button and the paragraph-marks toggle, and it exists on that one screen only.
Marty: *the fullscreen button should be more visible and be somewhere else*; asked where, he chose
the rail, beside the account.

Two things are wrong with where it was. It is drawn as a bare glyph in a strip whose every other
glyph is a document command, so it reads as one — and it acts on the **window**, which is not a
property of the document, the selection, or the sheet. And it is editor-only for no reason: the
browser's fullscreen applies to the whole app, and the list, the board and the hub are exactly as
worth reading without browser chrome as the writing sheet is.

**Decision.**

1. **The control moves to `RailHeader`'s default slot**, immediately before the account plaque, and
   is drawn as a **paper-faced button at the chrome box** (`variant="paper" surface="chrome"`,
   ADR-175) with an icon — the same face the pre-auth pages already give their theme toggle. That
   is the "more visible": a face and an edge instead of a bare glyph.

2. **It belongs to the shell, not to a page.** `isFullscreen`, the `fullscreenchange` listener and
   `toggleFullscreen` move from `editor.component` to `bench-shell.component`, so it works on every
   screen inside the shell and there is one copy of the state.

3. **It is not published through `RailActionsService`.** That service is how a *page* hands the rail
   its one primary action (ADR-159), and this is the shell's own control — routing it through the
   page channel would make every page responsible for re-publishing a window property it does not
   own.

**Rejected.** *The worktop's chalk edge.* It is the strip above the sheet, which is the editor's
again — the same mistake one row up. *The rule.* `RulerBar` is read-only by design and offers no
slot; a control there is the invitation ADR-184 keeps refusing. *Leaving it in the strip with a
caption.* It answers "more visible" and not "somewhere else", and it leaves a window control among
document commands.

**Consequence.** The rail's right end now reads: save state, the page's primary action, fullscreen,
account — three things about the screen and one about the account, which is the order they are read
in. The editor's strip tail loses its second non-command glyph (the first, paragraph marks, went to
Appearance), leaving only the save-retry button, which is a command and is only drawn when a save
has actually failed.

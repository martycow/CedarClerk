# ADR-156 — The touch floor is inherited, not selected

**Context.** ADR-138 splits the app into two density surfaces and gives each a hit-target floor:
44px on paper, 30px in chrome. Under `@media (pointer: coarse)` it raised controls to those floors
with a selector that pins the surface — `[data-surface="paper"] button { min-height: var(--hit-target) }`
beside a chrome twin — and item 5 of that entry explains the outcome as equal specificity leaving
source order to decide.

Bench nests the two surfaces inside each other, in both directions. The shelf sheet is paper inside
chrome; the ruler is chrome on paper; a shelf panel on the worktop sheet is chrome inside paper
inside chrome. A descendant selector cannot say *nearest*: `[data-surface="chrome"] button` matches a
button three levels below a chrome ancestor just as strongly as one directly inside it, so where the
two selectors both match, the one written later wins regardless of which surface the control is
actually sitting on. Measured in real Chromium with `hasTouch: true`, reading resolved `min-height`
rather than box height: `sheetBtn`, `topBtn` and `drawerBtn` each owe 44 and each stood at **30**.

**Two obvious repairs were measured and both fail.** Swapping the block order fixes those three and
breaks the other direction — `rulerBtn` and `deepBtn` owe 30 and go to **44**; it moves the same
source-order answer onto the other nesting. Excluding descendants of the opposite surface
(`:not([data-surface="paper"] [data-surface="chrome"] *)`) fixes four and leaves `deepBtn` matching
**neither** block, standing at 20px — no floor at all, which is worse than the defect.

**Decision.** The floor is carried by a custom property, which is the one thing in CSS that does
resolve to the nearest declaring ancestor, at any depth, in either direction:

```scss
[data-surface="paper"]  { --hit-surface: var(--hit-target); }
[data-surface="chrome"] { --hit-surface: var(--hit-chrome); }

[data-surface] button, … { min-height: var(--hit-surface); min-width: var(--hit-surface); }
```

The two declaring selectors are mutually exclusive on a single element, so source order can never
arise between them. Per-member specificity is unchanged — `[data-surface] button` is (0,1,1), the
same as the selector it replaces — and deliberately not written with `:is()`, which would raise a
bare `button` to (0,2,1) and silently change which component rules it outranks.

All seven nestings measured after the change: `pageBtn` 44, `railBtn` 30, `sheetBtn` 44, `topBtn` 44,
`rulerBtn` 30, `drawerBtn` 44, `deepBtn` 30 — each its own surface's contract, none its ancestor's.

**Consequence.** A control outside any `[data-surface]` gets no floor, exactly as before; the
attribute is still what turns the rule on, and ADR-138's note that a missing attribute fails quietly
still stands. Four page stylesheets carried the same pinned-surface anti-pattern with a bare `44px`
in place of the token; they move onto `[data-surface] .x { min-height: var(--hit-surface) }` too.
`[data-surface="paper"] .row-actions { gap: … }` is left alone: the rule below governs the floor and
says so.

**It is enforced.** `tools/check-density.mjs` gains rule 7: under `@media (pointer: coarse)` no
`min-height`/`min-width` may come from a selector that pins a surface *value*, and every floor must
be `var()` of a property **both** surfaces declare, each resolving to its contract number. Verified
to go red on the code that shipped the defect, naming both blocks by selector and line, and on both
of the rejected repairs above, including the `:not()` one. Rule 6 is unchanged in what it checks.

The measurement lives in `cedarclerk-web/e2e/17-density.spec.ts` under `test.use({ hasTouch: true })`:
it asserts `pointer: coarse` actually matched before measuring anything, builds all seven nestings in
the page — the invariant belongs to `styles.scss`, not to whichever component nests today — and a
second test holds the fixture to the shipped shell so the two cannot drift. The unit runner cannot
reach it: `min-height` comes back `""` with `var()` unsubstituted, `window.matchMedia` does not
exist, and `getComputedStyle` returns a custom property only on the element that declared it. Rather
than a silent skip, `shelf-panel.component.spec.ts` carries a checked exception that goes red the day
the runner grows either ability, so the measurement can come home.

Supersedes item 5 of ADR-138 and the "paper qualifier" clause of its item 7. The two floors, the two
surfaces and the named WCAG 2.5.5 exception inside chrome are unchanged — only the mechanism that
applies them.

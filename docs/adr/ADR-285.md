# ADR-285 — A dialog leaves through Escape, the ✕ or an action; the scrim is not a button (T-043)

**Context.** `T-043` asked for one popup behaviour: every modal dims the page and closes only via
✕ or an action. Measured against the tree, the app has one dialog shell, `shared/modal.component`,
and every page dialog is an `app-modal` — the editor's insert/footnote/table/formula/translate/
version dialogs, the drafts page's new-document and evergreen dialogs, the posts manager's
confirms, the builds and sprint modals, the admin account modal. The shell dims the page with
`--scrim`, emits `closed` on Escape from the top layer only, and — the one thing the row was about —
also emitted `closed` for any click on the scrim, with the card stopping propagation so a click
inside stayed inside.

Three other fixed layers exist and none is a dialog: the Ctrl+K search palette, the debug console
and the feedback panel are the shell's transient overlays (ADR-246, one at a time, closed by
`OverlayCoordinatorService` when a page modal opens). The editor's `.term-menu` is a context menu
over a selection, `.wiki-suggest` a caret popover, `.ai-toast` a toast. `app-popover` is a popover.
Each of those is *meant* to vanish on an outside press, because none of them holds a decision.

**Decision.**

1. **A click on the scrim does nothing.** The overlay's `(click)` handler and the card's
   `stopPropagation` are gone. A dialog is on screen because something asked a question or opened
   a form; a stray press outside the card — reaching for the scrollbar, a mis-aimed tap on a
   phone — must not take a half-typed footnote or a delete confirm away. What closes a dialog is
   the ✕, one of its own actions, or Escape.
2. **Escape stays, and stays scoped.** Escape is the keyboard's ✕ and closes only the top layer
   (the coordinator's layer lease, ADR-246, answers for the stacked case). It is the one
   dismissal a dialog owes a keyboard user, and it is deliberate in a way a scrim click is not.
3. **The rule is the shell's, so it holds for every dialog at once.** No page wires its own scrim;
   a page that wants a dialog uses `app-modal` and gets this behaviour without a line. The test on
   the shell asserts both halves: a scrim click leaves `closed` silent, Escape fires it once.
4. **Transient shell layers and popovers keep click-away.** The search palette, the debug console,
   the feedback panel, popovers, the context menu and the suggester are not dialogs: they carry no
   pending decision, and an outside press is how a palette is put down. ADR-246's mutual exclusion
   is untouched — a page modal still dismisses whichever of them is open and blocks a new one
   while it stands.

**Rejected.** *Closing on scrim click with a "dirty" check*, which needs every dialog to say what
dirty means and is the per-dialog wiring clause 3 exists to avoid. *Removing Escape too*, which
would leave a keyboard user with a ✕ they have to Tab to. *Applying the rule to the shell
overlays*, which would make Ctrl+K a palette that traps you — the opposite of what a palette is.

**Consequence.** One behaviour for every dialog in the app, enforced by the shell's own spec rather
than remembered per page. The `ModalComponent` comment says the rule; the inventory's `app-modal`
row says it; a dialog that needs click-away is a popover and should be built as one.

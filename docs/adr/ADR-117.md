# ADR-117 — Desktop became a client of the cloud: one database, a local agent only for the disk (12.08.2026)

**Supersedes ADR-105** entirely (there are no longer two modes) and **ADR-108** (upstream authentication was a stopgap for the local database). **Refines ADR-107** regarding who bypasses the disk.

**Context**: Marty's request. ADR-105 left desktop with its own database and an explicit mode choice, ADR-108 glued identity together but not data — and honestly warned that "one identity, not one set of data" makes the confusion **stronger**, not weaker. A day into operation Marty put exactly that prediction into his own words: "I use the same email in desktop, but it's effectively a different account." The request: everything syncs with the cloud, but assets are never uploaded — at most auto-previews, which get replaced once indexed; on desktop, access to the real files, in the browser only previews marked as a fingerprint.

**Decision 1: don't sync — remove the second copy.** The desktop window loads `cedarclerk.mooexe.dev`, there's one database — the cloud one. Local mode is removed, not left as a second option.

This isn't abandoning ADR-105's caution but removing the task it was afraid of. Two-way merging of offline TipTap edits is CRDT or losing someone else's edits, and the project has already been through a text-loss incident (`T-060`, three guards ADR-065/066/067 around it). A single database means there's nothing to merge: there's nowhere to edit except the cloud. **The right conclusion from ADR-105 was never "sync is dangerous" but "there shouldn't be two copies"** — at the time it chose a second instance as the lesser evil, because the asset index required a local process; now only the process stays local, not the data.

**Decision 2: the local process stays, but becomes a filesystem agent, not a server.** `CedarClerk.Server.exe` with `Cedar:Agent=true` doesn't bring up Identity, migrations, the bot, or the SPA — only `/agent/*`: walking a folder, stat'ing a single file, generating JPEG previews.

It stays a .NET process rather than moving to Node for one verifiable reason: it already contains the `.blend` preview parser (Marty's direct request, `CedarClerk.Core/BlendThumbnail.cs`) and ImageSharp's coverage of TGA/TIFF/QOI/PBM/WEBP. Rewriting that in JS is weeks of work and a second set of format bugs, just to save the 70 MB of distributable size that ADR-104 already agreed to pay.

**Decision 3: the agent reads the disk, the page sends.** Asset and preview records travel to the cloud via requests from the **page**, which already has a cookie session — not from Electron. So the agent needs no credentials at all, and Electron doesn't handle authorization at all. The side benefit matters more than the savings: the work becomes observable and cancelable through the ordinary UI, rather than an invisible background process you can't ask what it's doing.

**Decision 4: the ability to walk the disk disappears from the hosted server entirely, rather than being switched off by a flag.** `Cedar:AssetIndex:Enabled` and the `POST/GET/DELETE .../assets/index` endpoints are removed; in their place — import (`PUT .../assets/source`, `POST .../assets/batch`, `POST .../assets/sweep`).

This is a hardening of the boundary that ADR-107 (refinement 1) held with a flag. The dangerous capability was "the server enumerates its own disk at a tenant's request"; now that code physically exists only in the agent, meaning it's absent in production rather than dormant behind a config setting. Accepting a list of names from the owner is not a dangerous capability — it's ordinary data writing. The flag was removed precisely because there's nothing left to guard: the capability is determined by whether the client has the bridge, not by a server config.

An open write channel still needs ceilings, and they're stated as numbers, not as "reasonable values": ≤500 rows per batch, ≤200,000 rows per project, `RelativePath` ≤1024 characters with rejection of `..` and absolute prefixes, ≤256 KB per preview with JPEG magic-byte verification.

**Decision 5: previews are generated and uploaded for everything, with no limit for the author — but with a system-side ceiling.** This departs from "on demand, not during the scan" (ADR-107, addendum T-140), made by Marty's direct choice after the cost was stated: a folder with 20,000 images is 20,000 decodes and ~600 MB.

Three things make this workable, and without any one of them the decision would be irresponsible:
- **The pass is resumable and idempotent.** `GET .../assets/thumbs/pending` returns whatever has `ThumbnailForModifiedAt != ModifiedAt` — meaning a break at file 8000 costs a continuation, not a repeat, and the pass can be caught up later, separately from the scan.
- **The `Cedar:AssetIndex:ThumbBudgetBytes` ceiling** (default 2 GB per owner) fails with text naming the number. "No limit" is about the author having no limit, not about the droplet with 45 GB free disk having no ceiling. Silently filling the disk would be a denial of service, not generosity.
- **A counter in the UI shows files and megabytes.** A long pass with no numbers is indistinguishable from a hang, and that's the one and only reason progress is mandatory here rather than nice-to-have.

`ThumbnailForModifiedAt` is reused, not duplicated: the meaning "this preview matches this version of the file" hasn't changed, only the source of the bytes has.

**Decision 6: disk access is granted to a remote origin, and that's a real cost, not a formality.** The window used to load `127.0.0.1`; now it loads `cedarclerk.mooexe.dev`, and the SPA renders TipTap documents plus user-pasted HTML. **An XSS on the domain turns into reading a chosen folder.** This is recorded here as an accepted risk, not a solved problem.

What narrows it, each on its own separate basis:
- **`shell.openPath` is not part of the bridge** (Marty's choice). `showItemInFolder` highlights a file in the file explorer and launches nothing — that's the difference between reading and executing, and it's worth giving up double-click-to-open on a `.blend` for.
- **The agent's bearer token** — 32 random bytes per launch, passed by the shell through the environment. Without it, a local HTTP server that can enumerate any folder is open to any process on the machine and any page in any browser. Today's sidecar was closed off by the Identity cookie; the agent, which has no Identity, needs its own lock.
- **Only granted roots.** A root is handed to the agent by the main process only after an OS dialog — that is, after a gesture from Marty. A compromised renderer can't ask for `C:\Users\marty\Documents`.
- **Preload gated by origin**, and navigation outside the upstream is blocked: the bridge isn't reachable by a page that arrived from anywhere else.

**Decision 7: the window loads `/projects`, not `/`.** The landing page intercepts exactly `GET /` without a cookie (`LandingEndpoints.UseLanding`), so any other path serves the SPA — meaning `Cedar:Desktop` is no longer needed to bypass the landing page. This also removes the bug Marty found on 10.08.2026 (the app opened on the marketing pricing page), not with a flag, but by choosing the address.

**The cost that has to be said out loud: without a network connection, desktop doesn't work at all.** Local mode was the only offline scenario, and it's removed. A thirty-day cookie saves you from logging in again, but not from having no network. This is a direct consequence of Decision 1, and it's acceptable precisely because Marty's working machine is constantly online, and the alternative is exactly the mess this ADR was written to fix.

**`ApplicationUser.RemoteUserId` remains a vestigial column.** All of the `UpstreamAuth` code was removed, the column wasn't: dropping a column in SQLite means rebuilding `AspNetUsers`, and Identity touches that table on every authorized request (the "no such column" incident from `.claude/rules/ef-migrations.md`). Zero benefit against non-zero risk on a live database.

**What this closes and voids**: `T-121` (the second mode from ADR-105 — done not as a mode but as the only one) and `T-137` (the desktop database has no backup — there's no longer a database, so the line is moot, not done).

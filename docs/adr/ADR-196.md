# ADR-196 — Compact controls stay reachable and long collections scroll or page

**Context.** Several annotated screens spend desktop height on controls or collections rather than
content: small toolbar buttons draw at the full paper-control height, popovers can leave the viewport,
the statistics range uses a precision slider for six common choices, and unbounded Glossary and credit
activity lists keep growing.

**Decision.**

1. `size="sm"` is a real 30px desktop button on paper as well as chrome. Coarse pointers still receive
   the global 44px touch floor. Medium paper controls remain 38px.
2. Shared modals keep their header and actions visible while the body scrolls. Shared popovers are
   clamped to the viewport and give long contents their own scrollbar. Dropdowns and menus therefore
   never rely on page overflow to remain reachable.
3. Statistics period selection becomes a compact discrete select for 7, 14, 30, 60, 90, or 180 days.
   ADR-149's free-range slider is superseded. The latest-reading time names the configured display
   timezone explicitly.
4. Glossary uses server paging and reports the languages available for every term. Credit activity
   uses server paging, and consecutive rows with the same reason and timestamp are combined into one
   displayed activity with a quantity and summed delta.
5. AI operations and other long-running jobs render in an independent modal overlay with progress and
   cancellation. They do not shift or cover the document workspace inline.
6. Owner-facing registration-form results resolve question and option labels in the current UI
   language when that language exists in the form.

**Consequence.** Desktop density follows the supplied Cedar Bench component sizes without reducing
touch accessibility. Collection size is bounded at both transport and layout layers, and a long-running
operation has one stable, dismissible visual home.

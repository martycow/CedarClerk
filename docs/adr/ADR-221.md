# ADR-221 — The project switcher keeps the open screen (29.08.2026)

**Context.** The rail's project switcher (ADR-186) linked every entry to `['/projects', id]` — the hub. Standing on project A's Assets and picking project B landed on B's hub, and the reader walked back to Assets by hand. For anyone comparing the same screen across projects — the whole point of a switcher — that is a wrong turn on every switch.

**Decision.** The switcher derives the open child segment from the current path — one of `assets | tasks | planner | builds | canvas | showcase` — and every entry links to that same screen on its own project. Deeper paths fold to the child: `canvas/:boardId` becomes `canvas`, because a board id means nothing on another project and the boards list is the honest landing. No child open (the hub itself, or a non-project screen) keeps the old target, and "All projects" still goes to `/projects`. No page changes ride along: every project page already refetches off `paramMap`, so the switch is a navigation, not a reload.

**Consequence.** `/projects/A/assets` → pick B → `/projects/B/assets`, list already showing B. The set of carried segments is a named constant (`PROJECT_CHILDREN`) rather than "everything after the id", so a future child screen opts in explicitly — a screen whose state cannot survive a project change (like a board) is folded rather than carried broken.

# ADR-121 — `cedar run`: локальная проверка настоящей сборки (18.08.2026)

Марти попросил команду, которая собирает фронт и бэк локально и открывает всё в браузере. До неё «посмотреть на изменение целиком» значило либо два терминала (`dotnet run` + `ng serve`), либо чужой сценарий (`e2e.ps1 -Serve` — скретч-база, не твои данные).

**Решение 1: обслуживается публикация, не исходники.** `cedar run` = тот же `BuildPipeline` с `NoDesktop`, затем `dotnet CedarClerk.Server.dll` из `publish/` — один Kestrel на 8080, Angular из его `wwwroot`, ровно то, что уедет на дроплет. Проверяется артефакт, а не дев-сервер.

**Решение 2: данные — дев-база.** `CEDAR_DATA_DIR` указывает на `CedarClerk.Server/data`, ту же базу, что у `dotnet run`. Без этого база жила бы в `publish/` и стиралась каждой сборкой. Скретч-вариант уже есть — `e2e.ps1 -Serve` — и не дублируется.

**Решение 3: бот выключен принудительно, пробелом.** Ребёнок получает `Cedar__BotToken=" "` — один пробел. `IsNullOrWhiteSpace` в `TelegramBotService` читает это как «токена нет», а пустая строка не годится: `SetEnvironmentVariable(x, "")` на Windows УДАЛЯЕТ переменную, и глобально экспортированный токен прошёл бы насквозь — тот самый 409 из `.claude/rules/telegram-bot.md` (инцидент 26.07.2026 с PowerShell — та же ловушка). Строка «bot is disabled» из лога сервера показывается как доказательство, по правилу «строка в логе — единственное доказательство».

**Решение 4: занятый 8080 — отказ, не убийство.** Если `/api/health` уже отвечает, команда называет версию и окружение отвечающего и останавливается. Чужой процесс (обычно `dotnet run`) — не её собственность.

**Решение 5: сервер — ребёнок на переднем плане.** Ctrl+C останавливает команду, и раннер убивает дерево процессов (то же поведение отмены, что везде) — осиротевших Kestrel не остаётся. Ничего не демонизируется, `cedar` не становится менеджером сервисов (граница ADR-118 не двигается).

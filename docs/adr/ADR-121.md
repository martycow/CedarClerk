# ADR-121 — `cedar run`: local verification of the real build (18.08.2026)

Marty asked for a command that builds the frontend and backend locally and opens the whole thing in a browser. Before it, "look at the change as a whole" meant either two terminals (`dotnet run` + `ng serve`) or someone else's script (`e2e.ps1 -Serve` — scratch database, not your data).

**Decision 1: what gets served is the publish output, not the sources.** `cedar run` = the same `BuildPipeline` with `NoDesktop`, then `dotnet CedarClerk.Server.dll` from `publish/` — one Kestrel on 8080, Angular from its `wwwroot`, exactly what will ship to the droplet. What gets checked is the artifact, not the dev server.

**Decision 2: data — the dev database.** `CEDAR_DATA_DIR` points at `CedarClerk.Server/data`, the same database `dotnet run` uses. Without this the database would live in `publish/` and get wiped by every build. The scratch variant already exists — `e2e.ps1 -Serve` — and is not duplicated.

**Decision 3: the bot is forcibly disabled, with a space.** The child process gets `Cedar__BotToken=" "` — a single space. `IsNullOrWhiteSpace` in `TelegramBotService` reads this as "no token", and an empty string won't do: `SetEnvironmentVariable(x, "")` on Windows DELETES the variable, and a globally exported token would pass straight through — the very same 409 from `.claude/rules/telegram-bot.md` (the 26.07.2026 PowerShell incident — the same trap). The server log's "bot is disabled" line is shown as the proof, per the rule that "the line in the log is the only proof".

**Decision 4: a busy 8080 — a refusal, not a kill.** If `/api/health` already answers, the command names the version and environment of whoever is answering and stops. A foreign process (usually `dotnet run`) is not its property.

**Decision 5: the server is a foreground child.** Ctrl+C stops the command, and the runner kills the process tree (the same cancellation behavior as everywhere else) — no orphaned Kestrel is left behind. Nothing is daemonized, `cedar` does not become a service manager (the ADR-118 boundary does not move).

# ADR-142 — One icon runtime: the generated Phosphor set behind `app-icon`

**Context.** Cedar Bench arrives with an icon runtime of its own. `.design-sync/ds-v2/assets/bench-icons.js` defines two custom elements, `cc-icon` and `cc-logo`, holding 36 hand-drawn stroke glyphs on a 16px grid; `components/scenery/Icon.jsx` is a thin React wrapper that injects that script into `<head>` on import. The app already has a runtime: `cedarclerk-web/tools/icon-map.json` (96 rows resolving to 94 distinct Phosphor names) feeds `tools/generate-icons.mjs`, which writes `src/app/shared/icon-data.generated.ts` (94 icons × 2 weights), rendered by `src/app/shared/icon.component.ts`. `icon-usage.generated.ts` records the result: 76 distinct icons across 239 call sites, excluding the two dev pages. `shared/cedar-logo.component.ts` (`app-cedar-logo`) and `shared/brand-icon.component.ts` cover the two marks a general set never carries. The mirror offers the drop-in in the opposite direction — its comments invite replacing `bench-icons.js` with "the Cedar Clerk app's own generated Phosphor set (`assets/cedar-icons.js`)" — a file that does not exist and, under ADR-072, never will: the app's set is a build-time TypeScript constant, not a script that defines an element.

**Decision.**
1. **`app-icon` and the generated Phosphor set stay the app's only icon runtime.** `bench-icons.js` and `Icon.jsx` are reference material: read them to learn which glyph a bench component wants, then bind `app-icon` to the Phosphor name. Nothing from `.design-sync/` is loaded at runtime.
2. **A glyph the design wants and the set lacks goes through `tools/icon-map.json`** and `npm run icons:generate` — which regenerates `icon-data.generated.ts` and `icon-usage.generated.ts` together — with both generated files committed. There is no second path, and in particular `Icon.prompt.md`'s advice ("draw an inline stroke SVG on the same 16px grid") does not port: an inline SVG is a second runtime with one call site, and the next one makes it two.
3. **Six of Bench's 36 names have no counterpart among the map's 94 targets** and need rows, each verified present in `@phosphor-icons/core/assets/regular/`: `magnifying-glass` (bench `search`), `dots-three` (`dots`), `chart-bar` (`chart`), `flag` (`sprint` — the bench glyph is a pennant on a staff, not a timer), `text-h` (`heading`), `tree-evergreen` (`tree` — the map's `tree-structure` is a hierarchy diagram, not a conifer). The other 30 already resolve: 13 exist verbatim, 17 are renames onto entries the map carries.

**Rejected: shipping `bench-icons.js` as the app's set.** ADR-072 turned down `@phosphor-icons/webcomponents` for precisely the mechanism this file uses — a custom element forces `CUSTOM_ELEMENTS_SCHEMA` on every component that renders an icon, which switches off Angular's template type-checking for that component's *whole* template, not merely the icon tag. Bench would charge that price for a strictly smaller set: 36 glyphs against 76 in use, so the editor toolbar alone outruns it.

**Rejected: running both**, bench's element inside bench components and `app-icon` everywhere else. That gives two answers to "which glyph means archive", two failure modes, and two grids in the same viewport; it also blinds `generate-icon-usage.mjs` to half the app, and that scan is the only reason `/dev/icons` can be trusted at all (ADR-075).

**Consequence.** A missing glyph costs a map row, a regeneration and two committed generated files instead of one line of SVG. That friction is deliberate, and it is also real — someone in a hurry will be tempted, which is why this is a rule.

The failure it guards against is worse than the friction. `icon.component.ts` resolves `ICONS[this._weight()][this._name()] ?? ''`, so a name the set does not hold renders an **empty `<svg>`: nothing, silently**, with no console error and no fallback glyph. `strictTemplates` catches a bad literal, since `IconName` is a generated union — but not a name arriving through the `Record<…, IconName>` tables in `core/asset-index.service.ts:18`, `core/projects.service.ts:26` and `:35`, and `core/tasks.service.ts:21`, which is exactly where server data becomes an icon name. Bench's runtime fails differently (`P[name] || P.info` draws the info glyph), so a name lifted from a kit can render in the mirror and render blank in the app. That asymmetry is why the missing-glyph path needs a written rule rather than a preference.

The optical match is given up with eyes open. Bench draws on a 16px viewBox at stroke-width 1.4; Phosphor is a 256 viewBox filled with `currentColor` and sized from `--icon-xs/sm/md/lg` — 13/17/20/24 at `styles.scss:154-157` against bench's 13/16/20/24. Bench components will read slightly heavier and a step larger at `sm` than the kits do, and the only alternative on offer is redrawing 94 glyphs.

# ADR-265 — The production Angular build is a `cedar test` phase (05.09.2026)

**Context.** `cedar test` ran five phases by default — backend, frontend units, icon inventory,
contrast contract, density contract — and every one of them reads source. Nothing in the runner
produced a production bundle. `--smoke` starts the Angular *dev* server through `ng serve`, which
is precisely the compiler that tolerates what the production build rejects. So a build-only
regression — a bundle over the ADR-251 ceiling, a template error the dev build lets through, a
chunk that fails to lazy-load — stayed invisible to the project's own runner until `cedar deploy`
hit it, after the branch guard, at the moment the maintainer had decided to ship. T-362 asked for
either a sixth phase or a stated decision that the build belongs to the deploy alone.

**Decision.** `ng build` is the sixth default phase of `cedar test`, named *Production build
(ng build)*. It runs the same invocation `BuildPipeline` uses for the web build —
`BuildPipeline.AngularBuild()` is one method both call — so what the test run proves is what the
deploy ships, and a second command that could drift does not exist.

Order: the five source-reading phases first, the build after them, the smoke suite last and still
only under `--smoke`. A template that fails to compile goes red in about a minute this way rather
than after the browser run has spent five. The phase belongs to the frontend half of the selector:
`--frontend` runs it, `--backend` does not.

`--smoke` does not skip the build phase. The smoke harness never builds a production bundle — it
starts `ng serve` for Playwright — so there is no duplicate work to avoid, and the dev compile it
does run is not evidence of anything this phase checks.

**Rejected.** *Leave the build to the deploy* — the deploy is the last place to learn that the
front end does not compile, and it refuses to run from a feature branch, so the failure could not
even be reproduced where the work was done. *Skip the phase under `--smoke`* — it would trade a
minute of `ng build` for a run that proves less. *A separate `cedar build --check`* — a check that
has to be remembered is a check that is not run; the whole point of `cedar test` is one command.

**Consequence.** A bare `cedar test` takes about a minute longer and answers a question it could
not before. The grid draws nothing for this phase — `ng build` names no tests — and the verdict
row reads "no results parsed" with the phase's own exit code, which is the design of ADR-118
decision 8: the exit code decides, the grid only illustrates. `docs/tech/QA.md` and the Key
commands table in `AGENTS.md` list six default phases, seven with `--smoke`.

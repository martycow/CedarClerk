# ADR-056 — NF1: post templates as a `Draft.IsTemplate` flag, not a parallel entity
**Context** (28.07.2026): idea/NF1 — "a preset authored in the editor, named like a draft but not a post." `docs/BACKLOG.md` already recorded the cheapest-honest-shape call: a flag on `Draft` plus filtering, since the editor, autosave and every export already work on `Draft` unchanged.

**Decision**:
- **`Draft.IsTemplate`** (migration `AddDraftIsTemplate`), toggled through `POST /api/drafts/{id}/template` — same one-endpoint-one-bool-body shape as the existing `/private` endpoint, not the two-endpoint `/archive`+`/unarchive` shape, since there's no asymmetry here worth two routes.
- **A template is edited exactly like any other draft** — same editor, same autosave, same `.cedar`/`.zip` export. Nothing about content-authoring changes; only `/drafts`' own filtering changes.
- **`/drafts` gets a `template` filter tab**, and every *other* filter (`draft`/`scheduled`/`published`/`attention`/`archived`, plus the default) now excludes `IsTemplate` rows. A template is never itself scheduled or published in practice, but excluding it explicitly means marking a draft as a template immediately moves it out of the main list rather than leaving it to coexist confusingly in both places.
- **No "new draft from this template" duplication flow.** Scope was deliberately capped at "a flag plus filtering," per Marty's own framing — a template today is authored, kept out of the way in its own tab, and copy-pasted by hand when its content is wanted elsewhere. Building a one-click "duplicate into a fresh draft" action was a natural next step but is a separate, larger piece of work (a generic draft-duplication endpoint doesn't exist at all yet) and wasn't asked for.
- **No relation to `NewDraftTemplate`/`NEW_DRAFT_TEMPLATES`** (the new-draft dialog's built-in blank-content starting points, e.g. "blank"). Same English word, unrelated concepts — one is a hardcoded starter snippet picked at creation time, the other is a real, user-authored `Draft` row flagged after the fact. Naming collision noted here so a future session doesn't conflate them.

**Consequence**: `DraftMeta` (frontend) and the two `/api/drafts` list projections (backend) all carry `isTemplate`. `dotnet build`/`ng build`/`ng test` clean; no new Core renderer surface (a template's content renders exactly like any draft's, since nothing reads `IsTemplate` outside of `/drafts`' own filtering and the toggle endpoint). Not yet live-verified in a browser; the migration has not been applied against production.

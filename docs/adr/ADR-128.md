# ADR-128 — Дерево документов и wiki-links: структура ГДД (18.08.2026)

**Context.** T-181 (Phase 13): ГДД {game design document} — не плоский список, а дерево («Геймплей → Боёвка → Оружие») с перекрёстными ссылками между документами. Сегодня у Draft есть только папка (плоский фильтр) и проект; ни иерархии, ни ссылок «этот документ упоминает тот» нет. Решение Марти — обе половины сразу: дерево И wiki-links с backlinks.

**Decision — дерево.**
1. **`Draft.ParentDraftId (Guid?)` + `Draft.SiblingOrder (int, default 0)`** — прямо на Draft, без отдельной таблицы: узел дерева и есть документ. Корень = `ParentDraftId is null`. **Папка ≠ дерево**: папка остаётся плоским фильтром списка, дерево — структурой; в tree-view фильтр папки отключён, потому что показать «поддерево, отфильтрованное папкой» честно нельзя — родитель может не пройти фильтр.
2. **`PUT /api/drafts/{id}/parent {parentId, beforeId?}`**: owner-чек обоих концов, **cycle-guard** проходом по предкам (перенос под собственного потомка → 400), **глубина ≤ 10** (структуре ГДД хватает, UI не деградирует), перенумерация нового набора сиблингов 0..n (splice перед `beforeId`, иначе в конец).
3. **Удаление узла поднимает детей к деду** одним UPDATE (`ParentDraftId = удаляемого.ParentDraftId`) — поддерево не удаляется каскадом и не сиротеет: документы ценнее структуры.
4. **Tree-view — третий вид `/drafts`** рядом с таблицей и карточками; раскрытие — клиентский Set. v1-контролы: меню строки «Переместить…» (пикер родителя) и кнопки вверх/вниз; drag&drop — только если останется время (у cdk нет tree drop-list, самодельная математика — главный риск сессии в последней задаче). **Хлебные крошки** в редакторе строятся по предкам из уже загруженного списка, клик открывает документ напрямую.

**Decision — wiki-links.**
5. **Нода `wikilink` — inline atom `{draftId, label}`** (по модели footnote-node + stopEvent из image-node): ссылка по id, не по имени — переименование цели не ломает связь; label — снапшот имени на момент вставки. Триггер `[[` через `@tiptap/suggestion@^3.27.2` (семейство TipTap 3.27, как остальные extensions); поповер самодельный по clientRect; источник — клиентский фильтр по загруженному списку драфтов (серверного поиска нет — T-176 FTS апгрейдит).
6. **`DocumentLink {Id, OwnerId, FromDraftId, ToDraftId, CreatedAt}`, unique(From, To) — отдельно от `EntityLink`** модуля: EntityLink — *заявленная* связь с обязательным `ProjectId`, DocumentLink — *выведенная из текста* и живёт и вне проектов. Синк — диффом на сейве **primary-языка** (переводы наследуют связи, не порождают свои); удаление драфта чистит обе стороны. `GET /api/drafts/{id}/backlinks` → `[{id, title}]`; в редакторе чип «← N» открывает список.
7. **Рендеры** (правило renderers.md — эскейп + тест на узел): блог — ссылка на цель, если она видима индексом (`IsBlogPublished && (!IsPrivate || IsListedWhilePrivate)`), иначе экранированный `<span>` с label; карта видимости строится одним запросом. Blocks/legacy HTML/MD — экранированный plain label (в Telegram внутренние ссылки некуда вести). **`wikilink` вносится в whitelist `PublishValidator` и в эмиссию `TipTapTextNodes`/`CedarPlainText`** — иначе валидатор откажет посту, а тизеры/og:description молча потеряют слово.

**Consequence.** Порядок сиблингов в списках — `(SiblingOrder, UpdatedAt)`; плоские виды дерево игнорируют. Битая ссылка (цель удалена) рендерится как plain label — документ не ломается. Reorder перетаскиванием, серверный поиск для саджеста и связи между проектами — отложены на борду.

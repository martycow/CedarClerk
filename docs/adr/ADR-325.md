# ADR-325 — Registration field rules

**Status**: DRAFT
**Session**: BR-002
**Supersedes**: none

## Context

`Program.cs` sets only `RequiredLength = 8`; Identity's defaults still require a digit, lower and upper case and a symbol, while the form says "8+ characters". The account name allows 63 characters, the invite code has no limit, and register has no password confirmation or avatar.

## Decision

1. Password: 8–32 characters, at least one letter, one digit and one symbol. Identity's upper/lower-case requirements are switched off; a custom validator enforces the rule. It applies to new and changed passwords only.
2. Account name: at most 16 characters, enforced by `Usernames` and the client. Existing longer names stay valid.
3. Invite code: at most 32 characters, enforced on the entity, the admin generator and the client.
4. Register has a password confirmation field, live validation on every field, and an optional avatar uploaded after account creation through `POST /api/auth/avatar`.
5. Register copy: no cow-themed title, no invite-only line, no "cannot be changed" hint; placeholders `USERNAME` and `CEDAR_CLERK_CODE`.

## Consequences

- Reset and change-password forms share the same rule text.
- The 32-character password maximum is a product choice; it is above the common minimum and does not block passphrases up to that length.

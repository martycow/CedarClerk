# ADR-311 — Customizable project overview

**Status**: DONE

## Decision

The Project overview uses the selected modular layout: a banner, separate project
logo, name and description, followed by Documents, Links, Analytics, Sprints and
tasks, and Journal. The default grid gives writing more width and places the
Journal across the bottom. Small work areas stack sections in their saved order.
This supersedes the fixed column and separate resume-card layout in ADR-239.

Customize page enables drag ordering, keyboard movement, section widths and
visibility. Hidden sections remain available in the customization controls.
Preferences and an optional library-picked banner are stored in browser storage,
scoped by account and Project ID. The UI states this scope. Storage failures keep
the current layout usable and display an error. Reset restores the default layout
and banner; it does not delete assets or change Project data. The existing logo,
name and description remain Project settings managed by the server.

Analytics uses existing Project document views, publication counts, Showcase
metrics and the explicitly account-wide publishing streak. Telegram views remain
not tracked. Links retain existing destinations and valid authored Showcase links.
Planning respects the IndieDev installation flag. No new database fields or API
contracts are required. The shell inspector starts collapsed on the overview and
can be opened explicitly without rewriting the account's preference for other pages.
On phones its closed handle floats over the page instead of consuming a column.
The shell row has a distinct class so document-row spacing cannot shrink the workspace.

## Rationale

A single hierarchy and readable sections make the overview useful without losing
its existing content. Restrained customization accommodates different workflows
without creating a second document editor or changing the public Showcase.
Personal browser preferences need neither a migration nor shared Project writes.

# ADR-164 — A scanning screen is one board: index tiles, one panel, and a shelf that is never empty

**Context.** Four screens share a shape the port has no reference kit for: `project-assets`,
`media-library`, `drafts` and `admin`. Each is a filtered list with a chip strip over it, a
page-level toolbar of commands, and — on two of them — a modal that opens one row. The metrics tab
(T-222) is the nearest worked example the port produced, and it answers only part of the shape:
one `app-shelf-panel` with two `app-index-tabs` strips in its `actions` slot, and a second panel
beside it for the audience split.

What these four have that metrics does not is a **selection**. `media-library` and `project-assets`
each open a chosen file in `app-modal`; `drafts` opens a row by navigating to the editor; `admin`
expands a user card in place. Four screens, four answers, and no rule saying which is right.

The chip strips are the other unshared thing. All four ship a hand-rolled strip of `<button>`s with
a count in a `<span>` — `.filter-tabs` in three files and `.admin-tabs` in the fourth — and each
count is written straight into the markup, so `0` prints and a five-digit number stretches the
control. `indexTabBadgeLabel` in `bench/chrome/index-tabs.component.ts` already holds both rules
(nothing at zero, `99+` past ninety-nine) and is the component T-231 is folding
`shared/count-badge.component.ts` into.

**Decision.** A scanning screen is laid out as: a page toolbar only where the screen has commands
that change the data, one `app-index-tabs` strip across the top for its primary filter, one
`app-shelf-panel` holding the list, and a right column of shelves that always carries something.

1. **The chip strip is `app-index-tabs`, and every count on it is a tab badge.** The badge rules
   arrive with the component rather than being restated: a count of zero draws nothing and a count
   past ninety-nine draws `99+`. This changes what three of the four screens print — `All 0` on an
   empty media library, `Templates 0` on `drafts` — and that change is the point, not a casualty.
   A strip whose tiles are *hidden* at zero keeps hiding them: `media-library` and `project-assets`
   drop a kind's tile entirely when the index holds none of that kind, which is a different rule
   about a different thing, and it survives.

2. **A second strip, in the panel's `actions` slot, switches the view.** Grid/list on the two asset
   screens and table/grid/tree on `drafts` were icon-only toggle groups with their own CSS in three
   files. They become a second `app-index-tabs`, which is exactly what the metrics panel already
   does with its chart/table pair. One vocabulary for "switch what this panel shows", and the
   icon-button toggle group leaves the app.

3. **Where the selected object is a readout, the modal becomes an inspector.** A modal takes the
   list away to show one row of it: on `media-library` the delete that answers 409 with *"used by
   these posts"* cannot be checked against the list it names, and on `project-assets` linking a file
   to a document hides the file's neighbours while you choose. Both become a shelf beside the list,
   and the list marks which row is being read.

4. **Where there is no such object, the shelf carries the screen's standing context instead — and
   no screen invents a selection it did not have.** `media-library` gets a Storage shelf (the usage
   figures already in its toolbar), `project-assets` an Index shelf (root path, machine, when it was
   last scanned — the sub-line under the old title), `drafts` a Folders shelf (the filter that was
   buried in a popover), `admin` a Summary shelf (the seven cards that were a grid across the top).
   Every one of these is data the screen already showed somewhere worse.

5. **`drafts` rows and `admin` user cards keep the behaviour they have.** A draft row is a door to
   the editor and stays one (ADR-163). An admin user's action form is a wide multi-field editor —
   two selects, a date, three text inputs and six buttons — not a readout, and a 340px shelf would
   be a worse home for it than the row it expands from. Neither gets an inspector here. What
   `drafts` is owed instead is named in the backlog rather than guessed at.

6. **These four keep `data-density="compact"`.** The hub dropped it because it is a screen you read;
   these are tables you scan, which is the case ADR-071 principle 3 describes. The surface split
   (ADR-138) governs the chrome inside them either way, and the two vocabularies do not meet.

7. **The audit log becomes `app-log-line`.** It is the one genuine journal in the app — a time, a
   stamped word, a sentence and an actor — and it is what the primitive was cut for.

**Rejected.** *Moving the page commands into the panel header too.* `ShelfPanel.prompt.md` puts a
panel's own commands in `[actions]` and nowhere else; importing a `.zip` into the library and
creating a draft are not this panel's commands, and `sp-actions` is a single non-wrapping row that
seven controls would run out of. The split that holds is: what changes *what this panel shows*
(search, view) goes in the header, what changes *the data* stays on the page. *Making the folder
filter a third tab strip.* Folders are user-created and unbounded; index tiles are a fixed, short
vocabulary. *Keeping the modals and adding a shelf as well.* Two homes for one object is the second
place `.claude/rules/ui-changes.md` rule 1 exists to stop.

**Consequence.** Closing an inspector is now a button in the panel header, not Escape and not a
backdrop click — a shelf is part of the page, and a page-wide Escape handler on four screens would
be four handlers competing with the modals those screens still open for import, delete confirmation
and new-draft. The list gains a selected-row mark it did not need while the reader was a modal, and
that mark is the only new visual vocabulary these four screens acquire.

# ADR-274 — Engine and target platforms are closed-vocabulary keys, stored comma-joined (05.09.2026)

**Context.** T-247 gives a project an engine and a set of target platforms, shown as a hero tag
(`Unity · Windows, Switch`) and edited from the settings modal. `Project.PressEngine` already holds
free text for the press page. Three storage shapes were possible for the platform set: a JSON
array, a child table, or a delimited string.

**Decision.**

1. **Both fields are keys from a closed list**, not free text: `ProjectEngines` (`unity`, `unreal`,
   `godot`, …, `custom`) and `ProjectPlatforms` (`windows`, `mac`, …, `quest`) in Core. A key is
   labelled by the client in either language; free text would have to be translated after the
   fact, and "Unity" versus "unity" versus "Unity 6" would be three engines.

2. **`Project.TargetPlatforms` is comma-joined keys in the list's order, no spaces** —
   `"windows,switch"`. The keys never contain a comma, so `Split(',')` round-trips exactly, a SQLite
   `LIKE '%switch%'` filter works later without a join, and the shape matches the file's own
   precedent: `ShowcaseLinks`/`ShowcaseGallery` are line-delimited strings and `Draft.Tags` is a
   delimited string. `ProjectPlatforms.Parse` and `Join` are the only two doors: an unknown or
   repeated key never reaches the column, and the stored order is the list's whatever the client sent.

3. **`PressEngine` stays as it is and is not synced.** It is the press page's own sentence about
   the engine ("Unity 6, custom rendering"), a different field on a different page; a sync would
   either overwrite prose with a key or leak a key into prose.

**Rejected.** *JSON array* — a JSON column cannot be filtered with `LIKE` honestly (`"switch"` matches
`"switch"` and `"nintendo-switch"` alike, and the quoting is the parser's business), and nothing here
needs nesting. *A child table* — a project has at most ten platforms, and a join for a tag on a
hero is a join for nothing. *Free text with suggestions* — see 1.

**Consequence.** Migration `AddProjectEngineAndPlatforms` adds two non-null `TEXT` columns
defaulting to `""`, so existing projects are simply unset. The API projects `targetPlatforms` as a
`string[]` and accepts one back; the column shape is the server's business and never crosses the
wire. Adding an engine or platform is one constant and one label pair, and a stored key that leaves
the list keeps working (`Parse` drops it silently), so a later cut of the vocabulary is not a
data migration.

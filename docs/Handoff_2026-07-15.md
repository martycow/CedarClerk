## Что за проект
**Cedar Clerk** — self-hosted personal publishing SaaS: веб rich-text редактор (TipTap), посты публикуются в Telegram-каналы через бота и на блог-страницы. Ядро архитектуры: **один документ (TipTap JSON) → много рендереров** (Telegram Rich Message HTML, блог-HTML, позже Markdown/файлы).

Репозиторий: `D:\Moo.exe\CedarClerk`
- **CedarClerk.Server** — ASP.NET Core (.NET 8): REST API, хост Angular-статики, хост Telegram-бота, Quartz.NET, SQLite + EF Core
- **CedarClerk.Core** — формат документа и рендереры (чистый C#, покрыт тестами)
- **CedarClerk.Tests** — xUnit (сейчас 162 теста)
- **cedarclerk-web** — Angular SPA (standalone components, signals, TipTap напрямую)

## Жёсткие правила (уже кусались)
1. **Telegram 409 Conflict**: токен бота поллит ровно один процесс. Локальный запуск с токеном: сначала `sudo systemctl stop cedarclerk` на Pi, после — `start`. Локально без токена бот отключён by design (export отвечает 503 через guard `IsRunning`).
2. **EF-миграции**: любое изменение `Entities.cs` → сразу `dotnet ef migrations add`. Rename колонки — руками править миграцию на `RenameColumn` (EF делает Drop+Add и теряет данные).
3. **Рендереры**: пользовательский текст всегда экранируется (`< > &`); каждый mark/block покрыт юнит-тестом; `dotnet test` перед любым деплоем, задевающим Core.
4. **sendRichMessage** (Bot API 10.1): `Html` и `Markdown` — альтернативы, заполнять ровно одно. Html-режим поддерживает блочные теги и инline-медиа; **не-void теги обязательно закрывать** (незакрытый `<video>`/`<audio>` «съедает» контент, и Telegram уносит медиа в конец сообщения). `<img>` — void. URL медиа должны быть публично доступны (localhost не работает — Telegram скачивает сам; см. fallback `Cedar:PublicBaseUrl`). Честный превью — только отправкой в тест-канал **@testingandfun**. **Никогда не постить в Dev Dairy Diary без явного разрешения.**
5. **Секреты**: `appsettings.Development.json` в gitignore. Если секрет попал в коммит — сначала ротация (BotFather /revoke), потом чистка истории.

## ПРОМПТ

### Что за продукт

Cedar Clerk — самохостящийся инструмент для инди-разработчика игр. Начинался как редактор длинных постов с публикацией в Telegram и на собственный блог; сейчас разворачивается в тулкит, где пост — лишь один из типов документа, а документы живут внутри проекта (проект = игра).

Пользователь — один человек, совмещающий роли: программист, гейм-дизайнер, продюсер, сценарист, звукорежиссёр, композитор, режиссёр, маркетолог, аналитик. Работает подолгу и ежедневно, знает интерфейс наизусть. Это меняет приоритеты: плотность информации важнее приветливости, а обучающие подсказки не нужны почти нигде.

### Визуальное направление — уже задано, не выбирается заново

Тёплая редакторская эстетика: бумажные и древесные нейтрали, оливковый акцент, просторная мера чтения. Не «дашборд IDE», не неон, не корпоративный SaaS.

**Одна палитра и одна шкала типографики на весь продукт.** Второго набора цветов для новых экранов не существует. Различие между экранами выражается только через плотность, отступы, радиусы и размеры.

### Токены — обязательны, дословно

Светлая тема (`:root`):
```
--bg: #ECE9E2;       --canvas: #E2DED4;    --surface: #F7F5EF;
--sheet: #FCFBF8;    --alt: #EFECE4;       --border: #DBD5C8;
--text: #26231D;     --t2: #686257;        --t3: #847E72;
--accent: #566842;   --danger: #A84129;    --ok: #386D46;
--warn: #7B5E0E;     --border-strong: #857D6F;
--shadow: 0 1px 3px rgba(40, 35, 25, .10);
--shadow-md: 0 8px 24px rgba(40, 35, 25, .12);
--asoft: color-mix(in srgb, var(--accent) 13%, var(--surface));
--abord: color-mix(in srgb, var(--accent) 38%, var(--border));
```

Тёмная тема (`:root[data-theme="dark"]`) — переопределяет только перечисленное, остальное наследуется:
```
--bg: #1D1B17;        --canvas: #171511;    --surface: #25221B;
--sheet: #2B2820;     --alt: #2F2C23;       --border: #3C382D;
--text: #EAE6DB;      --t2: #A69F8F;        --t3: #8B8477;
--accent: color-mix(in srgb, #5B6E46 55%, #E8F0E8 45%);
--danger: #E2745C;    --ok: #82BB8C;        --warn: #E3C35C;
--border-strong: #7B7465;
--shadow: 0 1px 3px rgba(0, 0, 0, .45);
```

Радиусы: `--radius-sm: 6px`, `--radius-md: 10px`, `--radius-lg: 14px`.

Отступы: `--space-1: 4px`, `-2: 8px`, `-3: 12px`, `-4: 16px`, `-5: 24px`, `-6: 32px`. Прогрессия примерно ×2, не строгая сетка по 4px. **Значений между этими шагами не существует** — если нужно 11px, значит нужно 12px.

Типографика: `--font-sans` — системный стек (`-apple-system, "Segoe UI", Roboto, …`); `--font-mono` — `ui-monospace, Menlo, Consolas`; `--font-serif` — `ui-serif, Georgia, …` и **только** для поверхностей чтения (тело поста в блоге, лист редактора). Всё остальное — панели, таблицы, формы, меню, кнопки — sans.

Размеры — целые пиксели, обращаться к смысловым ролям, а не к числам:
```
--fs-caption: 11px   подписи над полем, отметки времени
--fs-meta:    12px   вторичные данные строки, счётчики
--fs-ui:      13px   кнопки, пункты меню, ячейки таблиц
--fs-body:    14px   основной текст интерфейса
--fs-title:   19px   заголовки страниц и секций
--fs-read:    17px   поверхности чтения, --lh-read: 1.7
```
Полупиксельных размеров (12.5px, 11.5px) быть не должно — от них специально избавлялись.

Иконки: набор **Phosphor**, размеры `--icon-xs: 12px`, `--icon-sm: 15px`, `--icon-md: 18px`, `--icon-lg: 20px`. Другой набор не смешивать.

Анимация: `--motion-fast: 120ms` (реакция на то, что уже под курсором), `--motion-base: 180ms` (появление/перемещение), `--motion-slow: 280ms` (смена всей поверхности), `--ease: cubic-bezier(.2, .6, .3, 1)`.

### Плотность — режим поверхности, а не решение компонента

У страницы есть атрибут `data-density`. Списочные и табличные экраны — `compact`; поверхности чтения и письма — `comfortable` (умолчание). **Ни один цвет между режимами не отличается** — только отступы, размеры, радиусы и способ разделения (в compact границы вместо теней).

```
                    comfortable        compact
--dens-row-y        10px               6px
--dens-control-y    7px                5px
--dens-control-x    14px               10px
--dens-gap          12px               8px
--dens-section      24px               16px
--dens-radius       10px               6px
--dens-fs           14px               13px
--dens-elev         --shadow           none
```

Новые экраны распределяются так: список проектов, доска задач, планировщик и сетка ассетов — **compact**. Дашборд проекта, референс-борд и Press Kit — **comfortable**.

### Что уже нарисовано и НЕ перерисовывается

Эти экраны прошли редизайн (Phase 11) и живут в продакшене. Они нужны как образец языка, а не как объект работы: редактор, `/drafts` (список черновиков), `/posts` (менеджер постов со статистикой и обратной связью), `/settings`, `/admin`, страницы входа и регистрации, публичная страница блога.

Новые экраны должны выглядеть их продолжением, а не соседним продуктом.

### Что нарисовать

**1. Список проектов** — точка входа в модуль. Проект = игра. Карточка или строка: обложка, имя, счётчики (документов, открытых задач, ассетов), дата последней активности, состояние (активный / в архиве). Нужны состояния: ноль проектов, один проект, двадцать проектов.

**2. Дашборд одного проекта** — центральный экран модуля, самый важный в наборе. Собирает воедино: документы проекта, сгруппированные по типу; ближайшие задачи и дедлайны; недавно изменившиеся ассеты; текущий спринт. Главный вопрос, на который отвечает экран: «что здесь происходит и за что взяться». Не превращать в сетку одинаковых виджетов — разделы неравнозначны по важности.

**3. Диалог создания проекта.** Проект не может быть пустым: создание сразу порождает стартовый документ. Значит это выбор типа проекта, а не поле «имя». Показать 3–5 типов с внятной разницей.

**4. Выбор типа документа** — при создании документа внутри проекта. Типы: пост (девлог), гейм-дизайн-документ, сценарий, сюжетный план, чейнджлог, заметка. У типа есть иконка и одна строка объяснения. Тип виден потом везде, где документ упоминается, — придумать способ обозначения (иконка? цветная метка? и то и другое — вероятно, перебор).

**5. Доска задач.** Поля задачи: имя, статус, приоритет, описание, исполнитель, срок, спринт. Нужны оба вида — колонки по статусу и плотный список с сортировкой, — и переключение между ними. Задача связана с документами/ассетами/другими задачами: показать эти связи, не превратив карточку в свалку.

**6. Карточка задачи** — раскрытая. Поля, связи, срок, спринт. Описание — простой текст, не богатый редактор: задача, которой нужны таблицы и медиа, на самом деле является документом.

**7. Планировщик разработки.** Спринты с датами, задачи внутри, дедлайны. Нужен обзор нескольких спринтов сразу, включая честное отображение просроченного — не прятать и не окрашивать всё в красный.

**8. Сетка ассетов.** Индекс локальных файлов из папки игрового проекта: спрайты, модели, звуки, музыка, шрифты. Файлы **не загружены на сервер** — это индекс путей, и интерфейс не должен обещать больше, чем есть. Нужны: сетка превью и плотный список; фильтр по типу; строка «файл на месте не найден» (диск отключён — не то же самое, что файл удалён); состояние во время обхода большой папки; экран выбора папки для индексации. Считать, что элементов могут быть десятки тысяч.

**9. Просмотр одного ассета** — превью, метаданные, где используется, связанные задачи. Для звука и модели превью может быть невозможно — показать это честно, а не пустым прямоугольником.

**10. Референс-борд** — свободная галерея-мудборд с изображениями и подписями. Единственный экран набора, где допустима нерегулярная сетка.

**11. Press Kit** — сгенерированный самообновляемый документ о игре: описание, скриншоты, трейлеры, факты, контакты. Нужны два вида: как автор его редактирует и как он выглядит снаружи.

**12. Навигация.** Модуль добавляет крупный раздел к существующему приложению, и главное решение здесь — как переключаться между «пишу пост» и «веду проект», не потеряв ни то, ни другое. Существующая навигация — горизонтальный топбар. Показать, куда встраиваются проекты.

### Обязательные условия

- **Обе темы.** Каждый экран в светлой и тёмной. Тёмная — не постобработка: если что-то работает только в одной, это не готово.
- **Контраст WCAG AA.** Проверяется автоматически (`npm run check:contrast`), так что нарушение не пройдёт. Отдельно: **`--t3` никогда не несёт информацию** — это плейсхолдер, выключенное состояние, декор. Если текст тихий потому, что он вторичный, это `--t2` плюс меньший размер.
- **Два языка.** Интерфейс на русском и английском. Немецкий использовать как стресс-тест длины: подпись **сжимается и обрезается многоточием, но никогда не расширяет свой контейнер**.
- **Устройства.** Десктоп (основной) и iPad 16 в обеих ориентациях. Сенсорные цели — минимум 44px по обеим осям при грубом указателе; для iPad в альбомной ориентации это ширина 1024px и при этом полностью сенсорный ввод, так что правило по ширине экрана не работает.
- **Состояния обязательны.** Для каждого экрана: пусто, загрузка, ошибка, много данных. Пустое состояние объясняет, что сделать, а не извиняется.
- **Фокус.** Одно глобальное кольцо `:focus-visible` в `--accent`, 2px с отступом 2px. Компонент, убравший обводку, обязан дать замену.

### Соглашения, которые стоит соблюсти

Заполненный акцентом — основное действие; обведённый контуром «ghost» — вторичное. Модальное окно: затемнение `rgba(24, 21, 16, .45)`, карточка на `--sheet` с границей `--border` и радиусом `--radius-lg`.

Честное предупреждение: общей библиотеки компонентов в коде **нет** — `.btn-accent`, `.btn-ghost` и `.modal-*` скопированы между двумя файлами со слегка разошедшимися значениями. Если прототип задаст им одно определение, это будет улучшением, а не расхождением с реальностью.

### Чего не делать

- Не изобретать вторую палитру, вторую шкалу размеров или второй набор иконок.
- Не рисовать заново редактор, `/drafts`, `/posts`, `/settings`.
- Не проектировать совместную работу: пользователь один, «исполнитель» задачи — просто текстовое поле.
- Не обещать синхронизацию между устройствами — её нет и в первой версии не будет.
- Не показывать ассеты так, будто они загружены в облако: это индекс путей на локальном диске.
